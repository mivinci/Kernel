# 代码约定

C89/freestanding，格式以 `.clang-format` 为准。类型使用 u8/u16/u32/u64、isize/usize；ABI 定义只保留一个来源。
裸 struct 加 typedef，枚举使用类型前缀。内部函数小写连写，硬件契约保留 arch_/hal_/plat_ 前缀。
核心不得包含架构寄存器、架构头文件或架构条件分支。注释解释不变量与边界。
新 ABI、地址布局、上下文结构尚未确定，不沿用旧能力对象命名作为约束。

## 命名与表达

名称简短、具体、能反映职责；采用常见且容易还原的缩写，不为缩短而创造生僻缩写。
服务不用 `srv` 后缀。代码、目录、文件和程序名统一小写；文档叙述可写 FS、TTY 等常见大写缩写，
涉及实际路径、符号和程序名时仍使用其小写拼写。

| 程序名 | 职责 |
| --- | --- |
| `init` | 系统引导、进程与资源管理 |
| `fs` | 文件系统 |
| `blk` | 块设备 |
| `tty` | 终端 |
| `sh` | 命令交互 |
| `net` | 网络 |
| `print` | 已命名的服务，具体职责待确定 |

不使用 `fssrv`、`blksrv`、`ttysrv` 等名称；不为每个服务添加重复的类别前后缀。
函数与类型继续遵循各自的命名规则，不要求类型名全小写。

## 文档组织

设计和待办统一放在 `docs/`。待办文件名必须以 `todo-` 开头，例如 `todo-redesign.md`；不建立单独的待办目录。

## 源码目录

公共代码直接放在 `kernel/`、`include/`、`user/`；各自的架构子目录直接叫 `arm64/`、`riscv/`。
不设置 `arch/` 中间层或独立 `platform/`。RISC-V 目录按架构家族命名，当前只支持 RV64；不提前实现 RV32 分支。
工具链架构参数与目录命名分开，ARM64 工具仍可使用 `aarch64` 名称。
设备树提供资源描述；CPU、定时器和中断控制器操作仍由内核架构代码提供。
普通设备驱动在用户态，早期轮询串口仅作为架构代码的诊断例外。
