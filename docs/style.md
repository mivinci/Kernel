# 代码约定

C89/freestanding，格式以 `.clang-format` 为准。类型使用 u8/u16/u32/u64、isize/usize；ABI 定义只保留一个来源。
共享 syscall/结构定义放 include/abi，内核硬件契约放 include/hal，用户态服务线上协议放 include/proto；按职责拆头，不默认聚合全部内容。
内核不包含 proto，用户态不依赖内核 HAL；跨边界使用定宽字段/显式对齐和静态布局断言，不依赖裸指针、long 或 enum 存储宽度，不滥用 packed。
结构体别名在文件前部统一写 `typedef struct Name Name;`，定义处只写 `struct Name { ... };`，不连写 typedef 与结构体定义。结构体每行只声明一个字段，同类型字段也分开写。私有类型留在所属源文件。枚举使用类型前缀。内部函数小写连写，硬件契约保留 arch_/hal_/plat_ 前缀。
当前物理ELF切高半区后不通用重定位代码指针：内核构建禁用编译器跳转表，跨地址域的显式函数指针须在目标地址域构造，不保留物理代码地址作运行期分支。
核心不得包含架构寄存器、架构头文件或架构条件分支。注释解释不变量与边界。
主机测试放 `tests/unit/`，在QEMU内执行的测试载荷及专用C/汇编、头文件放 `tests/kernel/`；按需使用其 `arm64/`、`riscv/` 子目录。测试只链接进明确选择的测试镜像，普通内核不包含测试源码或专用声明。
ABI、地址布局与上下文结构以对应设计为准，不沿用旧能力对象命名作为约束。

## 命名与表达

名称简短、具体、能反映职责；采用常见且容易还原的缩写，不为缩短而创造生僻缩写。
服务不用 `srv` 后缀。代码、目录、文件和程序名统一小写；文档叙述可写 FS、TTY 等常见大写缩写，
涉及实际路径、符号和程序名时仍使用其小写拼写。

| 程序名 | 职责 |
| --- | --- |
| `init` | 系统引导、进程、资源与设备管理 |
| `fs` | 文件系统 |
| `blk` | 块设备 |
| `serial` | UART 字节收发与设备中断 |
| `tty` | 终端与行处理 |

| `win` | 窗口、合成与焦点分发 |
| `input` | 键盘/鼠标等输入设备驱动 |
| `dis` | 显示设备与画面提交，替代旧 print |
| `sh` | 命令交互 |
| `net` | 网络 |

`dev` 是 init 内部设备管理模块名，不是必需的独立服务进程。

不使用 `fssrv`、`blksrv`、`ttysrv` 等名称；不为每个服务添加重复的类别前后缀。
函数与类型继续遵循各自的命名规则，不要求类型名全小写。

## 源码目录

源码按 `kernel/`、`include/`、`lib/`、`bin/`、`sbin/` 组织；架构子目录直接叫 `arm64/`、`riscv/`，跟随所属模块。
不设置 `arch/` 中间层或独立 `platform/`。RISC-V 目录按架构家族命名，当前只支持 RV64；不提前实现 RV32 分支。
工具链架构参数与目录命名分开，ARM64 工具仍可使用 `aarch64` 名称。
设备树提供资源描述；CPU、定时器和中断控制器操作仍由内核架构代码提供。
普通设备驱动在用户态，早期轮询串口仅作为架构代码的诊断例外。

普通命令放 `bin/<程序名>/`，系统服务放 `sbin/<程序名>/`；dev 为 init 内部模块。
启动对象放 `lib/csu/`（含 arm64/riscv 入口），用户态库放 `lib/libc/`、`lib/libsys/`、`lib/libvirtio/`；libsys 的架构适配放其 arm64/riscv 子目录。
libc 可依赖 libsys，libsys 不依赖 libc，基础模块不要求文件/网络服务在线；公共库静态按需链接，不增加启动依赖环。
运行时安装路径及启动包内容由清单决定，两架构产物放各自 build/<架构>/ 下，源码位置不决定执行特权级。

Unix API 保持标准名称；原生 IPC 使用 ipc_call 等 ipc_* 名称并放 sys/channel.h。libsys 私有 syscall 入口使用 __sys_*，不使用 k_*。这些及 _start 是既定接口命名例外，普通内部函数仍小写连写。
原生 create/configure/start/destroy 不直接导出为应用的裸 C 函数；libsys 桩使用 __sys_create/__sys_configure/__sys_start/__sys_destroy，标准库继续提供 fork/execve/posix_spawn 等名称。内核独立链接，不通过 C 符号跨特权边界。第三方 libc 复用同一份 libsys 桩，私有桩声明与应用标准头分开，SDK 适配头路径随构建规格冻结。
csu → libc → libsys 单向依赖；csu 为独立启动对象，libsys 不引用 libc 符号（含编译器隐式内存调用）。

libsys 同时承载内核接口与用户态服务适配（fd、连接、共享缓冲和取消收尾），不另建 libos；库内模块按需初始化。
libc 提供 C/POSIX API 与 errno 转换，第三方运行时可复用公开适配接口。

Handle 统一为 int64_t：有效值为正，编码为符号位0/类别4/代次43/索引16；位操作使用 uint64_t。pid_t 使用相同表示，特殊负数选择器只按明确接口解析，状态码使用独立状态字段。
