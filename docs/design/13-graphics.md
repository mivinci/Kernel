## dis、win 与显示缓冲（已确定）

dis 管显示设备、模式、扫描输出及提交/完成，win 管窗口、软件合成、焦点和应用输入分发；应用画面→win 合成→dis→显示设备。
应用仅操作自身授权画面缓冲，不直接修改扫描输出；只有 dis 持显示设备资源，GPU 设备权限不通过窗口句柄下放。
缓冲按可写→提交→消费中→完成归还→可写管理，提交接受与可复用完成分开；取消/关闭/进程退出不能代替显示设备停止读取证明。
win 消费不可信应用缓冲须快照或有效所有权交接，不能只信客户端不再修改；win/dis 至少双缓冲，不覆盖正在扫描输出的缓冲。
双缓冲不保证无撕裂；按设备能力使用垂直同步/翻页，不支持则明确限制，完成归还只表示不再读取，不承诺人眼已看到。
缓冲数量、尺寸与在途帧有预算/配置上限，生产过快背压或显式丢弃尚未显示旧帧；丢弃同样须结束实际消费才能归还。
显示模式有代次，变化后拒绝旧格式/尺寸提交；分配、显示切换失败保留明确可用状态或报告离线，不能继续使用失效缓冲。
键盘/鼠标由独立设备输入路径产生，不归 dis；win 根据焦点授权分发，应用不得读取其他窗口输入，串口 tty 控制终端不与图形输入混为一体。
首个实现可用软件合成/帧缓冲，但窗口授权及缓冲归还协议不依赖是否 GPU 加速；input 独立驱动布局已确定，具体输入/显示设备型号仍需选定。

## 图形输入与 PTY（已确定）

input 是独立用户态输入驱动进程，持获授权的键盘/鼠标设备资源；不是 init 内部 dev 管理模块，也不把 MMIO/IRQ 下放 win。
路径为设备→input→win→获焦点应用；input 处理设备协议/按键指针状态/断开，win 负责焦点路由/快捷键/受控捕获，应用负责文本和业务。
物理按键与文本分开，驱动不直接决定字符/输入法结果；键盘/按钮事件进入有界队列，事件位仅通知，不合并丢弃必要按下/释放。
队列溢出明确报告失步，并提供当前按键/按钮快照重同步；断开释放相关状态、唤醒消费者，不能留下永久按下状态。
焦点/捕获有代次，切换和窗口销毁取消旧绑定并校验待投递事件归属；普通应用不可映射全局原始输入队列。
input/win 不任意将 Ctrl-C 转为进程终止，图形终端收到输入后经其 tty 实例按模式解释字符或信号。
图形交互纳入 PTY：终端应用使用主端，sh/命令使用从端及控制终端语义；不能将一个串口终端当作所有窗口共享终端。
PTY 归 tty/VFS 打开会话与端点生命周期协议管理，创建/授权/挂断/关闭/前台组规则复用已有机制；主从端具体用户态协议待规格化。

## PTY 主从端（已确定）

Pty 是 tty 内部终端后端，复用串口的行处理/模式/作业控制；图形终端程序 term 为普通应用，不新增常驻管理服务。
主端由 term 使用，写入经 tty 输入处理后供从端读取；从端由 sh/命令使用，写入经输出处理后供主端显示。
回显进入主端输出流，term 不重复实现 tty 回显；Ctrl-C/退格/规范与原始模式统一在 tty 处理，转义序列显示归 term。
每对 PTY 有独立终端身份、主从会话和有界双向缓冲；主端仅授予创建者/明确继承者，从端通过受权限检查的 /dev/pts 节点打开。
路径编号可复用而会话/终端代次不可串线，打开从端不自动抢占控制终端；关联会话仍由授权管理协议建立。
最后一个主端引用关闭才触发挂断，复制 fd 关闭其中一个不影响其他引用；从端按协议排空已有可读数据后返回 EOF/挂断错误，不等不存在的主端。
两端引用与在途操作全部收尾后回收 Pty/缓冲，双向非阻塞/poll 及背压不阻塞整个 tty 或其他终端。
获授权 term 设置行列/像素尺寸，tty 校验范围、记录尺寸并向前台组投递 WINCH；尺寸查询是权威状态，不以信号次数重建尺寸。
term 不获得任意进程信号权，WINCH 经受限终端机制解析前台组；图形窗口输入与 PTY 控制终端资格继续分离。

## 机制层首版规格（候选，未冻结；2026-11-17）

范围：本节只定义"使后续 GUI 得以实现的机制"，不含工具包、控件、窗口装饰、`term` 应用、输入法与桌面。GUI 属最终目标；用户于2026-11-18明确，先让系统可通过 sh 正常使用，完成其他系统能力及图形/GPU相关机制，最后再推进GUI。本节候选机制规格仍未冻结，不因最终目标确认而提前实现。

### 帧缓冲几何（候选）

单 Mem 上限 64 KiB 且受 16 位保护掩码约束（`kernel/space.c` 的 `MEM_PAGES <= 16` 断言），故帧缓冲按 tile 表达，不引入"一张 Mem 一帧"的假设：

- 模式 512×384、32bpp `XRGB8888`；stride 固定 2048 字节，不接受自定义或负 stride。
- 每 tile 32 行、恰好 64 KiB、对应一个 Mem；全屏 12 tiles；双缓冲 24 tiles（1.5 MiB）。
- 扫描缓冲由 dis 出资（dis 持 R、win 持 RW）；应用缓冲由应用出资并仅向 win 授 R。
- 不支持 alpha 混合、YUV、多平面与缩放；X 位必须为 0，以便逐像素精确核对。

### 所有权与端点（候选）

| 角色 | 持有 | 不做 |
| --- | --- | --- |
| 应用 | 自身画面缓冲（tile 组） | 不碰扫描输出，不读他人缓冲 |
| win | 窗口表、z 序、焦点、扫描缓冲写权、源缓冲 R 映射 | 不碰 MMIO，不下放 GPU 权限 |
| dis | 扫描缓冲与显示设备租约 | 不做合成与窗口策略 |
| input | 输入设备租约与有界事件环 | 不解字符，不做焦点 |

### 提交与呈现（候选）

- `COMMIT` 在 CALL 内完成裁剪拷贝后回复，回复三态 `ACCEPTED`/`DROPPED`/`STALE`；"消费中"仅存在于该 CALL 内，缓冲五态语义不变。
- 下层向上一层只用 `SEND`/`NOTIFY`，不使用回调 `CALL`，避免单线程客户端重入死锁。
- 窗口装饰、拖动与缩放属 win 策略（服务端装饰），客户端不感知自身屏幕坐标；该部分不属于机制层。
- 模式变更推进代次；旧代次提交返回 `STALE` 且不写像素。

### 失败与清理（候选）

| 事件 | 行为 |
| --- | --- |
| 越界/超尺寸/坏代次提交 | 整笔拒绝，不部分写入 |
| 客户端死亡 | 经 observe/LIFE 回收窗口、释放映射、迁移焦点 |
| win 或 dis 死亡 | 停止呈现并报离线，保留最后一帧；不做热恢复 |
| 消费期间客户端改写源缓冲 | 不影响已合成结果，仅客户端自伤 |

### 验收方法（候选）

- dis 在模式设置后向串口打印各 tile 的物理地址与几何（沿用现有 VM 记录风格），主机 `pmemsave` 后逐像素断言；无 alpha 故期望值精确相等。
- 黄金图：帧转 PPM 后与基准逐字节哈希比对，差异时保留对比图。
- `CASE=gfx`：z 序与裁剪采样点、越界拒绝、提交后改写源缓冲、客户端死亡回收、双窗口输入隔离、输入环溢出重同步、旧代次 `STALE`、双缓冲交替不覆盖在扫缓冲。
- 首版**没有生产客户端**，机制只由测试载荷覆盖；status 须如实标注。

| 阶段 | 内容 | 前置 |

### 显示后端与能力位（2026-11-18）

dis 内部只有一个窄后端接口，合成逻辑与后端无关；后端以**能力位**声明差异，上层不按型号分支：

| 能力位 | 含义 |
| --- | --- |
| `flip` | 能否翻页使新帧直接成为扫描面；为假时必须全帧 blit |
| `cursor` | 是否有可用的硬件光标 |
| `maxwidth` / `maxheight` / `stride` | 后端可用几何 |
| `formats` | 支持的像素格式集合 |

三个后端按角色分层：

| 后端 | 角色 | `flip` | 前置 | 依赖 |
| --- | --- | --- | --- | --- |
| `simple-framebuffer` | **生产路径**：真机唯一可用的显示方式；QEMU 以注入节点走同一路径 | 否 | 固件或注入 DTB 节点 | 无 DMA |
| `ramfb` | **可选开发设施**：仅 QEMU 内实时可视调试 | 否 | fw_cfg 与一次 DMA 描述符配置 | QEMU 专属，非真机路径 |
| `virtio-gpu` | **虚拟机/DPU 与未来 GPU 入口**：免全帧拷贝的翻页、可选硬件光标 | 是 | DMA 后端与 2D 资源队列 | 排在 DMA 就绪之后 |

选择顺序固定，不做运行时热切换：DTB 存在 `simple-framebuffer` → 用它；否则存在 virtio-gpu 且 DMA 就绪 → 用它；否则存在 fw_cfg → `ramfb`；否则报离线。任一后端因格式、几何或依赖不满足时报告**明确的不可用原因**，不静默退到另一个后端。

`simple-framebuffer` 的约定：

- 节点给出 `reg`（物理地址与长度）、`width`、`height`、`stride`、`format`。该区间从页管理器可用区排除（`reserved-memory`），并以 Device 的 **RAM 型窗口**租给 dis：dis 持 RW 映射，其他进程不可得。**Device 租约支持 RAM 型窗口属 09 的待接内容**，本节只记录需求，不在图形侧改内核。
- 只有一块缓冲：win 合成到 RAM 后缓冲，dis 全帧 blit 到扫描缓冲；不实现垂直同步，明确接受撕裂。
- 首版只支持 32bpp XRGB（`x8r8g8b8`/`a8r8g8b8`）；`stride < width*4`、格式不受支持、或显示面小于合成面时报离线并保留可用状态，不猜测替代模式。
- 合成面 512×384 居中显示，四周黑边；不缩放、不旋转、不做多平面与 YUV。

QEMU 验证方式：以 `dumpdtb` 取得完整树，再用 `tools/fdt.py` 注入 `reserved-memory` 与 `simple-framebuffer` 节点，以 `-dtb` 启动，使模拟器与真机走**同一条代码路径**；断言用 `pmemsave` 读取帧缓冲并与黄金图逐字节比对，帧另存 PPM 供人工查看。节点与保留区必须成对出现，否则帧缓冲会被页分配器当作空闲 RAM。

验证分级（控制矩阵规模）：

| 后端 | 回归职责 | 场景量 |
| --- | --- | --- |
| `simple-framebuffer` | 承担全部像素断言 | 全部 `CASE=gfx` |
| `ramfb` | 仅证明能出画面 | 单个冒烟 + 人工查看 |
| `virtio-gpu` | 仅证明协商、资源创建与一次 flush 可用 | 1–2 个能力场景，不做像素全回归 |

明确不做：后端热切换、缩放与旋转、YUV/多平面/HDR、为不支持显示的目标板自研显示控制器驱动（按 14 的硬件矩阵记为不可用）。
