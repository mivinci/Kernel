## 文件描述符和路径

整数 RPC 资源句柄与文件描述符是不同概念；文件描述符表示一次打开的文件/终端及其读写状态。
已确定：用户态库维护有上限的 fd 表，0/1/2 为标准输入/输出/错误，后端为 fs/tty 会话；内核不管理 fd。
跨进程继承应由管理者和服务显式建立或复制会话，不能直接把父进程的本地句柄当成子进程句柄。
定义 open/read/write/close、偏移、EOF、短读写和错误语义；关闭和进程退出不能泄漏服务会话。
当前目录是 VFS 管理的目录引用，不以客户端路径字符串作为权威；定义相对路径、根目录、`.`/`..`、路径长度与目录枚举。
共享缓冲按连接隔离或明确定义串行使用，不能让多个进程相互覆盖请求。

fd 表项保存后端类型、服务句柄、会话标识和访问模式；文件偏移由 fs 打开会话维护，不由客户端重复维护。
会话标识不等于访问授权，服务按内核提供的完整调用者身份检查会话引用归属，禁止猜测标识访问他人文件。
普通 spawn/fork 继承由调用者运行库与服务直接准备子进程连接/受限授权和会话引用，必要状态全部准备好后再发布孩子；不逐次请求 init。
继承引用共享原打开会话及偏移，独立 open 创建独立会话/偏移；失败撤销本次新增连接、授权和会话引用。
close 先固定 fd 发布前已保证的必要收尾责任，再原子摘除本地 fd，后端按原会话引用异步收尾；通信失败不能按已复用的 fd 数字重放关闭，具体标准返回语义见下文。
进程异常退出由后端依据可靠生命周期观察清理对应实例/镜像的会话引用，不依赖用户态 close 或 init 逐会话代办；清理必须幂等。
fd 1 重定向不改变控制终端；控制终端关联、标准流及资源授权分别管理。
会话使用服务实例及槽代次，打开/关闭/继承采用[全局设计与冻结条件](00-overview.md)操作序号与确认协议；具体参数编码在用户态协议头定义。

- [ ] 定义 fd 表、标准流和 spawn 的继承/重定向协议。
- [ ] 支持文件读写、创建、删除、目录列表和当前目录；确定截断/覆盖写的持久化边界。
- [ ] 清理进程死亡后的打开文件、连接和共享缓冲。

### 未发布孩子的继承核验与清理（已冻结）

复用孩子完整实例身份区分本次构造，不因正常 fork 另设通用公开事务对象。FS 的父快照仍使用该连接已有操作序号，必须同时绑定真实父实例/镜像、原 FS 连接及准备中的孩子；同一快照的消费/重复查询规则由继承协议定义，不能把任意快照令牌当跨进程文件权限。

父请求为孩子准备继承时，FS 从 IPC 取得可信 source，并通过获权内核机制核验：目标完整身份存在且仍未发布，构造者正是该 source 的对应镜像，准备关系有效。不能只读取可由父填写的 Boot 或相信消息中的 parent PID。服务仅能观察有业务关联且获准的实例，不因此取得任意进程管理权；具体权限/证明由本篇CHILD/FUTURE的真实REQUEST关系及06的observe/getcred契约核验，不凭裸PID。

仅一次查询不足以保证安全。FS 必须在安装子引用前取得生命周期观察，登记与读取当前状态形成原子交接：目标已经终结则返回终结状态，尚未终结则保证其后变化可查询。观察固定旧 Life/镜像引用，不能随运行槽复用指向新进程。后续核验或观察容量不足均不发布新会话，回滚本次准备引用。

FS 本地安装的子会话先处于准备状态，仅绑定该孩子，父不能以孩子会话冒充 source 发起普通读写。若登记之后孩子被撤销，允许 FS 暂时完成本地安装，但持久终结状态必须使它最终撤销；已终结目标不能再运行，因此不会把暂存会话交给复用槽的新实例。普通发布方案不要求 FS 就绪证明；服务成功回复前使子会话可按可信 source 使用并登记清理责任，正确 libsys 等待该回复再发布。会话已就绪不授予父冒充孩子访问的权限。

普通发布的机制安全与 FS 业务就绪分工、提前发布竞态和服务回复约束见 [发布条件](03-process.md#普通发布不验证-fs-业务就绪已冻结)。准备中的服务不得不经检查继续写已经发布孩子的私有内存。

### 生命周期观察的可靠性（已冻结）

方案为有界、受权的观察记录加可合并事件提示，不另增每次状态变化的消息队列。普通服务观察固定的“完整实例＋镜像代次”，只关心仍有效或已经终结；原因区分退出、未发布撤销与成功 exec 淘汰旧镜像，不记录 STOP/CONT、父关系或运行状态历史。服务监督的其他查询与此分开。

一个固定镜像只有一次终结，可采用 ACTIVE→ENDED→释放，不需要保存无限变化版本。观察记录仍有防复用代次，确认必须匹配原记录及目标身份，不能影响复用后的新记录；编码及PREPARING/ACTIVE/ENDED值以本篇确切接口段为准。此前通用状态版本方案收窄为单次终结交接，不删除其他协议确实需要的版本。

观察记录从固定池预付或在接纳业务前保留，计入观察者配额；不足时拒绝新会话/继承，不在目标退出时临时申请。一个服务可按目标实例/镜像共用观察而非每 fd 一份；查询可有界枚举待处理记录，提示合并仍可恢复。服务退出时撤销其观察，但它持有的业务引用仍按服务自身死亡/下游协议收尾，不能把删除观察等同于停止 DMA 或完成所有清理。

普通业务观察须先获准使用机制，再凭服务自己持有的真实接收请求核验关联：可观察该请求 source 的镜像；孩子继承另须原子核对 source 是目标未发布孩子的合法构造者。核验期间相关请求/关系引用保持有效，不能只传任意 PID。观察归服务当前镜像，不默认跨该服务 exec/fork 继承，不授予信号、用户内存或 wait 消费权。显式监督授权也仅允许观察指定范围。

观察接口固定为observe/obsread/obsnext/obsack/obsdrop，不新增通用事件对象或公开OP。服务先保留本地会话与必要清理容量，再取得观察容量，最后安装业务引用，失败逆序撤销。已终结目标直接拒绝准备，不安装新可用会话。

终结记录在确认前持久可查。服务先关闭旧会话的新业务入口，在预付清理表稳定保存剩余引用/下游请求及必要 Life/资源引用，再确认观察；通知责任可解除，实际清理责任仍占配额。没有独立稳定清理记录时必须保留观察，不能先确认再临时申请空间。事件只提示至少有一项待处理，服务有界枚举排空；新终结保留待处理状态，最后检查与 recv 登记协调以免丢唤醒。首轮可扫描服务自己有上限的观察表，不预设复杂索引。

父 wait 结果与服务观察分别确认：FS 确认仅表明自身已接管该生命周期变化，不消费父的退出结果；父 wait 完成也不删除 FS 未接管的终结状态。观察与临时清理引用继续保持旧身份，直到安全解除，不要求保留整个用户地址空间或永久占运行槽。

发布前取消按孩子终结收尾；孩子发布后父死亡，不撤销孩子引用。成功 exec 是同实例的镜像变化而非进程退出，旧连接清理与新连接继承必须使用对应镜像和会话代次，不能“PID 未退出就不清理”或“一变镜像就关闭全部新旧连接”。该规则与08的目标独立引用/按需接入共同执行，旧终结不撤销已ACTIVE目标。

exec 保留的 File 引用须按专门协议先归属新镜像，旧观察不能删除已移交的新引用。服务自身死亡时旧观察可由内核回收，业务引用由服务死亡恢复链处理；观察表为空不证明下游 DMA 已停止。

#### 示例：确认通知后仍在排空块请求

FS 得知 A 的旧镜像终结，关闭旧会话入口并在预付清理表保存未完成 blk 请求和资源引用，再确认观察。blk 仍访问的共享页继续固定和计费，不能因观察已确认就释放。清理容量必须在接纳业务前保证，不在退出时赌临时分配成功。

#### 示例：核验之后孩子被撤销

FS 原子登记对未发布 B 的观察并取得其构造者 A 的关系，随后 A 被 KILL，内核终结 B。即使 FS 本地准备恰好继续建立一个 File 引用，B 的终结状态仍待处理，FS 随后撤销该引用并确认；B 的旧身份不会变成新进程。若 B 先发布再 A 死亡，观察显示 B 未终结，FS 保留 B 的会话。两种顺序不依赖 init 逐次转发退出消息。

### 直达后端的首次连接（已冻结）

以A已拥有FS控制连接、首次open某TTY后端为例。复用已建立后端连接时不重复转移Mem；VFS OPEN仍可交付本次后端CALL，核对真实目标后释放多余入口引用，普通文件继续复用FS路径。

1. A向VFS提交open并同意接收后端CALL权。VFS按可信A身份、路径和控制终端关系检查权限，保留本次File/节点引用及本地结果槽；不能因后续数据直达就跳过VFS。
2. VFS经其预配置控制权限请求TTY准备一份绑定A完整实例/镜像、访问模式及本次操作序号的会话。TTY只接受受信VFS实例的此类控制操作；应用即使有TTY CALL权也不能prepare他人会话。TTY先预付会话/清理容量，记录创建它的VFS实例和本次目标身份。
3. VFS已持有可授予的该后端CALL源授权，使用单资源reply交付A；其业务三字为[本次seq,session,prepare_token]。内核只转交调用入口，不理解文件权限或把CALL权当成任何File的访问权。
4. A用无槽[ATTACH,0,bootstrap_seq,prepare_token]向该后端接入并同意接收SharedMem。TTY从私有准备记录取得原VFS/会话关系，并核对真实IPC source、目标身份/镜像和阶段，登记A生命周期观察，预付共享槽/引用后回复受限Mem及[bootstrap_seq,connid,region_bytes]；冒领其他会话或过期准备拒绝。
5. A显式map并验证共享区协议/大小，短临界段把后端Handle、会话、Mem映射及File模式整体安装到预留fd结果位置，再返回open成功。此前不把半连接当有效fd，也不在信号处理路径复用该预留槽。

获得后端CALL权只允许向后端发消息，每次数据操作仍核验真实source及会话归属/模式；不能猜会话号访问他人File，也不能用该权访问UART/MMIO/IRQ。后端Handle绑定具体实例/镜像，后端重启不静默改指向新服务。服务可共享同一条调用授权，但会话/缓冲使用期和关闭引用仍独立。

#### 未接入客户端的准备清理

TTY在步骤2收到的直接请求source是VFS，尚无A发来的直接请求，不能伪装成拥有对任意A的普通观察权限。准备会话先归该VFS控制关系负责；TTY可凭直接请求观察VFS，VFS则凭A的open请求观察A。A在接入前死亡由VFS可靠发起补偿；VFS先死亡则TTY按旧VFS代次清理其准备会话。A接入时TTY才凭真实A请求登记自身对A的观察，不透传REQUEST授权给第三方。

准备记录受每客户端/每VFS及后端总容量限制，并有明确的接入截止；超时后拒绝迟到接入、幂等撤销准备。普通open接入准备固定10秒，计费按实际持有量；fork/exec/spawn继承的ACTIVE引用不适用这个TTL，不能因未领取而撤销，更不能把仍使用的共享页强制复用。已有有效数据会话的故障清理继续按原VFS/后端实例和既有恢复策略执行，不因重连而复活旧fd。

#### 示例：拿到TTY调用权后A退出

A已取得TTY CALL Handle，但尚未接入会话。内核清理A的本地授权，VFS观察到A终结并撤销本次TTY准备；即使VFS也在此时死亡，TTY对旧VFS的观察仍让该准备进入收尾。TTY不需要A完整管理权，也不依赖A发送最后一次close。若A已接入、SharedMem已交付，则TTY还按A自己的终结观察排空在途请求，等待实际访问结束再回收页。

#### 部分成功与缓存

Mem交付/map失败、权限准备失败或服务失联均用原操作序号补偿；本地CALL权free与后端File关闭分别执行，不能free后以为后端会话已经消失。连接可以缓存供多个File复用，缓存淘汰需引用归零且在途访问已结清；关闭一个fd不撤掉其他File仍使用的连接。缓存是用户态优化，不减少服务每次请求的身份/模式校验。

固定后端结束的客户端依据只取原绑定RPC返回的内核ERR_PEER，或原异步CALL在未产生RPC时的真实返回窗口；业务负值、REVOKED、CANCELLED和超时不产生该证明。标记只作用于原PID/image及目录代次，停止新接入，仍保留其他LIVE本地引用/别名。最后alias关闭后可依旧后端结束进行本地责任恢复；已有CLOSE的RPC/页仍须等待RQ_FINISH、处理已安装资源并ACK，继而归还记录。受信代收尾及下游/DMA安全沿[04的rqclean约束](04-ipc.md#rqclean-管理代收尾已确定)，后端死亡不自行解除隔离。此处本地恢复完成不改写应用已经确定的I/O错误，也不替代生产管理者的授权或实际排空证明。

### fd 标志与共享打开状态（已确定）

libsys 的本地 fd 表保存每个描述符独立的 FD_CLOEXEC；服务端 File 保存共享偏移、访问模式及 O_APPEND/O_NONBLOCK 等文件状态标志。客户端缓存不能成为共享状态的第二权威。
dup/dup2 和进程继承引用同一 File，偏移及可修改状态标志共享，访问模式不因复制改变；独立 open 创建不同 File。
dup 新描述符的 FD_CLOEXEC 按该接口规则初始化，不机械复制源 fd 标志；设置某个描述符的 FD_CLOEXEC 不影响其他描述符。
修改共享文件状态须经后端协议原子提交，其他引用后续操作观察一致结果；F_SETFL 仅允许已声明可修改位，不能改变原访问模式或忽略不支持选项。
O_APPEND 写入由 fs 将选择当前 EOF 与提交实际接受的数据/长度作为同一文件上的原子操作，不仅串行同一 File；独立 open 的追加也不能互相覆盖。
追加写可按接口返回短写，但不能先预取 EOF 后解除协调再提交；追加原子性不等于持久化，也不要求整个任意大写入都无短写。

### dup2 的原子替换（已确定）

dup2 不实现为 close 后再 dup。先校验并固定有效源引用；源/目标相同则校验后返回，不清除原描述符标志。
源/目标不同时，先取得源 File 新引用并保证其关闭容量；旧目标使用发布时已有的收尾保证，失败保留目标原样。准备期间本地标记与引用须能抵御信号重入，不能保存裸 fd 数字后假定其未复用。
提交在短暂屏蔽可捕获信号的本地临界段完成，重新核对表项代次，将目标替换为已准备引用、更新 fd 代次并按接口清除 FD_CLOEXEC；临界段不等待 IPC。
旧目标引用在提交前转交有界收尾记录，提交后按原服务实例/会话/引用/操作序号释放，不能以已复用 fd 数字发出关闭操作。
提交前失败完整回滚，提交后旧目标关闭失败不回滚新目标、不误报整个替换未发生；后台收尾失败可诊断，仍遵守有限配额和服务故障清理协议。
本地引用记账与后端引用协议保持一致：同进程别名可按协议聚合持有，但最后本地引用/在途操作消失前不得释放后端持有。准备方式须在实现规格中选定，不额外假定每次 dup 都要新增 IPC。

### close 的提交与后端收尾（已确定）

原生关闭分为准备、摘除提交、后端收尾。准备时校验 fd/代次并固定发布前已保证的有界收尾责任；校验失败不改变原表项，不在此临时申请清理容量；提交时短暂屏蔽可捕获信号、原子摘除并更新代次，不等待 IPC。
提交后 fd 可复用，不因后端失联或关闭失败恢复旧表项。旧引用由收尾记录按服务实例、会话、引用和操作序号释放，不按 fd 整数重新定位。
最后描述符引用消失后，在途操作仍按其引用完成或取消；底层 File/共享槽不能因本地 fd 摘除提前回收。收尾结果不明则查询原操作或纳入退出清理，不关闭同号新文件。
POSIX 关闭映射采用：摘除前被信号中断可返回 EINTR 且保留 fd；摘除后等待关闭完成时被信号中断返回 EINPROGRESS，fd 已失效且后台继续收尾；关闭完成才返回成功，不能仅以关闭请求已排队宣称完成。
此处固定中断与描述符状态的对应关系，不替代其他错误及后端特定关闭效果的逐项定义；完整规则及选项仍须核对 POSIX.1-2024 正文。close 不隐含 fsync，延迟持久化错误按既定同步协议报告。

审计边界：不能将准备失败保留表项泛化为 POSIX close 的任意池满错误。

### open/close 的信号重启边界（已冻结）

read/write 已讨论语义见 [信号中断与重启](11-terminal.md#readwrite-的中断与重启已冻结)。

open：未交付或确认尚无副作用时，无 SA_RESTART 可中断并清理准备；有则继续安全步骤。原操作已经完成时，稳定保存 File/授权/共享区及本地 fd 保留槽，handler 返回后只完成一次安装，不重新打开路径；handler 不得占用尚未发布的保留槽。O_CREAT/O_TRUNC 可能已经改变目录或内容，不能凭通信中断从头重做，也不能为回滚擅自 unlink 已创建文件或恢复旧内容。已提交但结果未明时跟踪原操作；后续接入失败按原操作补偿临时引用，已经发生的文件系统效果不承诺回滚，具体错误仍待逐项审计。

close：保留前节的摘除前 EINTR/保留 fd、摘除后 EINPROGRESS/fd 已失效的区分，EINPROGRESS 仍保留标准审计标记。SA_RESTART 只允许继续原关闭操作；摘除后不能再次按原 fd 数字执行 close。摘除前若需跨 handler 继续，须重查原表项代次；若已被 handler 关闭/替换，不能摘除替代项，返回EBADF，指原表项代次已无效。摘除后的原关闭等待可按同一操作号继续，故障不能恢复已释放的 fd。服务访问/DMA 的最终排空仍独立于标准 close 返回。

示例：close(3) 已摘除旧 File，handler 的 open 得到新 fd3。无 SA_RESTART 的外层方案返回 EINPROGRESS；有 SA_RESTART 则只跟踪旧 File 的关闭结果。两者均由原收尾记录继续持有旧引用，不向新 fd3 发出关闭。

open中断从原RPC领取服务真实结果；仅QUEUED取消或原reply保证零效果EINTR才按接口重启，fd安装窗口按预登记Rctx处理；close前表项变化EBADF，后失效EIO，中断按EINTR/EINPROGRESS处理。POSIX.1-2024 正文与各后端关闭完成条件仍需核对，不能以 Linux 行为替代。

### close 的资源保底与完成点（已冻结）

本轮已读取 Austin Group #529 标记的最终接受文本（note 1200）：捕获信号可对应 EINTR/fd 保留、EINPROGRESS/fd 已关闭或成功；除 EBADF/EINTR 外的错误要求 fd 关闭，并禁止 EAGAIN/EWOULDBLOCK。这支持前节区分 fd 状态的方向，但不能用较早草案或讨论者意见替代最终文本，也不等于完成 POSIX.1-2024 全文审计。posix_close/POSIX_CLOSE_RESTART 的 SDK 范围及 SA_RESTART 的具体要求仍待核对，不因参考文本出现就自动纳入本轮接口。
依据：[Austin Group #529 最终接受文本 note 1200](https://www.austingroupbugs.net/view.php?id=529#c1200)。本轮直接访问2024 close/poll正文仍403。

用户已接受：将关闭责任在描述符发布前预留，而不是 close 临时申请：open、dup、dup2 新引用、pipe 两端、fork/spawn 继承及 exec 新镜像交接发布 fd 前，都先保证对应逻辑关闭和必要后台清理容量。close 只校验/固定既有责任，再摘除并移交；不得因清理池满留下一个无法合法关闭的 fd。这里规定的是容量保证，不强制每 fd 复制一个独立结构；同一 File 引用聚合方式及对应上界随布局冻结。关闭控制所需 Rq/服务处理名额也要保底，不能只预留本地记录却仍须临时争抢全部普通请求容量。

摘除后原记录跨 fd 复用独立存活。新 fd 需要新的可用关闭容量；旧关闭/设备访问尚未收尾造成背压时，在新 open/dup 等发布之前按该接口实际耗尽类别拒绝，不假装 fd 表满，也不为接纳新 fd 提前回收旧记录。dup2 按同一保证处理：旧目标使用其既有保证，新引用在替换前取得自己的保证；失败仍保留原目标。

close 成功点是本描述符引用的逻辑释放已经落实：仅减少本地聚合别名时可由本地提交确定；需要通知后端时须取得绑定原引用/操作序号的有效关闭结果，不能仅以排队发送作为成功。最后读写端的逻辑存在状态按剩余合法描述符及在途操作引用更新，避免服务仍把已完成关闭的唯一端点视为无限存活。后端特定的排空/关闭效果须另列；服务确认逻辑关闭不证明 DMA 停止，也不要求为了内存回收而把所有共享页收尾塞进标准 close 成功条件。

例子：A 关闭最后一个管道写描述符且没有在途写操作，B 等待读取。A 不能在 FS 尚未落实写引用释放时返回成功，让 B 永久等一个已不存在的写者；FS 确定写端逻辑消失并更新可读/EOF 状态后可返回成功，遗留控制 Rq/共享页按自身安全条件收尾。若 A 在等待确认时被捕获信号中断且 fd 已摘除，返回路径按原 EINPROGRESS 方案保留后台责任，不再次 close 同号新 fd。

关闭容量为每进程256条责任记录上限及2个控制清理Rq保底；别名可聚合、每fd仍独立保留代次责任；后端期限1秒后故障EIO，摘除前原代次变化EBADF。以上预留修订和成功点已被用户确认；原有按服务实例/操作序号收尾、不误关复用 fd 的方向保持。

### 文件读写与持久化语义（已确定）

read 返回实际字节数，0 表示 EOF；write 返回实际接受字节数。允许短读写，偏移只推进已提交的实际字节数。
pread/pwrite 指定偏移，不改变打开会话偏移；同一打开会话的 read/write 串行提交结果与偏移，继承引用共享该顺序。
独立 open 使用独立会话与偏移，服务不得因不同客户端本地 fd 值相同而混淆。
尚未执行的请求可取消；已接收请求把实际结果reply到原Rq，客户端仅查询原RPC，不以新Rq/原业务序号重发副作用。
read实际数据保留在本次原共享槽，服务reply后停止访问，调用者复制/保存后才释放槽；rqpoll只重复读取原短回复，不重新读文件或推进偏移。原槽和执行记录均有预付配额，耗尽背压，不另建服务结果快照表。
write 成功表示服务已接受、对后续读取可见，不代表已落盘；缓存有界并可批量回写，不要求每次 write 执行设备 flush。
fsync 成功表示此前相关数据及必要元数据完成约定的设备持久化协议；必须追踪脏数据、回写错误和本次同步覆盖范围。
close 释放本进程会话引用，不隐含 fsync；延迟写回错误须通过后续同步/查询明确报告，不能静默当成持久成功。
崩溃后未同步数据可按磁盘协议部分保留，但目录/分配结构必须一致，不出现重复分配、悬空引用或释放块仍可达。
同一Rq只执行并回复一次，不承诺跨新Rq或跨服务崩溃exactly-once；未取得原结果的写遇服务崩溃可能已执行，报告EIO且不自动重放。

旧后端独立确认终结后，READ/WRITE的原生PEER空失败结果仍须等原RQ实际FINISH/ACK，才归还该操作的页与仍被pin的File；未提交的准备可直接撤销。共享DONE、已写入的槽字节和退出通知均不能替代排空或确认字节数。另一操作的失败不覆盖这个请求已经固定的成功，成功数据仍沿原槽保存/复制再ACK。私有收尾返回0只表示责任已经转移，不是read的EOF或write的零进展；不改原失败、不重发I/O、不替调用者unpin或关闭别名，创建/CLOSE/命名等事务保留各自的收尾规则。

- [ ] 验证短读写、EOF、共享偏移顺序和 pread/pwrite 不改变会话偏移。
- [ ] 注入执行后信号/完成提示丢失，rqpoll/rqwait原RPC返回同一结果，原read槽数据不重读，不再次推进偏移或写入；服务失效不伪造可恢复业务结果。
- [ ] 覆盖有界缓存满、批量回写、回写错误和 fsync 覆盖边界；不以普通 write 成功冒充持久化。
- [ ] 崩溃恢复核对已同步数据与元数据一致性，并保留未确认写的结果不确定性。

### 有界 I/O 与短返回（已确定）

每连接使用预配置有界共享槽，单次原生 I/O 不因应用请求长度临时分配同等大共享区；先取得独占槽，再快照/传输本次允许数量，完成及收尾后才复用。
POSIX read/write 可按实际完成量短返回，不强制在库内循环到全部请求长度；应用/stdio 依据返回量继续。请求序号、结果快照与偏移只覆盖本次实际接受量，不以原请求总长推进。
配置的槽容量/单请求上限须保证不超过公开 PIPE_BUF 的管道原子小写入可完整一次提交；不能拆成多个可交错请求。非阻塞原子写空间不足按既定规则失败，不以短写绕过原子性。
单次 O_APPEND 请求实际接受部分作为一次追加提交，不在内部多块传输间释放协调再插入其他追加；短返回不等于允许破坏本次接受部分的原子边界。

#### 示例：4 KiB 传输处理 10 MiB 写入

应用请求写10 MiB，普通文件路径本次最多取得/复制4 KiB到独占槽并发起一个服务操作，返回实际接受量；调用者按返回值继续。若为不超过 PIPE_BUF 的管道写，配置必须容纳完整写入，不能借槽小拆分。

### VFS 分层（已确定）

fs 内部提供 VFS，不新增独立 VFS 服务进程；具体磁盘格式、缓存和日志是后端实现，不成为统一文件接口的约束。
Mount 表示挂载实例/位置，Vnode 表示命名节点，File 表示打开状态及共享偏移/访问模式/后端引用；用户 fd 引用经授权的 File 会话。
File 可关联 Vnode，也可关联无路径的管道/网络端点，不为每个 fd 强造命名节点；偏移只对支持定位的后端有意义。
后端提供精简节点/文件操作表，磁盘 FS、tmpfs、devfs 共用打开和路径语义；不把磁盘 inode 布局直接当作 Vnode ABI。
Vops 负责 lookup/create/unlink/rename/getattr/readlink 等节点和目录关系，Fops 负责 open/read/write/seek/sync/close/readdir 等打开实例操作。
Vnode 标识节点，File 保存一次打开的偏移/访问模式/后端状态；同一节点多次独立 open 各有 File，继承引用共享 File。
设备节点经 open 可转为设备后端 File，不要求 tty/net 等设备服务实现目录操作；不支持的方法返回明确错误。
同类节点/打开实例共享静态操作表，不为每个对象复制表，不因分表额外引入 IPC 或多层分发；不照搬 Linux 完整接口。
后端支持有界 Fsop 异步完成，保存 Mount/Vnode/File 引用而非临时栈或未快照共享参数指针；单个 File 的偏移操作串行，不持全局 VFS 锁等待 I/O。
Vnode 身份使用挂载实例、后端节点编号及代次，不使用路径字符串；删除名字不销毁仍打开的节点，最后打开/在途引用结束才回收，恢复也处理未关闭已删除节点。
VFS 统一路径解析、挂载穿越、权限、打开/关闭及引用生命周期，各后端不重新解释绝对路径与挂载关系。
当前目录保存 Vnode 引用，目录重命名后仍有效；用户态缓存的路径仅供显示。继承 fd 共享 File，独立 open 创建独立 File。
“一切皆文件”统一名称和 fd 操作，不要求设备/管道/网络端点具备磁盘路径、文件偏移或 seek 能力；不支持的操作明确报错。
devfs 提供设备服务命名，/dev/tty 按请求者控制终端解析；打开设备会话不授予 MMIO/IRQ/物理内存权限。
tmpfs 与 proc 类虚拟后端可通过同一接口实现，具体首轮后端功能及工具验收在 VFS 接口确定后细化，不能用空挂载点冒充已支持。
路径与 open 授权归 VFS，数据可直达获授权后端；直达绑定必须由 init/VFS 与后端按完整调用者身份建立，不信任客户端自报 PID 或任意服务地址。
直达后端与 VFS 使用同一打开状态/引用协议，不能两边各维护独立偏移或关闭账目；后端崩溃使相应打开会话失效，不静默指向新实例。

设备文件仍经 VFS 路径解析、权限检查和 File 创建，不依据 /dev 前缀直接绕过打开语义。
打开设备采用准备/发布：VFS 检查调用者和节点，后端准备绑定该调用者的会话，VFS、后端与获权客户端按受限连接协议配置必要调用授权/共享区，不逐次经 init，全部成功才返回有效 File 会话。

受限连接使用CALL绑定的单资源reply，CALL权限不授予目标管理权，普通grant仍不能安装到任意运行中对端。具体双方同意/请求绑定/容量及取消原子点见 [授权审查](03-process.md#grantrevoke-的目标边界审查收口)，冻结前不宣称直达连接接口完整。
客户端 fd 保存后端本地调用句柄、会话标识、访问模式和通道，不能自报任意服务地址；后端每次检查完整调用者及会话访问模式。
数据可按 File 后端直接 RPC 至 tty 等服务；普通文件仍由 fs 提供，VFS 打开语义与是否经 fs 进程转发数据是不同问题。
同一后端连接可承载多个 File，关闭一个 fd 不撤销其他打开引用共用的服务句柄；VFS 协调关闭/收尾及后端引用释放。
打开任一步失败按操作序号补偿本次会话/授权/共享区，不暴露半绑定；后端重启使旧会话失效，不复用同号新会话。

### 路径与挂载（已确定）

VFS 为每进程保存 root/cwd 目录引用：绝对路径从 root，相对路径从 cwd 或指定目录 fd 开始；继承/退出明确增减引用。
目录重命名不使 cwd 失效，.. 不越过该进程 root。路径根不撤销已有 fd/资源，不宣称本身构成完整沙箱。
统一命名树由 init 授权管理挂载；路径进入挂载后端，从后端根的 .. 由 VFS 返回挂载点父目录，并遵守调用者 root。
Mount 被打开文件、目录引用、在途请求及未同步状态持有；卸载遇这些使用返回 BUSY，不支持无协议的强制释放。
路径总长度、组件长度及符号链接跟随次数有编译上限；绝对链接从调用者 root，相对链接从链接所在目录解析。
是否跟随最后组件按操作语义决定，防止 unlink/readlink 等误操作链接目标；跨挂载 rename 返回明确错误，不隐式复制删除。
查找与 create/unlink/rename 的最终提交协调，不能对路径查找后已被替换的节点误提交；目录引用/fd 使用仍检查访问权限。
根目录、挂载和引用变化的同步协议在 VFS 操作状态机中执行，不交由每个后端各自解释完整路径。

### 符号链接解析（已确定）

VFS 统一展开符号链接，后端只提供有界链接内容；创建链接不要求目标存在，内容原样保存，允许悬空链接。
相对链接从链接所在目录继续，绝对链接从调用者 root 继续，不以客户端 cwd 替代链接目录。完整路径解析共用跟随计数，跨挂载或多次展开不重置，超限明确失败。
展开路径总长、组件和暂存容量有界且查溢出，超限不截断；本次解析取得稳定链接内容快照，不能混用并发变化前后的内容。
普通 open/stat 跟随最终链接，lstat/readlink 访问链接自身；unlink 删除链接目录项，rename 操作源/目标名字而非追随其最终链接目标。O_NOFOLLOW、O_EXCL、末尾斜杠等组合按具体操作冻结，不能由一条全局跟随规则代替。
后续命名修改仍按稳定节点/目录项及提交前版本复核执行；链接展开不绕过 root、目录搜索权限或已有引用生命周期。

#### 示例：链接所在目录与目标

/home/leo/config 的内容为 ../../etc/config，则从 /home/leo 解析相对目标，不从调用进程 cwd 开始。
/tmp/current 的内容为 /home/leo/data，unlink("/tmp/current") 只移除 current 目录项，data 不变；目标不存在也不影响 readlink 获取链接原内容。

### 路径组件顺序与最终组件（已确定）

路径解析保留组件顺序、末尾斜杠及本次操作对最终组件的要求，不在解析前用字符串规则消除 name/..。符号链接展开后再按实际节点关系处理后续 ..，同时遵守 root 与挂载规则。
末尾斜杠施加目录解析要求，不能直接删掉后按普通文件打开；空字符串在本阶段普通路径接口中报错，不解释为 cwd。
O_NOFOLLOW 限制最终链接，不等于禁止前缀链接；O_CREAT|O_EXCL 遇已存在最终符号链接即拒绝，即使目标不存在。与末尾斜杠等组合按操作规范逐项确定错误，不简单覆盖规则。
删除/重命名 . 和 .. 须专门识别并按接口拒绝，不当可直接修改的普通目录项；重复斜杠及开头斜杠的支持策略须统一，不借字符串处理绕过权限检查。
解析使用有界迭代状态机，符号链接展开替换待解析内容，不递归调用完整解析器；跟随计数、暂存空间和 Fsop 续执行状态均有上限。

#### 示例：不能提前消除 `link/..`

/a/link 指向 /b/c，解析 /a/link/../file 时先进入 /b/c，再处理 ..，得到 /b/file；不能先删除 link/.. 得到 /a/file。
普通文件 data 后加 / 不得成功作为普通文件打开；open("link", O_CREAT|O_EXCL) 在 link 为悬空链接时仍失败，不能在其目标处意外创建文件。

### cwd、改名与路径重建（已确定）

cwd 是稳定目录节点引用，路径是当前命名关系的结果。目录改名不改变 cwd 所指节点，相对查找仍从该节点开始；shell 的 PWD 等缓存不是 FS 查找权威。
chdir 先取得目标目录引用并检查类型/搜索权限，成功后原子替换上下文 cwd、更新版本并释放旧引用；失败保持原 cwd。fchdir 使用有效目录 fd 的节点引用，不转成路径后重新查找。
getcwd 从当前命名关系重建路径，跨挂载和 root 边界按既定规则处理；并发重命名时校验版本并有界重试，不能返回由不同时刻碎片拼出的路径。缓冲不足/不可达/名字消失按兼容接口报错，不静默返回旧路径。
目录被删除后，cwd/目录 fd 引用可维持节点生命周期，但不保证仍有可返回的路径；不能自动切换到根目录。删除后的操作规则见下文。
cwd 持有挂载使用引用，相关挂载忙时不直接卸载。

#### 示例：当前目录被改名

sh 的 cwd 指向目录 D，名字为 /home/leo/work；另一进程将 work 改名为 project。sh 的 cwd 引用仍是 D，open("a.txt") 仍从 D 查找，getcwd 成功时返回 /home/leo/project，而不是缓存的旧名字。
若名字随后被删除且无法构造可达路径，getcwd 返回明确错误，cwd 不擅自改为 /；新的显式 chdir 成功后才替换引用。节点保留不等于允许向已删除目录创建内容。

### 已删除目录的状态（已确定）

目录区分 LINKED 与 REMOVED，REMOVED 不等于立即回收；此状态独立于普通文件硬链接计数，具体磁盘目录链接计数仍遵守对应格式规则。
rmdir 在同一命名事务中检查空目录、阻止新内容插入、标记 REMOVED、移除目录项并更新父目录及相关链接计数；不能在空检查与删除之间允许插入。
REMOVED 禁止新内容创建，旧名字不再查到原节点；已有 cwd/目录 fd 可保留节点引用、查询原节点状态，getcwd 无可达名字时报错，不自动切换目录。
保留必要的父目录关系及稳定引用供已有上下文解析 ..，同时遵守进程 root 边界；该关系不重新发布目录名字、不以旧路径字符串查找新父节点。
最终释放须等待 cwd/目录 fd/在途引用及持久回收条件满足，再解除保留的父关系引用；父链引用计入有界节点/挂载资源，不能依靠循环引用永久阻止清理。

#### 示例：删除后同名重建

A 的 cwd 为 /tmp/work，B 对空 work 成功 rmdir。A 的 getcwd 失败，open("new", O_CREAT) 失败，但 chdir("..") 可按保留父关系回到 /tmp，成功后释放旧 cwd 引用。
B 再 mkdir /tmp/work 得到新节点；A 的旧目录引用仍指向原 REMOVED 节点，不自动转移。inode 槽若复用必须使用新代次，且旧节点仍有使用引用时不能先复用其身份。

### 文件时间戳（已确定）

atime 表示最近访问，mtime 表示最近内容修改，ctime 表示最近元数据状态改变而非创建时间。三者保存于共享 inode/Vnode 权威状态，不按每个 File 分别维护。
首轮采用明确的访问时间更新，不引入 relatime/lazytime 策略；有效读取按接口规则更新 atime，写入/截断等更新 mtime/ctime，权限/链接数等修改更新 ctime。零长度、失败和部分完成等边界逐接口冻结，不能将所有调用尝试视为有效访问。
目录项增删/重命名更新相关目录及规范要求的节点时间；每种操作明确受影响节点。单纯 open/close 不视为内容修改，O_TRUNC 等具有实际修改效果的操作另按其效果处理。
时间取实时时钟；未校时限制见 [时钟模型](05-events.md)。更新随对应操作提交到内存权威状态，可合并回写，不为每次 read 同步写盘；持久化仍按既定日志/同步覆盖范围执行。
utimensat/futimens 按权限修改 atime/mtime，ctime 由系统维护；显式时间、当前时间及保留原值的参数语义逐项检查，不能由客户端任意设置 ctime。

### 路径检查与原子提交（已确定）

请求先快照路径参数，解析后固定 Mount、父目录与目标节点引用；权限检查与最终修改必须针对同一节点身份/目录关系，不保存路径后无条件重新查找修改。
提交前取得相关节点的修改权，重查目录项、节点代次、版本及权限；变化则有界重取或明确失败。异步 I/O 不持全局 VFS 锁，引用与修改状态通过 Fsop 保留。
open(O_CREAT|O_EXCL) 将不存在检查与创建作为同一命名提交，竞争创建只能一个成功；unlink 对已检查目录项提交删除，已打开节点不随名字删除提前回收。
同文件系统 rename 将源移除、目标替换/安装作为一次命名变更，不暴露中间缺口；跨文件系统返回错误，不隐式复制删除。跨目录修改权按稳定节点身份的固定顺序取得，同目录只取一次。
目录移动检查祖先关系、不形成环，验证时须与相关并发重命名协调，不能只在取得修改权前检查一次祖先链。具体命名事务范围及版本规则在后端实现规格中冻结。
提交前核对父目录搜索/写权限、sticky 规则和替换条件；access 不作为后续 open 的授权证明。内核不解析路径或执行文件权限策略。

### 硬链接与节点回收（已确定）

nlink 表示命名空间中指向 inode 的持久链接数，区别于 File/在途使用引用及内存缓存引用。纯缓存引用不能永久阻止无链接且无使用者节点回收磁盘空间；回收前须从缓存撤下或使缓存节点失效。
link 原子提交新增目录项与增加 nlink；unlink 原子提交删除目录项与减少 nlink。跨文件系统硬链接拒绝，不向普通程序提供目录硬链接，链接计数上限和溢出显式检查。
两个名字指向同一 inode，内容/权限修改一致；独立 open 仍各建 File，不因硬链接而共享打开偏移。具体符号链接跟随规则按对应标准接口冻结。
nlink降为0时，与命名删除在同一事务形成持久待回收成员（已分配inode且nlink=0，见下文恢复扫描）；存在打开或在途使用引用时仍允许已有 File 按权限访问，不允许通过消失的名字重新查找。
最后使用引用消失后，按既定日志协议分批回收块和 inode，持久记录回收进度；重启可幂等继续，不能出现已释放块仍被可达元数据引用。
整机重启后旧进程引用不存续；fs 单独重启须先按实例恢复协议使旧会话失效并完成下游 I/O 安全收尾，不能仅凭内存引用表丢失回收仍在使用的缓冲。
Vnode/File 身份包含挂载实例、inode 编号及代次；inode 槽复用递增代次且不回绕，旧缓存、会话和回复不能访问新节点。

### 非阻塞 I/O 与多路等待（已确定）

统一 fd 接口支持非阻塞模式及 READ/WRITE/HUP/ERROR 就绪状态，后端检查实际 File/会话权限，不以通知代替授权。
READ 包括可取得 EOF，WRITE 表示可接受一定输出，不预留整个请求长度；状态可变，非阻塞 I/O 无进展返回 WOULD_BLOCK，有部分进展返回实际字节数。
采用电平式查询；动态客户端的等待方案复用异步CALL/defer及内核请求完成事件，不要求后端额外取得客户端notify授权。后端在登记等待时原子重查状态，避免查询与挂接之间丢唤醒；引导期已授权的静态共享环通知仍按自身协议使用。
用户态 poll 汇总各 fd 状态，有就绪则返回，无就绪才 recv 等事件；事件可合并，醒来重新查询后端状态。
poll 由运行库结合后端协议与内核事件实现，内核不理解 fd/socket；订阅与完整调用者、打开会话及 fd 本地代次关联。
关闭/复用 fd 不能命中旧订阅；后端退出唤醒等待者并报告 HUP/ERROR，进程退出清理其订阅；数量受编译配置限制。
订阅登记、关闭、通知及 wait 信号中断的清理属于有界操作，不能因 poll 退出泄漏后端订阅；定时截止由统一逻辑定时器管理层处理。

- [ ] 检查状态变化发生在订阅前/中/后、通知合并、假唤醒以及查询后就绪消失。
- [ ] 验证非阻塞无进展/短结果、fd 关闭复用、后端死亡、poll 被信号中断及订阅配额回收。

### poll 调用契约（已确定）

poll(fds, count, timeout) 由 libc/libsys 固定 fd 会话/代次与请求事件，按后端登记订阅并取得当前状态；有就绪项立即返回，否则事件等待/单调截止后重查状态，填写 revents 并清理本次订阅。
后端订阅与当前状态检查原子协调，通知仅提示查询，不能将通知位直接当可读/可写。订阅绑定原 File 会话及 fd 代次，不追随信号处理期间关闭/复用的同号新文件。
timeout=0 不等待，正值转为一次固定单调截止、虚假唤醒不重置，负值不设超时；零描述符可纯超时等待，不要求 fs 在线。
负 fd 忽略，无效非负 fd 置 POLLNVAL；返回 revents 非零数组项数量，不计事件位数。HUP 与可读可并存，已缓冲数据不因挂断直接丢弃；其他标志按标准逐项定义。
信号中断、服务失联、订阅取消/引用释放按既定状态与收尾协议；正常结果不提供资源预留，调用者实际 I/O 仍可能遇到状态变化。

#### 示例：管道状态与合并提示

poll 等待管道可读，写端发布数据并通知。即使多次通知合并，poll 重新查询仍能得到 POLLIN；写端全部关闭且缓冲非空时，可同时观察可读和挂断，继续读取已有数据再得到 EOF。

### poll的Rq等待实现（已冻结）

方案保留用户态poll，不新增poll syscall或动态notify资源交付。libsys按后端连接分组，把同后端的一组File/事件项放入本次受限共享槽，每后端最多保留一个异步等待Rq；POLL固定4字参数放args、128条记录正好一数据页，不是每fd一个内核订阅对象。

1. 固定原File引用、fd代次和输入事件，先向所有相关后端做立即状态查询并汇总，不在发现第一个后端就绪后跳过其他后端的稳定就绪项。timeout=0只做这轮查询，不登记等待就绪的长期Rq；“不等待”指不等数据就绪，不承诺跨进程控制请求无调度开销，服务查询协议不得defer去等设备。
2. 没有就绪且尚未到固定截止时，向各后端异步提交检查并等待请求。后端原子检查所列对象：已就绪则立即reply，否则成功defer并保持本次等待；状态变化时完成该Rq。初查和这一步之间发生的变化由重查捕获，不需要原子跨多个服务登记。
3. libsys等待内核Rq完成提示或自己的逻辑定时器，提示可合并。完成后保存对应结果，取消不再需要的等待，并查询/汇总其他后端当前状态；若只是虚假/已消失的就绪且期限未到，则重新登记。各后端并不构成全系统同一时刻快照，不能依赖结果预留资源。
4. poll返回、信号中断或超时后，所有未完成等待均显式rqcancel；已被后端接收的取消等待在后端结束访问前保留槽/Rq，由预付清理记录继续收尾。成功结果先保存再ack，不能为尽快返回复用仍被后端写入的revents槽。

实现需预留本轮各后端Rq、快照/结果区及取消收尾容量，不能借信号/控制专用预留；不足时在部分提交前拒绝，或对已提交部分完成明确补偿，不静默少观察几个fd。后端长期名额满仍可用即时名额回复资源不足，不让poll占满后取消也无法处理。大数组以有界快照和批次处理，不让单次查询无限阻塞其他客户端。

后端reply是共享结果写入结束的承诺，其业务结果可以是零就绪、HUP/ERROR或状态变化；内核只报告Rq完成。后端死亡走已有PEER失效及连接清理，不把“无法取得状态”伪装成正常零就绪。

相对持久notify订阅，本方案增加每轮初查/重登记的控制RPC，减少动态通知授权和独立订阅生命周期；分组与已有连接可复用，实际吞吐/延迟必须测量，不能声称必然更快。单后端的确定性优化只有在同样覆盖全量查询、取消和快照语义时才采用，不先增加第二套接口。

#### 示例：同时等待TTY与管道

A先查询TTY和FS中的管道，都无就绪；随后向两个后端各提交一条异步检查/等待。管道写入发生在初查与登记之间，FS登记时重查发现可读并立即reply。A收到Rq完成提示，检查TTY当前状态并汇总，取消无须继续的TTY等待；TTY确认收尾前其共享槽不复用。整个过程不要求TTY持有A的notify句柄。

### poll超时、故障与返回结局（已冻结）

区分用户等待就绪的期限与短控制查询的故障期限。用户timeout按调用时单调时钟形成一次固定截止，不因虚假唤醒、分组查询或重新登记重置；timeout=0不登记数据就绪等待，负值不设置用户就绪截止。短状态查询必须在后端即时处理并回复，不defer等待设备；所有本轮控制查询共用有界故障截止，不给每个后端重新加一整段时限。

控制故障期限是连接/服务策略及既有逻辑定时器管理的一部分，不是新的内核timer对象，也不因用户timeout为负就禁用。它只约束需要立即回答的控制查询；已经合法登记、正在等待就绪的defer请求不能因超过这个短期限就认定服务故障。当前默认CONTROL_NS=1秒，见本篇首版fd/poll规格和14；它是故障策略，不是硬件响应保证，也不代替真实访问排空。

| 情况 | 用户态结局及边界 |
| --- | --- |
| 初查成功，暂无就绪，用户期限到 | 返回0，不表示任何后端失败；取消剩余等待并保留必要后台清理 |
| timeout=0且初查成功 | 返回本轮就绪项数或0，不留下等待设备的订阅 |
| 负fd | 忽略该项，revents为0 |
| 非负fd在本地无有效对应 | 该项POLLNVAL，按有事件的数组项计数，不把整个poll当权限成功 |
| 后端实例/镜像已明确失效 | 旧连接相关项报告POLLERR；仅有明确流挂断语义时再带POLLHUP，不因任意RPC错误猜EOF |
| 即时控制查询超过故障期限 | 本次poll走明确控制失败，不伪报零就绪；也不凭超时宣布进程已死或自动重建连接 |
| 本地/后端请求与暂存容量不足 | 整体准备失败或补偿已提交部分，不静默少观察fd；标准errno按统一映射冻结 |
| 信号在结果结局前中断 | 结束本次等待并走中断路径，取消/收尾独立保持；已固定成功结果不改为中断 |
| 用户输入/输出缓冲非法 | 受检查复制失败，清理本次订阅；不以结果复制失败为由重复poll或I/O副作用 |

用户就绪期限不是硬实时保证：跨服务查询、执行调度和结果复制有运行开销；初查尚无可信状态时不能因期限已过就编造“全部未就绪”。应有界取得本轮查询结局，或走控制失败，而不是无限等失联后端。该实现选择及故障errno须在兼容审计明确，不把短控制等待称为已经实现严格实时poll。

就绪、期限与信号的竞争以运行库本次结果提交点为准：先固定合法就绪结果则保留成功；先决定超时/中断则后续完成只收尾，不复活本次调用或覆盖同号新fd。没有业务副作用的状态查询可在明确协议内重查，未归还共享结果区仍不能复用；poll返回也不直接消耗管道/TTY字节。

#### poll 的控制故障与完整结果（已冻结）

用户已接受当前架构取舍：只有本轮所需后端状态均已获得/已按合法本地规则确定时才发布整体成功结果；若某个即时控制查询无响应，且原调用尚未被信号等结局终结，则故障期限到后整体返回方案 -1/EIO，即使其他后端已经回复就绪。不把缺失项填0后宣称整组查询成功，不因查询故障伪造 POLLNVAL/POLLHUP，也不把仅仅超时当作后端已死亡。此 EIO 是本系统拟定的故障映射，完整标准核对尚未完成，不能宣传为所有 POSIX 程序无需适配。

原输入/各后端已确认状态可留内部诊断；返回错误时不承诺 revents 是一份完整有效结果，具体输出失败/部分复制规则随 ABI 冻结。正常已提交结果不因后续其他清理故障改写；后端的确切失效证据仍按旧会话终结处理对应项，区别于“尚活但无响应”的查询故障。

timeout=0 仍不等待数据就绪，但跨进程查询会消耗调度及控制处理时间；不能同时承诺任意服务卡死下立即返回、完整当前状态和不引入其他就绪发布机制。本轮确定保留已有有界控制查询方案并明确这个限制，不新增共享就绪页/内核 fd 表作为默默认定的替代。故障期限过长的实际延迟及额外错误对外部事件循环的影响，必须在两架构场景及外部软件移植中测量/登记。

例子：poll 同时查 TTY 和管道，FS 已确认管道可读，TTY 控制查询一直无响应。整体结果尚未提交；若控制故障先裁决则返回方案 EIO，不声称完整查询成功且 TTY 无事件。取消未完成请求并保留旧槽，不自动重新绑定另一 TTY 实例。若信号先终结则沿已接受规则返回 EINTR，不等故障查询来推迟 handler。

以上完整结果/控制故障取舍已被用户确认；标准审计仍待交付核对，故障1秒及优先序已在首版协议固定。不能把该方案当作已达到严格即时 poll 的证据。

#### poll 的捕获信号与停止恢复（已冻结）

用户已接受：poll 不因 SA_RESTART 自动重启。捕获信号先终结本次尚未提交结果的等待时，及时递送 handler；handler 正常返回后，poll 返回 -1/errno=EINTR，取消和结果槽收尾由原上下文的预付记录持有。不得通过重新查询/等待延后 handler，也不在 handler 后隐式开始新一轮 poll。应用显式再次调用才是新操作。

判断依据是本次 poll 的整体结果提交点，不是某个后端 Rq 先 reply、事件位先置位或 TIMER 提示先出现。尚未汇总稳定的整组结果时，单后端就绪只是候选结果；信号可先终结整体等待。已经固定合法就绪结果或正常超时0时，保留该结局，handler 后只完成原结果输出；输出复制失败走 EFAULT，不重做 poll。整体提交通过Rctx结果标记与Sigctx返回现场交接，短本地保护段内固定快照，不通过跨 RPC 屏蔽信号解决。

纯 STOP 不产生 EINTR，不撤销原等待，也不暂停单调截止时间；CONT 解除停止后，先按原截止和已有查询/完成状态确定原调用结局，不能重新开始完整 timeout。期限已过且具备既定正常超时条件时返回0，已有合法就绪结果则按原提交规则保留；不得因期限到就伪造尚未取得的后端状态。CONT 若另触发可捕获 handler，则其捕获信号路径与解除 STOP 分开排序。KILL 不返回 poll，由退出清理接管请求/结果槽。

示例：poll 等待 TTY 和管道，FS 的管道 Rq 已完成，但运行库尚未汇总并固定整体结果。信号先终结本次调用，handler 返回后为 EINTR，即使设置 SA_RESTART 也不继续等；TTY 请求取消后仍可能占槽，服务收尾前不能复用。若整体就绪结果先固定，则保留该结果；poll 仅报告状态，不保证 handler 运行后管道数据仍可读。

示例：poll 的截止为 T+3秒，T+1秒纯 STOP，T+5秒 CONT，停止期间没有捕获 handler。截止仍为 T+3秒；在既定可信状态/查询及结果提交规则下结束原调用，不从 T+5秒再等3秒。控制查询 EIO 方案、同时可裁决条件的具体优先序及信号交接字段仍未冻结。

#### 示例：查询TTY无响应而不是没有输入

A以timeout=0检查TTY。TTY应立即回答现有状态，不能挂起等按键；若控制请求一直无应答，达到本轮故障截止后取消并报告控制失败，而不是返回0使应用误以为检查已成功。此时不自动重做旧请求、不宣称TTY已死，原Rq若仍被服务持有则保持收尾配额，新的poll不能复用其共享槽。

### 管道（已确定）

管道为 fs 中的 VFS 流后端，不新增内核管道对象或独立服务；有界字节缓冲及两端 File 使用统一 fd/I/O/关闭/继承/poll 协议。
容量、管道记录数及小写入原子上限由编译配置限制，原子上限不得超过容量，缓冲及在途快照计入明确预算。
空且仍有写引用时 read 等待或返回 WOULD_BLOCK；空且无任何写引用则 EOF。满且有读引用时 write 等待或返回 WOULD_BLOCK。
无读引用时写入报告断管；PIPE 信号默认终止，可捕获/忽略，捕获或忽略后的写接口返回断管错误。
小于等于原子上限的写入不与其他写交错，非阻塞空间不足整次失败；大写可部分完成及交错，已有进展返回实际字节数。
管道不支持 seek；poll 根据数据/空间/全部端点引用报告 READ/WRITE/HUP/ERROR，不以初始两个 fd 的存活代替引用计数。
阻塞请求使用已有 defer/取消/快照协议，不持全局 fs 状态等待另一端，取消与信号不能使已写字节被重复提交。
sh 创建整组管道并按显式 fd 映射继承：各成员仅保留所需读/写端，无关端点不继承，发布后 sh 关闭自身多余引用。
所有管道成员属于同一作业组；准备失败补偿本次 fd/会话/缓冲，已发布成员通过终止和收尾释放，不假装构造失败。
PIPE 的投递由受限制的后端结果与用户态库/内核自身信号机制配合，不授予 fs 任意给其他进程发信号的权限。

- [ ] 覆盖继承/重复引用关闭、最后写端关闭后 EOF、最后读端关闭后断管及 PIPE 默认/捕获/忽略。

### VFS 权限与设备授权（已确定）

VFS 管路径/文件访问，内核管 IPC/内存/IRQ 资源授权，两层分别满足，打开设备文件不授予 MMIO 或 IRQ。
本轮提供 uid/gid 及 owner/group/others 的 rwx 检查，可先单用户运行但不能省略权限校验；不引入 ACL/setuid 可执行文件或完整登录系统。
进程凭据由 init 在创建时配置，内核保存真实/有效 uid/gid，运行期间先保持稳定，子进程默认继承；fs 按内核确认的完整 source 身份取得凭据，不信任消息自报 uid。
首轮不开放运行期身份切换、setuid 可执行文件或补充组；普通文件访问使用相应有效凭据，access 按标准使用真实凭据，不能直接与 open 的检查混用。
cwd/root/umask 是 fs 中的进程上下文，不属于不可变凭据；umask 可由自身修改并被子进程继承，创建文件时由 fs 的权威值应用，不接受请求任意覆盖掩码。
uid 0 的文件权限不授予内核管理或设备权限。凭据查询/缓存须绑定完整实例，fs 重启可重新取得内核凭据；cwd/umask 等须按恢复协议重建或明确失效，不静默改为根目录/默认掩码。
目录穿越/查找检查 x，列举检查 r，创建/删除/重命名检查相应父目录 w+x；删除不以目标文件可写代替父目录检查。
共享目录支持 sticky 删除/重命名限制，防止删除其他所有者目录项；uid 0 的 VFS 权限不隐含内核管理授权。
设备节点关联可信设备注册实例，普通程序不能通过自造节点/编号/服务地址扩大授权；设备注册、节点创建与驱动授权分别检查。
open 固定打开访问模式，后续 chmod 不自动撤销已有 File；强制撤销使用显式会话协议。
每次 I/O 检查会话归属、访问模式、后端实例/代次及终端前台/挂断等动态条件，不重新解析路径。

- [ ] 验证客户端伪造 uid、设备实例/节点、跨用户会话和 uid 0 绕过内核授权均不能越权。
- [ ] 多后端的权限检查一致，路径查找后凭据/节点身份不被客户端替换，直接设备 I/O 不绕过动态终端检查。

### fs/VFS 实例恢复（已确定）

fs 崩溃包括 VFS 内存态丢失，磁盘日志恢复不等于打开会话恢复；旧 File、路径缓存、结果记录和后端绑定均按旧实例代次失效。
普通旧 fd 返回明确失效，不按原路径自动重新 open，避免路径替换、共享偏移及已删除打开文件的语义错误；写请求不自动重放。
init 确认旧 fs 退出，停止向旧实例配置连接，取消/排空相关请求和共享区，再清理旧授权/会话，启动新实例并恢复日志/挂载，READY 后发布新连接。
旧服务死亡不证明下游已停止访问通道，仍按 Rq/共享区/DMA 收尾规则保留必要资源，新旧实例不得复用未归还区域。
设备直达会话记录创建它的 VFS 实例代次；init 在 VFS 死亡后通知后端撤销该代会话并收尾，不能遗留 VFS 已无法管理的设备打开引用。
撤销旧设备 File 不销毁 tty 进程、控制终端、内核会话和前台组；收尾完成后可按授权建立新的打开引用。
sh 获知重建后通过 init 显式恢复其标准终端会话，普通文件 fd 不透明重开；程序自行处理其他失效 fd。
故障期间新请求明确报告不可用，不无限等待；诊断不依赖 fs 自身日志文件，可走独立 tty 或早期诊断通道。
不承诺 fs 重启后所有应用透明继续，持久会话/状态复制不由原路径重开冒充。

- [ ] 验证旧 VFS 的直达设备会话被撤销且引用归还，tty/blk 存活，其他代或独立授权不被误清理。

### fs 重启后的进程上下文（已确定）

进程的 fs 上下文绑定完整进程身份和 fs 实例代次；旧 fs 退出使旧 cwd/root 引用、文件会话及进程上下文失效，不能仅按进程槽号接入新实例。
连接新 fs 不自动恢复文件上下文；上下文未建立时路径操作/文件创建明确失败，具体 POSIX 错误映射按接口冻结，不静默使用系统根目录或默认 umask。
第一阶段不引入透明状态复制。sh 可向 init 请求显式恢复：准备获准的 root/cwd、明确 umask 及标准终端引用，全部成功后发布；失败补偿本次资源，旧 fd 不因恢复而复活。
恢复到根目录是显式策略，必须向用户报告工作目录变化。受限 root 只允许重建同等约束，无法证明边界合法则拒绝；不能因旧引用失效而退回系统根目录。
umask 可由 sh 作为自己的恢复配置显式设置，不称为从故障 fs 恢复的权威值。旧文件 fd 不按路径重开；普通程序可以处理失效后退出，不要求所有应用支持交互恢复。

#### 示例：sh 从 fs 故障中恢复

初始 sh 的 cwd=/home/leo、umask=027，fd 0/1/2 为 tty，fd 3 为 notes.txt。fs 崩溃后 sh/tty 仍存活，旧上下文和 File 失效；旧终端绑定依前文撤销/收尾，但控制终端关系仍在。
init 重启 fs，待挂载/日志恢复及 READY 后发布新连接；sh 此时尚不能用相对路径 open，不能把 test 自动解释成 /test。
sh 请求恢复，init 核对身份/权限；新 fs 准备获准 root、cwd=/、umask=027，tty 准备新标准流引用。相关资源全部准备后，按跨服务提交协议发布，libsys 在短本地临界段安装已准备的连接/标准流记录，不持信号屏蔽等待 IPC。
恢复完成后 fd 0/1/2 可用，fd 3 仍失效；sh 明确显示“文件服务已重建；工作目录已重置为 /，旧文件描述符未恢复”。notes.txt 名字仍在也不构成恢复旧 File 的依据。
任一准备失败则清理新增引用，保持上下文未恢复；若 sh 原 root 受限，则示例中的 / 只能表示其获准根，无法重建该边界必须失败。

### 磁盘后端：缓存与元数据日志（已确定方向）

具体磁盘 FS 使用有界块缓存、有序数据写入及元数据 redo 日志；blk 不另建文件语义缓存。
同一块只有一份权威缓存内容，记录引用、脏代次及 I/O；有引用/在 I/O 中不可淘汰，回写快照仅清对应脏代次，不误清后续修改。
缓存内部核心使用调用者预付的固定存储，一个实例固定对应一个设备实例，最多128项；每项4096字节内容加72字节状态。持有键为索引与绑定代次，释放消费该键；I/O票据另带单调序号与快照版本，独立保持淘汰责任。计数不回绕，脏项不直接淘汰，容量满返回背压。读失败保持无效；只有下层访问实际排空、取得确定结局才完成票据，取消/超时或仅结果已终结均不够。
元数据正式位置回写仅允许已由可信日志所有者在COMMITTED持久化后授权的精确版本；后续编辑使旧授权不再覆盖当前版本。这个私有授权入口本身不构成日志持久证明，不向客户端开放，也不替代完整事务、flush及恢复状态机。
缓存与日志以私有Txn衔接：准备时捕获独立不可变快照与CACHE_CAPTURE责任，元数据最多16项、加数据后总数不得超过同一缓存容量128。捕获不授予home回写权，普通cachecomplete不能完成这类票据。日志头/标记必须按捕获的目标与字节编码并校验后才开始提交；事务home写直接使用COMMITTED flush之后的精确快照，不重新读取可能已修改的当前缓存，也不授权后续版本。常规缓存home回写仍按cacheauthorize的精确当前版本门禁；两种路径均不得越过真实持久提交。
Txn在EMPTY flush及下层访问排空后才消费捕获责任并清对应脏版本；后续编辑保持脏，原调用者释放键不影响捕获锚。取消尚未开始I/O的准备只解除捕获、不撤销原cacheedit；这不是文件操作的逻辑回滚，上层必须用自己的事务视图/补偿维持权威状态，不能把保留脏内容当作业务已成功。已开始事务的未知/失败保持停止与恢复要求，所有设备写入路径均须遵守单写者停止状态，不能绕过它另启后台回写。
fs 事件循环通过异步请求处理磁盘 I/O，缓存满回写/背压，不无限分配；元数据提交串行，数据 I/O 可批量。
事务顺序：确认上次EMPTY标记已持久化，必要数据写入并 flush，日志头/镜像写入并 flush，COMMITTED标记写入并 flush，正式元数据写入并 flush，最后写EMPTY标记并flush才回收日志空间。
新分配数据先于引用它的元数据持久化；释放块只有在解除旧引用的事务持久提交后才能重新分配。
恢复先判定提交块：有效EMPTY允许丢弃未提交准备；有效COMMITTED要求整笔日志校验后才redo；提交块无法判定或已提交日志损坏则停止挂载并保留现场，详见下文恢复分支。恢复中断后仍可幂等继续；元数据 I/O 结果不明时停止可写操作。
逻辑块采用 4 KiB，由 blk 适配兼容的实际逻辑扇区大小，启动校验几何；固定字节序、字段宽度和校验范围，不直接强转未校验磁盘字节为 C 结构。
首个磁盘后端以inode标识节点，统一采用下文格式1的12个直接块号和一级间接索引，不实现extent或第二套索引；增长/覆盖/截断在4 MiB文件上限内处理非连续块。
目录统一采用下文8字节对齐、不可跨块的变长记录，按文件块索引跨块增长、删除/合并空记录及重命名，不再同时声称另有可分裂目录索引。
文件长度与实际占块分开，偏移/长度明确位宽并查溢出；磁盘块分配不复用内核物理页伙伴算法。
间接块更新、目录记录及空间修改纳入元数据事务，操作前预留最坏日志/元数据需求，避免修改中途因记录不足发布半成品。
unlink使链接数归零时，以已分配inode的nlink=0表示持久待回收成员；最后打开/在途引用结束后分批回收数据，最后清inode位图，不新增格式中未定义的孤儿表。崩溃挂载按下文扫描继续回收。
大文件回收以仍非零的直接/间接指针记录进度，每批把指针移除与块位图释放放在同一日志事务，恢复再次中断仍可继续，不依赖丢失的内存游标。
fsync(file) 覆盖文件数据/大小/块映射，命名修改须同步相关目录；sync 覆盖整个挂载的已接受修改。缺少可靠 flush 不提供相同可写持久化承诺。
未同步数据可按协议部分保留，但目录和分配结构必须一致；最大文件/目录/事务容量及具体格式布局必须明确，超限拒绝而非截断。

### fork 的文件上下文继承（新增设计方向）

fork 保留父可继承 fd 编号、每描述符标志及指向同一 File 的引用，父子共享偏移/文件状态，子有独立 fd表与调用身份绑定。FD_CLOEXEC 不在 fork 关闭，而在后续 exec 成功提交时处理；不同 close 只释放本主体引用。
cwd/root 节点引用及 umask 复制到子进程上下文；权限按继承凭据校验。此继承必须与父地址空间/库快照属于同一事务，不取得混合时刻状态。
File共享不等于共享运行库 staging/订阅或清理所有权；服务在发布前准备子引用、独立连接描述及接入容量；子用户态返回只做本地修复，首次实际后端操作才领取共享区，不等待批量接入。父已有阻塞操作仍属父，偏移/数据按服务既定提交顺序变化，不要求 fork 等待其业务完成。
准备失败释放本次新增引用和上下文，父打开状态不变；父子退出、已删除打开文件、管道最后读写端、后端故障均按各自引用和代次处理。

### exec 的 File 引用交接（已确定方向）

协调者已修订：采用 [调用者准备/新镜像启动交接方案](08-runtime.md#调用者准备与新镜像交接第5项审查修订)，不再由 init 在内核切换后逐次代办。

保留fd引用同一File而非路径重开，新镜像连接/会话引用先准备，CLOEXEC在不可撤销提交后逻辑关闭；新镜像只需本地fd/环境初始化即可进入构造函数或应用，实际后端操作按需领取连接；旧CLOEXEC关闭由后端独立推进。
fd编号保留不等于旧传输槽/请求可继承，旧PID+镜像代次+引用身份与新镜像独立；后端清理不能只按PID关闭所有File。详细提交与失败策略见 [运行环境](08-runtime.md)。

### 可执行文件装载会话（已确定方向）

FS 为受权调用者加载器建立绑定具体节点/内容版本/长度的装载会话，按目标程序调用者可信凭据检查执行权限、普通文件类型及挂载执行策略，不以init自身高权限代替检查，也不因此授予应用普通读权限。
装载期间阻止该节点内容写入/截断，既有修改先到安全边界或明确失败；只保护相关节点/内容，不持全局VFS锁，允许其他文件及已有稳定命名引用工作。
调用者加载器按固定会话分批读取/校验/构造，完整数据装入并封存后释放。取消/超时终止本次装载并解除保护，不允许继续拼接后来版本；会话引用及异常退出清理有界。
FS重启使旧会话失效，提交前exec回滚，不从新实例接续剩余段。已完整装入的程序不再依赖源文件不变；本阶段不增加整个执行期间的禁止源文件写入策略。

## 首版观察与文件协议规格（已冻结）

### 生命周期观察的确切接口

observe(permit,basis,relation,pid,image)：permit为调用者本地OBSERVE，SOURCE/CHILD/FUTURE/MONITOR权限位依次1、2、4、8。basis占原第二参数寄存器，不新增调用号；必须由relation决定其类型，不能凭整数外观猜授权。

| relation | basis必须显式传入 | pid/image与授权目标 |
| --- | --- | --- |
| SOURCE=0 | 当前服务仍持有的REQUEST | pid=image=0；目标取REQUEST的source PID/image，不由消息自报 |
| CHILD=1 | 当前服务仍持有的REQUEST | pid为完整孩子PID，image可0取其初始准备镜像；必须原子核对REQUEST.source PID/image为该未发布孩子当前构造者 |
| FUTURE=2 | 当前服务仍持有的REQUEST | pid必须等于REQUEST.source PID，image为非零目标准备代次；必须核对该source镜像拥有这一次exec准备 |
| MONITOR=3 | 本地CONTROL QUERY，且绑定单一完整进程Life | 目标只取CONTROL绑定Life；pid=0或等于其完整PID，image=0捕获当前/未发布初始镜像，非0仅查该Life实际存在且仍保留的Image |

REQUEST按全局Rq表/请求代次解析，接收者必须匹配当前服务完整PID/image；MONITOR的CONTROL才在调用者本地资源表解析。REQUEST只限当前服务的合法持有记录，已取消但尚在DRAINING收尾中的REQUEST也可核验原source；已回复/rqfinish失效或其他接收者的REQUEST不可用。MONITOR不接收REQUEST/0、集合/域CONTROL、SYSTEM或裸PID；init同样显式传固定目标CONTROL。QUERY与permit MONITOR是两个独立条件，不自动附带INSTALL、REVOKE、TERMINATE或wait收取权；不扫描授权表补上一个未传入的CONTROL。

上述permit、本模式basis、目标关系及固定Image在同一短临界区检查/登记/读取；登记后exec只使该旧Image到ENDED，cookie不跟随新image。检查期间授权先失效则失败，不登记、不占配额；登记先提交则cookie独立承担这一个Image的通知责任，之后revoke输入授权不追溯删除cookie或取消已接管业务。已ENDED返回cookie=0和真实终态，不为已结束目标安装新业务引用；指定旧image已不保留则STALE，不重建历史。CHILD/FUTURE取消后也只有在仍能核验原构造/准备归属的保留记录上读取ENDED；归属证据已释放则STALE，不凭裸PID补造关系。ack/drop和观察者退出/exec的规则保持下文定义。

getcred(subject,pid,image)沿相同SOURCE/CHILD/FUTURE核验真实REQUEST关系，FS不信VFS消息中自报uid；CONTROL分支显式检查固定目标QUERY、pid只作一致性核对，不能越权查另一个目标，普通0/0/0只查自身。

示例：监督者S持有OBSERVE MONITOR和B的CONTROL QUERY，observe(permit,control_b,MONITOR,0,0)只捕获B当前镜像；没有INSTALL不能向B grant，也没有父wait消费权。传control_b却声称pid=C则INVALID，basis=0仅传B的PID则失败。S随后被撤销CONTROL QUERY时不能再登记新观察；已经登记的B旧镜像cookie仍只等该镜像终结，B执行exec不会把它重绑到B的新镜像。

观察cookie=u64，低16位服务观察槽、上48位代次，0无效，不是可转授Handle。所有读/ack/drop都验证观察者PID/image。obsread返回state PREPARING=1、ACTIVE=2、ENDED=3及reason EXIT=1、ABORT=2、EXEC=3、TIMEOUT=4；未终结的reason=0；成功后返回目标PID/image。只对ENDED置LIFE提示。obsnext(cursor)扫描本观察者固定表，0起始，返回cookie/下一索引/state/reason；到末cookie=0、next=0。最后检查与recv登记原子核对pending，单次提示后必须扫描到末，仍有本地清理游标不睡眠。

obsack仅ENDED且业务入口已在服务本地关闭、剩余责任已移入预付清理表后调用，移除观察/目标引用；内核不替服务证明后者业务安全。obsdrop主动解除不要求ENDED，但普通服务只能在已无该业务依赖后使用；服务违规丢业务观察只损害其可信业务，不获得跨主体权限。观察者死/exec时内核逐批删其观察，服务下游按观察者自己的终结清理，不伪造DMA完成。一个服务同一目标image合并一条观察，多fd共享；每个获权服务预付128，系统总1024，grant配额检查总和，普通应用无OBSERVE。

### 连接、操作和共享槽

首版连接握手复用04单资源reply。普通客户端先向获授FS CALL发HELLO，接收SHARED MEM。每个完整客户端PID/image与后端PID/image组合只持一条连接，三层Rctx共用它的独立槽；服务私有连接池上限128条，包含已准备、已接入及未安全释放的旧连接，调用者最多缓存8个后端连接。满则新准入前明确失败，不淘汰仍被fd/请求引用的连接，也不新建第二条同后端连接绕过槽满背压。未发布目标、exec新镜像及已终结但仍收尾的旧镜像有不同身份，各计真实持有量，不把128解释为保证所有父子/旧新镜像同时取得最大配额。

连接区36864字节（9页）：第0页为控制页，后8页为数据槽，每页4096字节。区头首64字节八u64=[magic,bytes,connid,serverimage,slots,slotbytes,reserved,reserved]，magic=0x4b434f4e4e303031、bytes=36864、slots=8、slotbytes=4096；描述符i在64+i*128，槽数据i在4096+i*4096。头加8描述符占1088字节，第0页其余字节0；映射RW/NX，私有记录才是尺寸/来源权威，不把魔数或共享描述符当授权。普通文件/TTY单次I/O及PIPE_BUF仍4096字节，协议页数不代表实际实现RAM/页表开销测量。

### 槽容量与重入分区（第7项审查修订）

每个槽描述符128字节：首64字节为八u64=[seq,state,payload_bytes,object,span,reserved[3]]，args[8]在64..127。seq/state/payload_bytes/object/span分别在0/8/16/24/32；保留字段及未用args输入必须0。args保存该操作的固定参数，payload只放字符串、数组、实际数据或固定输出，不再在4 KiB数据前重复放64字节槽头和参数前缀。普通reply仍为[status,seq,value,bytes]；read等回复先在原数据页发布内容，结果归原Rq，不新增共享结果缓存。

| 使用者 | 可用数据槽 | 单请求上限 |
| --- | --- | --- |
| 普通上下文 | 0、1 | 1页；冷路径可一次占用这对2页 |
| 第1层handler | 2、3 | 同上，普通上下文不得借用 |
| 第2层handler | 4、5 | 同上，其他层不得借用 |
| 控制推进 | 6 | 1页，只用于既定有界控制/逻辑关闭 |
| 后台收尾 | 7 | 1页，只用于既定清理/补偿 |

span仅1或2，服务按128字节头一次快照核验。span=2只允许从0、2、4开始，完整占用对应页对，数据视为两页连续的槽内字节区；只用于本节明确允许的冷路径。续页描述符清零，不单独发消息，归属由两端各自私有的占用表绑定原Rq；不能据共享state猜续页空闲。热路径一页即可，长度不因有两页而超过IO_BYTES。控制/清理不得申请双页或调用会把普通业务伪装成清理的大PATH请求。

取得/释放一页或页对都在短本地临界段整体完成；一页DONE但数据尚未保存、请求仍执行、强制终结未排空、后台接管尚未释放时，整次占用都不能借出。服务在读payload前也按私有在途表原子登记整个span，重叠的新Rq拒绝，不让它指向其他活动请求的续页。reply后客户端仍控制槽直到复制/保存完成；slot.state不代替Rq终态或真实安全归还。

分区是合规运行库的进展保证，服务只按私有记录验证span范围及重叠，不从IPC元数据推断用户的信号层；原生程序自行管理也不能越过8页、跨source授权或重复建连接的总量边界。

同一后端最多两个普通一页请求，或一个双页请求；这小于内核普通出站8份并不矛盾，后者还用于跨后端扇出/原生短消息。poll按每后端一页分组，另一个普通页可用于取消后的状态重查。所有普通页被旧请求占用时返回当前接口的资源错误，不等待被中断外层、不临时扩槽/建连接、不窃取信号/控制/收尾页。read/write/open等库内暂时无可用槽按EAGAIN，poll按既有资源不足EAGAIN；真正页/映射分配失败仍ENOMEM。close仍用发布前预付责任及控制/收尾页，不能因普通槽满返回EAGAIN；控制/清理页也未安全归还时按既有关闭故障EIO及后台责任处理，不破坏旧访问安全。

#### 参数大小与两页请求

| 操作 | 固定参数位置 | 最大payload及占页 |
| --- | --- | --- |
| READ/WRITE、LOAD | args中的原定参数 | 实际数据<=4096，一页；length及data_off范围同时验证 |
| OPEN、单路径PATH | args中的原定参数 | 含NUL路径<=4096，一页 |
| 双路径PATH（如RENAME/LINK/SYMLINK） | args最多7字 | 两字符串各<=4096，总<=8192，一次双页提交；副作用只有这一次原Rq，不分开执行路径操作 |
| POLL_QUERY/POLL_WAIT | args=[count,deadline_ns,generation,reserved] | <=128条32字节记录，共<=4096，一页；输出仍原条目的revents |
| FORK_SNAPSHOT/FORK_PREPARE/EXEC_PREPARE | 原64字节固定头移到args[8] | <=128条48字节记录，共<=6144，双页一次传输；不再为此普遍扩大I/O槽或增加分页提交协议 |
| STAT、TTYCTL等固定输出/参数 | args中的固定参数 | STAT128、Termarg80等既有固定内容，一页 |

payload_bytes<=span*4096，所有字符串/数组offset均相对本请求首数据页；offset+bytes、count*entry_bytes及取页运算先查溢出和上界。数据以外参数不占payload，不能仍把旧前缀算入偏移。若一个合法小输入恰好不跨页则用span=1；预留最大输出也必须在提交前取得完整span。参数/环境的16 KiB私有快照和64 KiB Boot/Fix不在这个共享传输上限内，仍按原受限视图/本地快照处理，不允许一次把整块Boot塞进文件槽。

#### 连接建立与会话复用

连接本地状态为未接入、接入中、可用、失效待收尾，全部层共享同一记录及bootstrap发号器。标记接入中及原RPC归属后才提交HELLO/ATTACH/EXEC_CLAIM；handler遇外层正在接入不能等待外层、重复建连接或借其尚未安装的Mem，普通操作返回EAGAIN。接入已完成且记录可用时，handler只取自己的页/页对；原接入后续结果由原Rctx稳定安装，不被handler改写。无外层接入时handler可以自己成为该连接唯一接入者，失败按原RPC及token收尾，不把锁跨RPC持有。

多次VFS打开同一后端只新增各自会话/引用，不新增连接。目标的预付区按该身份唯一连接记录保存；首次HELLO/ATTACH/EXEC_CLAIM实际交付它后标记已交付，不能再次交付另一块来绕过容量。首次ATTACH/EXEC_CLAIM按同意MEM的CALL取得共享区；若服务私有记录和客户端缓存均已有该source/backend的连接，新的会话ATTACH或尚未领取的继承EXEC_CLAIM普通reply=[0,bootstrap_seq,connid,region_bytes]确认绑定既有连接，未用接收槽按04归还，不再次交付MEM。资源reply与普通确认由kind明确区分；客户端没有可用匹配Mem/connid时不能把普通确认当作新授权，必须报协议/连接错误并补偿该会话，不猜本地Handle或重发旧建立操作。新交付CALL的固定目标PID/image通过06的本主体RESOURCE查询取得，作为缓存键，不按Handle整数是否相同猜后端；在固定会话关系后可free多余本地入口引用。该查询只在新授权冷路径使用，热I/O不追加查询。

未发布连接的运输放弃：对仍由精确claim拥有、从未READY的首次bootstrap，调用者先补偿token/session并结束绑定Rctx责任，才能显式放弃运输。固定业务结果不证明原RPC排空；原生RQ_FINISH/ACK成功后依次解除外部Bootmap和释放bootstrap自持MEM，最后解除该claim的目录owner。等待/ACK/unmap/free失败保留剩余步骤，不能丢资源或重新发送ATTACH。工作页已持CALL保持独立，不随MEM释放；源VFS连接不被标死。目录保持DRAINING且不伪造peer-ended，不恢复UNCLAIMED、不忘记仍存活peer的键或自动重发HELLO。已发布READY/已有connid、其他槽责任及已移交MEM均不能走此路径。

已有READY连接上的失败/放弃确认只补偿本次新引用。该token/session及绑定Rctx已另行结清后，按精确claim等原RPC实际排空/ACK，再释放意外回复所新交付的资源、结束本次bootstrap并解除owner；不unmap、不free原MEM/CALL/SELF_SPACE，不发布失败的新File，也不影响其他File、数据槽与持久操作。普通业务负值不是peer-ended证明；原生PEER则保留完整原记录给全连接死亡处理，不走本地复用清理。WAITING、FINISH/ACK/free失败保留本次责任，不能重新发送ATTACH/EXEC_CLAIM。原READY仅表示旧映射仍已安装，不构成存活证明；已DRAINING或已移交资源不由此恢复。

bootstrap原生PEER的终结证明必须绑定已提交的真实目标：Rctx注册CALL时保存的PID/image、原bootstrap地址及完整claim均与该工作页匹配。未产生RPC的失败CALL还核验仍持有CALL的真实目标；已提交RPC只接受同一Rctx经rewait保留的原目标、原RPC及空原生PEER元组，fresh wait-only不能补造提交目标。证明只标记这个旧peer的DRAINING/ended，不改变原错误或释放资源。尚未安装的运输仍按上述discard处理；已有映射的bootstrap收尾须有独立ended标记，待原FINISH/ACK后只解除该bootstrap和意外资源，旧MEM/CALL/map及其他File/操作各自排空后再清。业务负值、撤权、超时或原RQ尚未结束均不替代这一证明，kernel也不因服务退出自动代收尾。

资源OPEN的实际后端已独立终结时，创建者须先匹配该后端完整PID/image、原ATTACH token、完整claim及准备File ID，再结束本次逻辑预留。未提交ATTACH无RPC；已提交则固定结果且实际FINISH/ACK之前保持CALL与预留，WAITING不能直接丢弃。只释放创建者仍自持的CALL，不动已转入缓存的CALL、MEM/map或其他File；ENDED不是ABORT成功，不产生新撤销消息，也不标记源VFS结束。源bootstrap若仍持同File/token的独立ABORT，先BUSY，不能使它借用的CALL失效；不相关bootstrap不因owner数字相同而阻止清理。创建者结束后原bootstrap owner仍是其运输cookie，由后续运输收尾独立归还，不重新查询已经释放的File ID。

普通close即使连接仍未接入也须保留原引用的关闭责任；可以推进其唯一接入后关闭。若在handler内遇接入由被打断外层持有而无法独立推进，不能等外层或返回EAGAIN：摘除后明确EIO并把关闭责任交给已预付记录，后续接入/生命周期清理继续处理，fd不恢复；不声称已经后端关闭成功。_exit依旧无需接入，目标ENDED独立收尾。自定义原生入口主动重复HELLO或破坏库表不能取得第二份授权或绕过总容量。

#### 四字请求头与连接选择（审查修订）

已建立连接的有槽请求固定words=[opcode,connid,seq,slot_index]。File/session移到槽头object；OPEN/PATH按当前目录解析、POLL分组等不针对单个File的操作，object=0；openat类相对目录请求可在object指定已获权目录session。session不再挤占路由头，普通文件操作不能省略connid或按source猜一个连接。

服务先用自己当前的服务实例/镜像，加内核提供的source PID/image及消息connid，查私有连接记录；固定来源和连接身份全部匹配后，才按该记录的共享Mem/尺寸检查slot_index，再取得槽头和payload私有快照。connid=0保留给下表的建立连接路径；有效connid由服务分配，低16位为连接池索引、上48位为非零代次，复用必须递增，耗尽停用该槽。旧连接在请求/槽访问未收尾时不复用。客户端记录完整服务PID/image和connid；新服务即使出现同值connid也不重绑定旧连接，原CALL授权的镜像绑定仍由内核检查。

不得扫描同source的几个共享区、根据哪个槽的seq“看起来匹配”选择连接，也不得信任可写共享头里的connid来路由。连接头只用于核对已选连接；服务的尺寸、地址和所有者以私有记录为准。slot_index越界、槽seq与消息seq不符、连接头被改成另一身份时拒绝，不执行该业务。所有层共享同一连接发号器，seq从1起、不回绕；不同连接可以出现同值seq/slot，不构成同一业务键。信号上下文及收尾记录保存完整服务身份、connid、seq和槽归属。

槽状态仍FREE=0、SUBMITTED=1、DONE=2、QUARANTINED=3（仅机制强制终结且访问未排空）；具体128字节描述符、span及args/payload上界以本节第7项修订为准。object保存该操作的session/打开引用目标，服务先按真实source和connid取得连接，再按私有快照检查object归属；不以object选择共享区。

#### 无槽建立与准备撤销

仍只使用四个业务字。仅下表操作不把words[3]解释为slot，解析由opcode决定，不能靠数值猜消息类型；其余操作要求非零有效connid及0..7起始槽号，并核验本次span占用范围。

| 操作 | words[1] | words[2] | words[3] | 校验与结果 |
| --- | --- | --- | --- | --- |
| HELLO | 0 | bootstrap_seq | UINT64_MAX | 无共享区输入，仅建立传输连接，不授予File；成功MEM资源reply业务三字=[bootstrap_seq,connid,region_bytes] |
| ATTACH / EXEC_CLAIM | 0 | bootstrap_seq | prepare_token | token非零，私有准备记录须绑定真实目标source PID/image、用途及原授权方；首次成功MEM资源reply业务三字=[bootstrap_seq,connid,region_bytes]；复用已有连接的ATTACH/EXEC_CLAIM可普通reply=[0,bootstrap_seq,connid,region_bytes]，不安装MEM |
| ABORT | 0或有效connid | bootstrap_seq或本连接控制seq | prepare_token | 0时按下述token归属授权，非0还先验证连接；只撤销该token对应的准备或普通OPEN引用，不读共享槽；成功普通reply=[0,abort_seq,0,0] |

bootstrap_seq由运行库在当前客户端Image内统一发号，HELLO/ATTACH/EXEC_CLAIM和无连接临时ABORT共用一个从1起、不回绕的发号器，跨后端及所有信号层共享。已发序号不因提交前回滚、目录项释放或后端切换而复用；耗尽则拒绝新事务。服务匹配原请求seq，允许间隔，不要求该客户端对本后端的首次seq恰为1。保存结果仍须核对真实客户端PID/image、固定服务PID/image、opcode及bootstrap_seq，统一序号不替代身份授权。目录已满时，客户端仍可凭原CALL、token及预付清理责任向新后端发送临时ABORT，不占第九个目录项，也不淘汰活连接。这里不改变有槽操作按连接发号的规则，四字消息布局不变。

HELLO/ATTACH/EXEC_CLAIM的参数全部来自寄存器快照和服务私有准备记录，不要求先map才能取得自身共享区。prepare_token只是有代次的服务准备身份，不是可由持有者任意冒领的授权；跨source、旧image及已取消token的领取均拒绝；合法重复ABORT按下述幂等规则处理。资源reply提交和原Rq结果的恢复规则沿用04，中断后查询原RPC，不另建Rq重复建立；已有token/连接对象可拒绝重复领取，但不缓存一份可重发资源的业务结果。

普通资源OPEN的token在ATTACH提交后仍标识其唯一引用。ATTACH前沿既定准备者/目标取消关系授权；ATTACH提交并移交后，仅精确目标客户端PID/image可用原token执行ABORT，原VFS准备者失去撤销权。客户端本地map或验证失败时以此补偿；服务按token定位并幂等撤销这一份引用，复用CLOSE的逻辑关闭与实际排空规则，不撤销共享连接或其他引用。成功只证明该引用逻辑关闭，不证明下游访问/DMA已排空；客户端仍须独立结清原RPC、映射及本地CALL责任。重复ABORT不得再次减少引用，服务须保留足以识别原token归属及已撤销状态的有界生命周期记录；不能按同号新token或session误关后来的引用。继承token仍遵守下节既有规则，不扩大原准备者对已发布目标的撤销权。

例如VFS为A准备引用R并交付CALL/token，A的ATTACH已提交而本地map失败：A保存原ATTACH结果、结清其运输责任后，通过该固定后端CALL以原token发送ABORT。后端只关闭R并在原ABORT请求回复[0,abort_seq,0,0]，共享连接上的引用S仍可使用；迟到的VFS撤销请求被拒绝，A重复清理R不会关闭S。

VFS OPEN交付后端CALL时，资源reply业务三字固定为[seq,session,prepare_token]。客户端持该session和token，向后端发送无槽ATTACH；首次MEM交付得到connid/region_bytes后才map；普通复用确认仅核对已经持有的同一映射，不执行第二次安装/map，随后才能使用该会话。连接头connid/bytes必须与本次资源回复匹配；不能把旧镜像connid或token当新连接connid。普通FS OPEN已经有HELLO连接，不需要再建立一次共享区，成功普通reply中的value为新session。

创建类新引用返回格式已于2026-11-20确认：普通OPEN的value=session、bytes=8，VFS资源OPEN保留上述三字，两者均在原槽输出u64 reference_id；DUPREF的value=新reference_id、bytes=0且session不变；PIPE的value=2、bytes=32，原槽依读端/写端顺序输出两条{session:u64,reference_id:u64}。原RPC排空后保存、ACK前接管；free CALL不能代替关闭远端引用。实现与验收边界见文末。

业务取消通过原RPC的rqcancel，结果通过同一RPC的rqpoll/rqwait/rqack处理，不发送文件层控制查询或确认。槽/活动操作键含服务PID/image、客户端PID/image、connid、seq及原REQUEST；seq匹配原槽和返回，不是跨新Rq恢复业务的凭证。ABORT只撤销明确token对应的准备或上述普通OPEN引用，不取消或查询已提交I/O。

#### 示例：不同客户端连接使用相同序号和槽

A和B对同一FS分别有C1、C2，均可发送OPEN、seq=2、slot=0、object=0。FS按真实source及connid选各自Mem，一个连接的迟到结果/取消只处理自己的键；即使C1尚SUBMITTED/DONE，也不能让B的OPEN读C1。A冒用C2在payload访问前拒绝。A同一镜像再次HELLO不能得到C3来扩充普通/信号容量，必须沿原接入结果或既有连接处理。

操作码固定：1 HELLO、2 OPEN、3 ATTACH、4 READ、5 WRITE、6 CLOSE、7 DUPREF、8 SEEK、9 STAT、10 PATH、11 POLL_QUERY、12 POLL_WAIT、13..15不分配、16 FORK_SNAPSHOT、17 FORK_PREPARE、18 EXEC_PREPARE、19 EXEC_CLAIM、20 ABORT、21 SYNC、22 LOAD、23 TTYCTL、24 PIPE。PATH子码LOOKUP=1、CREATE=2、MKDIR=3、UNLINK=4、RMDIR=5、RENAME=6、LINK=7、SYMLINK=8、READLINK=9、CHMOD=10、TRUNCATE=11、UTIMENS=12、GETCWD=13、CHDIR=14；不会由内核解析。每种payload从定长字段/长度表开始，字符串为槽内offset+length，路径含NUL且总<=4096，不能嵌套裸指针或分多请求重新执行同次副作用。

客户端原RPC转后台的存储/容量见[运行库预付记录](08-runtime.md#后台责任的预付存储交叉复核修订)，不借共享控制页保存可信所有权，不因三层Rctx被复用而丢弃旧请求。

### 单一请求结果与协作取消（第6项审查修订）

每笔文件/TTY操作只有原内核Rq一份短结果，服务只保留其执行阶段/实际效果及安全收尾的活动记录；完成时在原槽发布数据/结果、停止本次槽访问后reply并释放服务活动记录。调用者用原RPC取得结果，复制/稳定保存数据、引用和已安装资源后rqack，再释放自己的槽。服务不等待额外业务ACK，不维护每连接8项未ACK结果表或可跨新Rq读取的read快照；共享区及页对容量已按本节第7项修订收缩，不恢复独立业务结果表。

- 捕获信号只退出call/rqwait，原请求及槽仍由原Rctx持有。POSIX适配可通过原RPC提出协作取消；QUEUED被摘除保证未交付，ACCEPTED仅置标记。服务须在尚无效果时停止并以原reply返回业务EINTR；有部分量则回复实际数量，有完整结果/资源则正常交付，不用取消标记抹掉效果。
- 原reply固定前，不能用共享DONE字样替代内核完成证据；原reply成功后也不得由服务复用客户端槽。调用者先保存结果/数据才重置FREE；下一操作用新seq重新提交。rqpoll重复读取同一原结果不重做副作用，不因内核已保存四字回复而复制第二份服务结果表。
- CANCEL/RESULT/RESULT_ACK三个文件操作删除，原编号13..15未分配。同一业务以新Rq再次发送就是新请求，库禁止用这种方式“找回”结果；准备token及有生命周期的会话/继承对象仍可幂等ABORT/拒绝重复领取，不因此保留通用I/O结果缓存。
- 服务死亡、旧镜像终结或实际结果不确定时，按原机制结果及安全隔离报告EIO，不按路径重开或重试未知写；强制终结且未排空的原槽保持QUARANTINED，直到RQ_FINISH及真实安全条件满足。逻辑超时只结束应用等待并转预付后台责任，不把正在执行的Rq谎报未执行。

例子：WRITE已推进128字节时信号打断call，库保存返回的原RPC h并请求协作取消；服务在h的原reply返回128，handler后库领取并只交付这128字节。没有第二笔RESULT或RESULT_ACK。若原请求尚QUEUED被rqcancel摘除，h的CANCELLED才构成零效果证据；若服务在回复前死亡，仅能报告EIO并保留未安全排空的槽。

VFS/TTY首次直达需要OPEN交付后端CALL、首次ATTACH交付共享MEM；同一镜像后续会话ATTACH复用既有连接，只普通确认，不再为每fd/信号层交付新共享区。VFS准备结果绑定目标PID/image及seq，后端每次核对真实source；普通open未交付应用fd的ATTACH准备10秒到期由后端自身事件循环撤销；fork/exec/spawn继承token按下节核验目标状态，ACTIVE后没有接入TTL。准备期VFS观察客户端、后端观察VFS；客户端真实ATTACH后后端观察客户端，释放原控制准备责任。失败按原seq补偿，free CALL不是close会话。已接入共享槽若仍被下游/DMA使用，截止不允许强制回收。

### 继承引用与按需接入（第5项审查修订）

FORK_PREPARE/EXEC_PREPARE及spawn继承在成功回复前预付目标File/上下文引用、观察、待接入共享区及收尾记录，返回的token始终绑定真实目标PID/image。未发布时可按本次构造/替换撤销；后端检查到目标ACTIVE时转成普通镜像归属，即使尚未ATTACH/EXEC_CLAIM也不能按原准备deadline删除。到期重查PREPARING则等内核撤销/ENDED，不凭超时臆测提交输赢；目标ENDED则清理，未曾观察ACTIVE也不漏收尾。父/旧source死亡首先核对目标状态，不撤销已发布目标。

子本地修复后返回0，新csu本地初始化后进入应用；fd可为合法但尚未接入状态。首次实际后端操作通过真实目标source及原token领取已有共享区，按既有MEM资源reply取得connid/bytes并map；不能回退父连接、重新按路径open或因接入失败强杀目标。接入资源不足按当前接口报告ENOMEM/EAGAIN等明确错误，后端失效EIO；仅未接入不构成EBADF。close沿既有预付责任收尾，必要时先接入后关闭，_exit不要求接入；本地描述符动作是否需要后端仍按既有引用协议，不为每个fd强制建立独立连接。

ACTIVE的待接入token没有独立TTL，引用/预付页按持有者实际计费直至领取或镜像归属结束；服务使用普通客户端配额及同目标合并观察，不长期占用可发布Prep。未用保底接收槽按08留在目标镜像资源表中；没有execready及发布后10秒杀进程。普通OPEN→ATTACH尚未交付应用fd的10秒准备/补偿继续保留，与上述继承token区分；不能因同用ATTACH操作码就套同一过期分支。

### fd/close、poll 与exec交接

继承 reference_id 待确认（2026-11-21）：当前 FORK_PREPARE 只回复 token，但本地子 Fileref 还需要精确 reference_id，线上尚未定义其取得方式。建议把引用键明确为真实客户端 PID/image 加 reference_id；准备时在目标命名空间沿用源 reference_id 数值，建立独立的目标引用并共享原 File/session，父子关闭各自引用互不撤销。后端的引用分配器须避让该目标所有已准备/已领取 ID，重复 fd 别名只准备同一个引用；token 仍只授权真实目标领取。本项尚未确认，未改线上结构或实现目标引用分配，也不能由当前 Filefork 测试自行选择的数值推导生产规则。

Fd记录64字节上限，含本地代次/File会话、标志、连接/保留槽、关闭责任索引。每进程128fd、256关闭责任记录（每条64字节上限）；发布新fd前保证责任和必要共享槽/控制推进容量。别名可聚合后端引用，但本地代次、FD_CLOEXEC独立；dup2先固定源，新引用保证成功后再替换，旧关闭按原身份推进。记录满在新open/dup返回ENOMEM，不将其伪报EMFILE。close自身不临时申请记录；摘除前表项被handler替换则EBADF且不动新项，摘除后错误不恢复fd。无SA_RESTART的捕获中断按EINTR保留/EINPROGRESS已摘除；SA_RESTART只继续原记录。后端1秒控制期限不能取得可信关闭结果时EIO、后台保留责任；不无限重试，服务死亡恢复链接管隔离。posix_close不纳入首版SDK，不声明完整POSIX版本能力。

poll每后端一组，固定参数args前4字：count、deadline_ns、generation、reserved；payload条目32字节：session、fd_generation、events、revents，最多128项（含一个group的完整输入），不逐fd建内核对象。POLL_QUERY立即回答当前状态，POLL_WAIT原子复查后defer，唤醒后完整汇总；同一轮所有控制查询共用1秒故障截止，合法defer不受它误杀。用户timeout固定不重置；信号先终结返回EINTR，控制故障先终结EIO，已固定合法整体就绪先保留，达到截止且完整状态可信才正常0；同时本地可裁决时按已提交结果>捕获信号>控制故障>合法就绪>正常超时排序。这里“已提交”不等于任一后端reply，IRQ/信号入口用本层结果标记原子交接。零fd无需FS；timeout0不登记长期等待，明确存在控制/调度开销。输出失败EFAULT且清理原订阅，不重做。EIO和超时查询限制为公开的兼容扩展，不虚称严格POSIX。

exec继承服务清单保存保留File稳定引用、旧source/目标image、CLOEXEC-only清单及未发布准备deadline。核验旧ENDED/新ACTIVE后后端独立关闭旧CLOEXEC引用并激活保留归属，不等新csu首次CALL；业务访问要先有界核对影响该File的旧归属，不能让STOP的新镜像永久持有旧管道端。新csu只建立本地fd/待接入连接，首次需要该后端时用EXEC_CLAIM领取同次准备，不在应用/构造函数入口前等待全部后端。保留引用选择“新目标独立引用”，旧清理只放旧引用；配额分别覆盖两份实际元数据但共享物理页不双计。没有跨服务物理原子提交；兼容边界公开，未知源/目标状态不伪造完成。

### 首版磁盘与失效策略

串口持久化MVP选择单一小型日志文件系统，不实现第二格式或恢复旧KFS ABI。4 KiB块、单设备、固定大小inode/块位图、物理redo元数据日志64块；事务最多16个元数据块，数据先写并flush，再提交元数据日志/flush，回写home并flush后写EMPTY标记/flush。不提供未写回数据的持久成功；fsync追踪本File此前数据及必要命名事务，失败只报告EIO而不重放未知写。目录项固定长度上限255字节、路径4096、符号链接跟随40次、单文件首版上限4 MiB，直接/一级间接索引，ENOSPC/EFBIG明确。磁盘超级块/日志的具体C字段属于FS格式实现规格，采用显式little-endian字段和校验，不暴露为内核ABI；构建工具和FS必须同一格式版本，不保持旧盘兼容。首次正式格式实现必须附掉电序列演算和双架构回读后才能称持久化通过。

fs重启使旧连接/未恢复会话失效，不按路径重开冒充原File。旧写无法确定时EIO，恢复仅重放有完整校验/提交标记的元数据日志；根/cwd/umask按既有恢复协议重建或明确不可用，不能静默回到/。服务监督保留控制清理名额，最多3次恢复、每次退避1秒，设备复位失败保持离线；后续显式管理员请求才重新尝试。

### 文件payload和磁盘格式的确定补充

线上固定参数均u64并置于描述符args[8]，未用字为0；下列原参数数组不再是payload前缀。字符串/数组引用相对首数据页，固定输出仍放payload，不解释裸用户指针。OPEN为[flags,mode,path_off,path_bytes]；ATTACH/EXEC_CLAIM使用上述无槽prepare_token格式，不在尚未建立的共享区中读取输入；READ/WRITE为[offset,length,data_off,io_flags]，io_flags POSITIONAL=1、APPEND=2，后者权限及共享File状态同时核验；CLOSE/DUPREF为[reference_id]；SEEK为[s64 offset,whence]；STAT输出128字节[dev,ino,mode,nlink,uid,gid,size,blksize,blocks,atime_sec,atime_ns,mtime_sec,mtime_ns,ctime_sec,ctime_ns,reserved]。PATH为[subcode,path1_off,path1_bytes,path2_off,path2_bytes,arg0,arg1]；PIPE为[flags,capacity]，capacity首版8192；SYNC为[data_only]；TTYCTL为[subcode,arg0,arg1,data_off,data_bytes]；ABORT无槽携带prepare_token。未知flags/subcode在副作用前拒绝。

FORK_SNAPSHOT/FORK_PREPARE/EXEC_PREPARE固定参数占args的64字节[pid,image,sourceimage,deadline,count,entries_off,token,reserved]，entries_off固定0；payload条目48字节[fd,flags,backend_pid,backend_image,session,reference_id]，最多128项6144字节，一次用最多两数据页提交/读取同一只读快照，不跨新Rq拼接一次继承事务。token绑定真实source、连接connid和seq，仅原构造关系可用；确认准备完成前记录全部引用、观察和清理容量。fork目标共享区只在服务侧预付，父reply只带token；子发布后首次需要后端时的真实ATTACH才resource reply到子表，子返回0不等待它，父收到的本地Handle不得当子授权。EXEC_CLAIM按上述无槽消息来自真实目标image，服务从token记录恢复清单，不能靠自报token冒充。LOAD固定参数args的64字节[inode,generation,content_version,file_length,offset,bytes,data_off,flags]，只读同一装载会话版本；大文件读块仍属同次LOAD，不重新按路径定位。

TTYCTL子码GETATTR=1、SETATTR=2、DRAIN=3、FLUSH=4、GETSIZE=5、SETSIZE=6；Termarg=80字节[iflag,oflag,cflag,lflag,ispeed,ospeed,cc[32]]，前6个u64，cc字节数组32；只接受11列出的位与控制字符，cflag首版8位/无奇偶/1停止位，未知组合ENOTSUP，速度只支持启动设备既定速率。尺寸四u32 rows/cols/xpixel/ypixel，总16；PTY后续扩展沿此TTY接口，不让term持设备权限。

磁盘格式1只支持4 KiB块、最大128 MiB、1024个128字节inode：block0超级块，1日志头，2..17最多16个日志镜像，18提交块，19..64保留；65 inode位图，66块位图，67..98 inode表，99起数据。inode0无效、inode1根目录。超级块首128字节：magic(u64)、format(u32)=1、blocksize(u32)=4096、blocks(u64)、inodes(u32)=1024、root(u32)=1、log_start(u64)=1、log_blocks(u64)=64、inode_bitmap(u64)=65、block_bitmap(u64)=66、inode_start(u64)=67、data_start(u64)=99、uuid[16]、crc32c(u32)@96、reserved[28]；CRC32C覆盖首128字节并将crc字段置0，余块必须0。

inode128字节：generation(u32)@0、mode(u32)@4、uid/gid/nlink(u32)@8/12/16、flags(u32)@20、size(u64)@24、atime/mtime/ctime(s64秒)@32/40/48、三个nsec(u32)@56/60/64、indirect(u32)@68、direct[12] (u32)@72..119、reserved(u64)@120。文件块号u32，0为空洞；一级间接1024个u32，文件上限4 MiB。目录记录按8字节对齐且不跨块，头16字节[ino(u32),generation(u32),reclen(u16),namelen(u16),type(u32)]加含NUL名字，namelen<=255、不含NUL长度；空洞ino=0，未知/跨界记录损坏报EIO不越界继续。

日志头首256字节：magic(u64)、txid(u64)、count(u32)、state(u32)=1（PREPARED）、payload_crc(u32)、header_crc(u32)、target_blocks[16] (u64)@32、reserved[96]@160；其余块字节0，未用target为0。count为1..16；header_crc覆盖首256字节、将自身置0；payload_crc覆盖按target顺序排列的count个完整4 KiB镜像。CRC32C反射多项式0x82f63b78。

提交块首64字节：magic(u64)@0、txid(u64)@8、header_crc(u32)@16、payload_crc(u32)@20、state(u32)@24、record_crc(u32)@28、reserved[32]@32；其余块字节0。state仅EMPTY=0或COMMITTED=1；record_crc覆盖超级块uuid的16字节与首64字节拼接，将record_crc置0；保留字段和尾部必须0。EMPTY的两个日志CRC必须0，txid保存最后已回写事务编号；格式化生成带有效校验的EMPTY(0)，全零提交块不是EMPTY。COMMITTED要求txid非0，两个日志CRC与日志头相同。日志头和提交标记有各自magic，不互换解释。尚无已实现磁盘格式，本次保持格式号1，工具与FS须共同使用此修订，旧草案镜像整体重建。

格式编码待确认（2026-11-21，尚未实现）：建议三种magic为固定8字节ASCII `KFS00001`、`KLOG0001`、`KCMT0001`；CRC32C初值0xffffffff、最终异或0xffffffff，多段拼接只在最后异或一次，CRC字段小端。反射多项式仍为上述0x82f63b78，格式号仍1，旧草案镜像重建。已单独提问，确认前不据此实现盘上编解码；全部整数字段字节序、inode flags及目录type等未编码字段亦须先收口。

### 日志提交与恢复分支（第3项审查修订）

持久化前提：独占设备的单一FS写者；成功flush覆盖此前完成的相关写并使其稳定，断电不破坏已完成flush覆盖的其他位置；失败/超时的写或flush结果未知，立即停止新事务和home回写，待隔离旧设备请求并重新读取恢复，不以重试业务调用代替恢复。4 KiB写及物理扇区写均不假定掉电原子；撕裂写可留下旧/新混合或无效内容，校验用于检测，不能承诺识别任意介质损坏或CRC碰撞。设备必须报告兼容的写入/损坏影响粒度（不大于4 KiB且整除4 KiB），各日志块与home块不共享此粒度的单元；不满足几何、flush或故障隔离前提，不启用可写挂载。成功flush后仍发生的位腐坏、不可读扇区及设备违约另属介质故障，不作为“未提交”证据。

事务单写者按以下顺序推进；未提交元数据即使在权威缓存中变脏，也不得被后台回写到home：

1. 必须已有持久EMPTY(n)，且没有遗留COMMITTED或结果未知的I/O。取txid=n+1；n达到UINT64_MAX后拒绝新事务，不回绕。准备失败尚未写提交标记时可以丢弃，重用n+1不构成已提交编号复用。
2. 写必要文件数据并flush；再写日志头及所有镜像并flush。第二次flush成功前不得提交；数据/日志写失败则停止写入。普通数据覆盖不因此获得整笔数据原子性承诺。
3. 写COMMITTED(n+1)并flush，成功后事务才可报告持久提交，且此时才允许任何home元数据写入。提交flush失败也不能当作未提交；保持未知结果并由恢复判定。
4. 写全部home元数据并flush。期间日志头/镜像和COMMITTED不得覆盖，也不接受下一事务复用日志；新释放块虽已逻辑提交，也不能让后续分配事务越过本次日志退休。
5. 只有home的flush成功，才写EMPTY(n+1)并flush。最后一次flush成功才释放本次日志占用并允许下一事务；失败保留未知状态，不继续复用。EMPTY保留编号，不通过清零丢失跨重启的txid依据。

私有顺序核心接收可信所有者已编码并校验的整笔快照，不解析盘上字段，也不凭块号识别目录/间接元数据。一次最多16个元数据镜像及128个有序数据快照；复制描述符并保持独立不可变4KiB快照，逐项异步提交，每次最多一个下层I/O。即使无数据写入也先完成数据flush边界。每次提交使用同一初始化生命周期内不回绕的序号及txid，尚在途时不重复发出；提交失败而无下层引用可按确定失败完成，结果未知则停止发出新操作但继续保持原票据与快照。只有精确下层访问实际排空才解除在途责任。失败后的释放保持STOPPED，必须隔离旧I/O、废弃旧回调/票据并完成磁盘恢复，不能重试原业务或以重新初始化绕过恢复。正常EMPTY flush后释放才推进last并重新准入；COMMITTED flush后的durable标记不意味着home退休或日志可复用。

挂载先验证超级块和几何，再读取提交块；在恢复完成前不发布挂载/READY，也不向用户暴露未经恢复的home视图：

| 提交块判定 | 日志头/镜像 | 恢复动作 |
| --- | --- | --- |
| 完整有效EMPTY(n) | 可为旧值、未完成的新头、撕裂镜像，或准备区读取失败 | 不需要读取准备区来判定事务；丢弃准备，home不写，下一事务以n+1覆盖准备区。若另有设备级故障，仍按设备故障处理。 |
| 完整有效COMMITTED(t) | 全部字段、txid、两个CRC及目标验证通过 | 先读齐最多16个镜像到有界恢复缓冲，完整验证后才按目标redo；home flush成功后写EMPTY(t)/flush，才可挂载。 |
| 完整有效COMMITTED(t) | 不可读、CRC错误、头/提交不匹配、非法count/state/保留字、重复或非法目标 | 视为已提交日志损坏；不写任何home、不清提交标记、不覆盖日志，EIO拒绝挂载。 |
| 提交块不可读、全零、CRC错误、未知state或其他格式错误 | 任意 | 无法判定提交；可能是写提交/退休时撕裂，也可能是介质故障。保留现场并EIO拒绝挂载，不猜成EMPTY。 |

目标验证在任何home写前完成：地址在盘内，排除超级块、整个日志区及保留块；无重复目标。仅允许位图、inode表及由事务视图识别的目录/间接索引等元数据块，不能仅因块号>=99就允许写普通文件数据；验证须考虑本次新分配元数据的镜像，不要求它已在旧home中分配。完整校验后redo使用已验证缓冲，不在回写途中重新读取可能失败的日志。恢复中任何写/flush失败立即停止，不清标记；已写部分home不会成为可挂载依据。

断电例子（协议演算，尚非实现测试）：

- 已有EMPTY(7)，写事务8的日志头/镜像时断电，头CRC已坏但标记仍有效EMPTY(7)：忽略准备，不redo，可继续正常挂载；新分配数据可能留下未引用内容，不变成已分配块。
- COMMITTED(8)已持久化，仅两块home中的第一块写到一半即断电：日志完整则恢复覆盖两块并flush，再退休为EMPTY(8)；重放完整块是幂等的。恢复写第一块时再次断电同样处理。
- COMMITTED(8)有效但第二个日志镜像不可读或校验失败：即使第一块home似乎正确，也不开始/继续猜测回写，不发布只读业务挂载；保存原盘供诊断。
- 写提交标记时断电：读回旧EMPTY(7)则无home曾获准写入，可丢弃；有效COMMITTED(8)则恢复；混合无效标记则拒绝挂载。写退休标记时断电：旧COMMITTED(8)可重复redo，新EMPTY(8)表示home已持久，混合无效标记仍拒绝挂载。这里为保守故障策略，不承诺所有掉电点都自动恢复可用。

坏超级块不自动格式化；校验不能修复介质故障，也不能使原始home读取成为一致性恢复。磁盘工具、FS及后续实现测试共享本格式定义。

### inode回收与崩溃进度（交叉复核修订）

格式1没有额外孤儿表或extent树。持久待回收成员就是inode位图已分配且nlink=0的inode；运行时仍有合法打开/在途引用时保持可用，最后引用结束才回收。服务重建使旧File会话失效，挂载在旧块I/O已隔离/排空后扫描1024项inode位图/表，每批32项；nlink=0成员此时没有可继承的旧内存打开引用，继续清理。根inode1必须有效且有合法链接，不把坏根作为普通孤儿回收。

每批回收在16元数据块日志上限内选一组已无在途数据I/O/缓存使用的块，将inode或间接表中的引用置0与对应位图释放同事务提交；提交并完成日志退休后才供后续分配复用。间接数据指针清空后才能移除/释放间接块，全部块清空后最后释放inode位图；不因nlink=0就一次清位图后再慢慢追旧指针。进度始终由盘上剩余指针恢复，不使用未定义的持久游标字段。inode复用递增u32 generation，耗尽停用而不回绕，不能使旧目录/File引用命中新节点。

已链接文件截短时先事务性固定新size，EOF以外仍未清的指针表示待释放尾部，恢复扫描亦继续清理；只有超过向上取整文件长度的整块可这样释放，最后部分块仍保留。后续增长必须先完成重叠清理，并按有序数据规则把新可见区域清零/初始化，不能重新暴露旧尾部内容。正常事件循环分批推进，不在IRQ/内核实现；对块仍有I/O或打开文件所需使用引用时保留，逻辑删除不等于实际可复用。

例子：unlink最后名字与nlink=0已提交，但文件仍打开，原File可继续读写。FS崩溃后旧会话全部失效，恢复发现该inode仍分配且nlink=0，逐批清其指针/位图；第二批回收中断，重放日志后从剩余非零指针继续，第一批不会再次释放。若truncate已把size降为一块但尾指针仍在，恢复仅回收EOF外的整块；未完成初始化前不能把旧尾数据当作新增长内容。

### 本地fd槽表原语（2026-11-20）

libsys私有Fdtable固定128项、每项32字节、总尺寸4096字节，存储由使用fd模块的调用者在发布前预付；库本身无全局表、malloc、原生调用或IPC。sysfdinit只用于无所有权的新存储，不是销毁活表的接口；重新初始化前须先移交全部LIVE引用并撤销预留。原生短消息程序不会因归档库增加该对象而自动分配工作区。fd模块每次调用前由运行库保证短暂屏蔽可捕获信号，所有操作有界且不跨RPC；此层不是文件服务、File引用池或公开POSIX fd API。

槽状态FREE=0、RESERVED=1、LIVE=2、RETIRED=3。每槽记录generation/file/flags/state，file仅为非零的本地File身份，不是内核Handle，也不单独提供后端权限；LIVE只表示本地描述符可见，不证明后端连接已经CLAIM/READY。后端偏移、访问模式、O_APPEND/O_NONBLOCK、连接及准备token仍由对应File/连接记录负责，表内只保留独立的FD_CLOEXEC。其既有位1现以abi/boot.h的BOOT_FD_CLOEXEC为唯一常量来源，Bootfd布局/格式不变。

Fdtag=(generation:u64,index:u32,state:u32)标识受理时观察的槽状态，不能仅比较fd整数或代次。reserve选择minimum起最低FREE项，推进代次并标RESERVED；发布必须仍匹配原RESERVED标签，随后以同一代次转LIVE。旧预留标签因state改变而失效，不能在发布后cancel或覆盖新fd。cancel和detach推进代次；replace则在重查旧标签后推进代次并提交新LIVE值。UINT64_MAX从不回绕，最后的关闭/取消将槽退休；需要新身份却无法推进时返回OVERFLOW且旧描述符不变。

publish/replace成功时，调用者事先准备的一份本地File引用移交表；失败仍由调用者持有。detach/replace成功将旧LIVE引用连同旧标签/标志移交调用者的预付收尾记录，不自行关闭后端，不按已复用fd整数再次定位。输出记录必须由调用者保证无待覆盖的所有权且不得与表重叠，失败保持其内容。条件replace拒绝仍RESERVED的目标，也拒绝已换代或状态已改变的旧观察；同文件身份替换仍是一次引用移交，不能暗自省掉新/旧引用记账。源File的pin、同fd dup2无操作、别名计数及旧对象关闭容量在上层处理，本地提交不重读源fd数字。

具体场景：外层open已预留fd4，handler不能用replace窃取该槽；外层发布后原RESERVED标签也不能取消LIVE fd4。另一场景观察fd3/gen7指向A，handler先将其替换为B/gen8，迟到detach(gen7)返回STALE，B和旧输出记录保持原样。两个描述符均指本地File42时，修改一个CLOEXEC不改变另一个；将目标再替换为同一File42时仍返回旧引用，由上层按别名/在途引用规则归还。

### 连接线格式与私有页租约（2026-11-20）

已冻结的FS/TTY连接头、128字节槽描述符、槽状态及操作码现集中在proto/file.h：头64字节、控制页4096、8个4096字节数据页，总36864；描述符seq/state/payload/object/span偏移0/8/16/24/32，args在64，保留字段0。13..15仍不分配，不恢复CANCEL/RESULT/RESULT_ACK协议。布局用共享断言锁定，内核不包含该服务协议。

私有sysfilehead只复制一次固定头到私有存储，再以调用者持有的真实映射长度、connid和服务image核对；不从共享bytes创造访问范围，也不凭魔数授予File或后端权限。真实source/backend连接选择、资源/映射来源及有效C存储是调用者前置条件。头函数不扫描整页padding，padding由创建者清零；每个操作的对象归属、固定args及payload仍须由服务按私有记录核验。

sysfilerequest只复制一次被选描述符，要求原消息seq匹配、SUBMITTED、payload不超过span*4096、保留字0；span=2只允许0/2/4起始且续页描述符128字节全0。固定输出不得落在被读连接区内，失败不覆盖旧输出。检查基于这份私有快照；共享字段后续变化不能改写已经保存的快照。这是共同形状检查，不冒充按操作完成权限/未用args或服务私有在途登记。

Filepages是每连接独立的私有占用账本，Filelease=(seq:u64,slot:u32,span:u32)，不是共享状态或RPC所有权表。普通上下文仅0/1，两层handler各2/3和4/5，控制6、收尾7；无可用页返回BUSY，不等待或借其他分区。所有层共用该连接的单调sequence，成功取得页/页对才推进；UINT64_MAX仍可完成旧租约释放，但不再产生新序号。释放须逐项匹配原seq/起始页/span，双页整体归还，不可把续页单独释放或以迟到标签清掉同页新请求。

本层不自动判断请求已完成：共享DONE、handler返回、Rctx离开或应用逻辑超时均不会归还页；调用者必须先保存真实结果/数据/资源并证明访问结束，或把原租约连同原RPC移交预付后台责任。账本不存应用缓冲指针、不发IPC、不分配内存，也不自行销毁File/资源；调用者在短本地信号排除段使用，并只初始化无所有权的新账本。它可嵌入后续每连接4 KiB私有页，但此点尚未实现8条连接目录、bootstrap或8*128字节责任记录。
