## init 与普通操作的责任边界（修订确定）

本节明确普通操作的协调者分配；权限检查、发布原子性、失败回滚和资源安全条件继续有效。

| 职责 | 正常执行者 | init 的职责 |
| --- | --- | --- |
| 基础服务启动、依赖、READY | init 与相关服务 | 引导、监督及发布服务实例 |
| 全局预算、初始授权、设备分配 | init 制定，内核强制检查 | 系统策略与受限权限配置 |
| 普通 fork/spawn | 调用者 libsys、内核、FS 等参与服务 | 超出既有权限或特殊身份创建时介入 |
| 普通 exec | 当前进程 libsys、FS、内核 | 不逐次代办镜像装载与替换 |
| wait 与退出结果 | 父进程直接向内核领取 | 接管孤儿，收取自身孩子，监督获权服务 |
| 普通会话及连接清理 | 资源所属服务与内核生命周期机制 | 服务失效后的恢复与必要兜底 |
| 作业组、会话和前台切换 | sh、tty 与内核 | 初始终端授权与系统策略 |
| 普通共享与连接建立 | 已获授权的进程及服务 | 扩大预算、设备权限或信任边界时介入 |
| 驱动/服务恢复、全局关机 | init 协调，相关服务执行 | 保留全局协调职责 |

普通创建权限须限制来源身份、子身份、数量、预算和可继承授权，不能借创建取得任意跨进程管理权。

调用者运行库只负责正常流程，不能成为唯一清理者。内核和服务必须持有绑定完整实例/镜像及准备阶段的有界记录，并在调用者死亡后停止发布、解除准备资源或完成已提交收尾；通知须可靠或可重查，不能依赖一次可丢事件。退出结果、管理者观察和服务清理通知是独立责任，不能互相抢先消费。

普通 ELF 加载器放用户态可复用模块，init 引导服务和调用者 spawn/exec 可复用校验逻辑；执行权限仍由 FS 按可信调用者及目标凭据检查。exec 不可撤销点之后旧镜像不能再负责继续用户态协调，由内核及已登记服务独立完成旧归属收尾，新csu只做本地初始化，连接按需领取；规则见08的第5项修订。

### 示例：父进程在 fork 准备中死亡

父运行库请求不可运行孩子，FS 已准备继承引用，内核尚未发布。父死亡后，孩子不得迟到发布；内核与 FS 根据同一实例的准备记录撤销孩子和暂存引用，不等待父发送 abort。init 不逐次代办正常 fork，但可监督异常清理。若发布先于父死亡，则孩子按孤儿关系处理，不能回滚成未创建。

### 冻结规格的阅读位置

- 普通创建/受限委托权限、预算归属和失败返还规则。
- 父直接 wait 的记录所有者、确认点、信号取消与孤儿转交；不再强制 init 复制第二份结果表。
- 服务订阅生命周期的权限、预付容量、可靠交接与重查方式；不得给普通客户端任意清理他人资源的权限。
- 调用者协调的 fork/spawn、exec 提交后的继续执行责任，以及 sh 自有作业屏障；普通流程不走init专用代办协议。

## 基础进程与启动闭环

目标用户态按最新架构图组织职责，但方块不都代表进程：dev 合并进 init。以下不表示全部都是第一阶段的启动依赖。

| 组件 | 职责 | 范围 |
| --- | --- | --- |
| init | 引导、进程构造、授权、加载、退出收取、设备管理及恢复 | 串口 MVP |
| sh | 命令交互，调用用户态 spawn/wait 和标准流 | 串口 MVP |
| serial | UART 初始化、字节收发、IRQ 和有界设备缓冲 | 串口 MVP |
| tty | 行处理、回显、退格、终端实例及控制终端协议 | 串口 MVP |
| dev（init 内部） | 设备发现、驱动匹配和启动协调 | 先支持静态清单和 DTB，不单独启动服务 |
| blk | 块设备协议、DMA 及扇区读写/flush | 存储阶段 |
| fs | VFS、统一命名空间、打开会话及具体文件系统后端 | 存储阶段 |
| net | 网络设备与 IPv4/TCP/UDP 等协议服务，范围见[文件描述符、VFS 与持久化](10-filesystem.md) | 网络阶段，lwIP 已选、设备型号待验证 |
| dis | display 显示服务：显示设备、帧缓冲或画面提交，替代 print | 图形阶段 |
| win | 窗口、合成及焦点输入分发 | 图形阶段，设备输入来自 input |
| input | 键盘/鼠标等设备驱动及输入状态 | 图形阶段，独立驱动进程 |

init 内部 dev 模块处理发现、匹配和设备登记，授权/进程管理模块核对 MMIO/IRQ/预算并创建驱动，普通驱动仍独立进程。
发现结果不是可信授权，仍必须核对来自启动资源或获准总线窗口，不能登记任意地址扩大资源范围。
模块间使用普通函数和操作状态记录，不为 dev 增加 RPC、READY 或独立恢复进程；设备 I/O/复位等耗时外部操作仍异步推进，不阻塞 init 控制循环。
早期 RAM/保留区和控制器资源仍由内核从 DTB 获取，普通设备协议及总线枚举策略归用户态。
首版不承诺设备热插拔或通用 PCI 配置；支持设备须按[文件描述符、VFS 与持久化](10-filesystem.md)定义 DMA 安全恢复或明确安全离线，不以驱动重启代替复位验证。

串口交互先跑通 init → serial → tty → sh；init 内部 dev 的初始清单/匹配在这一过程中接入，不能引入依赖环。
随后接入 blk → fs；net 及图形路径单独推进，不把未支持设备的空进程算作服务交付。
init 用异步 call 与有界操作状态机加载程序、建立连接并等待 READY，主循环持续处理请求、事件和退出确认；不拆独立内存管理或注册中心。
内核只启动 `init`；基础服务镜像由启动镜像携带，挂载后普通程序从文件系统加载。
服务必须完成 READY 握手后才能启动依赖者；失败有明确错误，不能无限等待伪装成启动中。
基础镜像清单、依赖关系、预算和授权集中配置，明确 `init` 故障为首版致命错误，不宣称可自恢复。

### 内核向 init 的启动交付（已确定）

只读 Boot 描述 ABI 标识/大小、页大小、内存与保留情况、镜像清单、启动参数及设备资源对应 Handle；实际权限来自 init 资源表，不来自地址描述。
设备资源记录含精确范围、类型/匹配信息及可选 IRQ；子进程启动信息仅列实际获授资源，不能照抄 init 完整清单。
可将原始 DTB 只读交给 init，但授权只依据内核已验证资源范围，不能凭用户传入 DTB 地址取得任意物理映射。
启动依序建立早期异常诊断、验证固件/DTB、物理页和内核映射、必要时钟/中断/调度，再创建授权完备的 init 并进入用户态；架构必要的早期步骤在其入口内完成。
基础服务镜像由构建清单携带，内核装载初始 init 时仍检查边界/架构，其余镜像由 init 检查并加载，不依赖尚未可用的 fs。
init 按 serial→tty、blk→fs 等依赖等待 READY 后发布连接；启动镜像可提供串口调试环境，fs 就绪后普通命令须能从磁盘加载。
必要 DTB/内存/控制器资源缺失明确失败，不猜测设备地址；早期故障输出仅保留目标开发板最小固定串口例外。

### 启动包与根目录（已确定）

启动包以清单和只读文件内容携带 init、基础服务及救援 sh，不要求实现 initramfs 文件系统。
内核只装载首个 init；init 从包中装载 serial、tty、blk、fs，基础服务不依赖磁盘根目录。
fs 完成磁盘根目录挂载和日志恢复后报告 READY，随后 init 启动普通 sh，普通程序通过 fs 加载。
启动包按恢复清单保留基础服务镜像，计入保留内存预算；临时装载页及时回收，仍被引用的包页不能释放。
磁盘缺失、挂载或恢复失败时，init 从启动包进入串口救援 sh；文件请求明确返回根目录未就绪，不无限等待。
串口和 tty 自身失败不能宣称已有交互救援环境，须报告具体启动阶段；init 故障仍为致命错误。
无需先挂临时根再切根；未来内存根目录通过 fs 后端接入，不向内核引入 VFS。

- [ ] 无磁盘、损坏根目录及恢复失败场景进入明确救援状态；正常启动从磁盘加载程序。
- [ ] 重启基础服务不依赖旧 fs 可用；重复加载后临时页回收，保留包引用和预算正确。

### 启动包格式与装载边界（已确定）

启动包包含定宽头、程序清单、首个 init 的预生成装载描述和各程序 ELF 内容，明确字节序/对齐。Boot 是进程启动信息，不与启动包容器混为一体。
构建工具解析 init ELF，生成包内数据偏移、目标 VA、filesz/memsz、最终权限及入口描述。内核仅校验包/描述边界、溢出、段冲突、入口/权限，按描述复制/清零和封存，不引入通用 ELF 节表/动态链接/路径解析。
init 读取基础服务原始 ELF，按既定用户态加载器校验/装载；内核不装载所有服务。包中保留原 ELF 与装载描述时可引用同份文件字节，不要求重复保存内容。
名称唯一、条目范围合法，镜像偏移不解释为任意物理地址；必需程序缺失构建时拒绝，运行时仍校验包。具体格式字段/布局在共享定义冻结，未知格式不兼容旧版本。
包原始内容只读保留并计预算，进程可写数据独立分配，不把整包映射为可执行；校验和只检测损坏，不构成签名/可信启动承诺。tools 中主机打包工具负责生成，不向内核引入 tar/cpio/文件系统解析器。

#### 示例：首个 init 与 serial 的不同装载路径

构建工具从 init.elf 生成装载描述，内核验证后建立首个 init；init 再从启动包取得 serial.elf、自行解析并创建用户实例。两者最终都用相同用户态 Boot 格式启动，但只有首个实例由内核依预生成描述装载。

### 构建与服务清单（已确定）

构建清单分别描述程序安装位置、启动包成员及服务配置；服务配置含 READY 依赖、预算、设备匹配规则和失败策略。
同一架构的同一个 ELF 产物可同时进入启动包与磁盘镜像，不维护重复源码或构建规则。
设备匹配不写死 MMIO 地址或 IRQ 号，init 必须将匹配结果与内核发现的实际资源授权核对；清单不是额外硬件权限来源。
主机构建工具校验重复名称、缺失成员、循环依赖、目标配置和字段范围，生成定宽、有界、带格式标识的记录；init 仍校验记录边界和语义，不携带复杂文本解析器。
依赖以服务 READY 为条件，独立服务可并行初始化；必需服务失败进入对应救援或失败状态，可选 net/dis/win 失败不阻止串口环境。
编译配置选择硬件支持与容量，清单选择程序与启动策略；两者不重复定义 ABI 或绕过运行时资源检查。

- [ ] 重复名称、依赖环、缺失镜像、超限预算和损坏生成记录明确失败。
- [ ] 验证独立服务初始化可并行、依赖者不会提前启动，可选服务故障不阻断串口。

### 服务就绪与发布（已确定）

init 内服务记录区分 STARTING、READY、STOPPING、FAILED；这些是用户态管理状态，不新增内核服务对象或注册中心进程。
READY 表示声明支持的请求所需初始化已完成：serial 的设备/缓冲/IRQ、tty 的后端连接和终端状态、blk 的协商与队列、fs 的根挂载与恢复均须完成。
init 配置未运行实例的权限、预算和依赖连接后启动；服务经专属控制连接报告 READY，init 核对完整进程身份、启动状态和协议版本后才发布连接并启动依赖者。
初始化超时不等于退出：先撤销发布，再终止并按既定请求/DMA 协议收尾；收尾未完成不能重授危险设备资源。
重启使用新实例和连接代次，旧连接明确失效，不能将旧句柄重定向到新服务；READY 后故障同样撤销发布并通知受影响客户端。

- [ ] 伪造、重复、迟到及旧实例 READY 不改变当前发布状态；退出与 READY 竞态不发布已退出实例。
- [ ] 初始化超时和 READY 后故障均完成撤销、通知与安全收尾，依赖者不取得失效连接。

### 启动依赖与故障恢复（已确定）

依赖 READY 表示启动前提，绑定具体服务实例，不自动意味着上游退出就杀死全部下游。init 先撤销旧发布/阻止新连接，再通知依赖者处理旧连接失败；可保留本地状态的服务不无条件重启。
依赖者终结受影响请求并按协议收尾，待旧资源安全、新实例 READY 后显式重连；不能把旧会话悄悄指向新实例。无法保留状态/重连才按配置退出或重启。
恢复次数/频率有上限及退避，隔离资源到限停止尝试；关键服务失败进入救援/失败，可选网络/图形故障不阻断已有串口环境。

#### 示例：serial 故障不会复活旧终端

serial 退出后 tty 停止旧后端 I/O 并按协议挂断、唤醒等待者；sh 旧终端会话按挂断规则处理。新 serial READY 后 tty 可建立新后端，但已挂断旧会话不复活，应创建新终端并显式启动/恢复交互环境。
fs 故障则旧 fd 失效、sh 显式重建上下文，不自动重启所有应用；依赖图不能替代各服务的恢复协议。

### init 的非阻塞管理与自有内存

- init 仍是单线程策略中心，所有与外部 fs/tty/驱动的协作使用 CALL_ASYNC 和预付操作表，不同步等待外部服务；用户请求以延迟回复持有。
- 每个受管服务启动/恢复操作保存阶段、已取得资源、目标代次和截止时间，主循环处理完成事件并推进，不在一个操作里等待到结束。
- 超时对外部Rq请求协作取消、转后台跟踪并隔离尚未归还槽，不假定已接收Rq立即终结，操作向调用者明确失败；服务失联不阻塞退出收取、信号与其他管理请求。
- 普通进程可被授予 SELF_ALLOC/SELF_MAP：仅自身地址空间、既定预算及允许的普通内存类型，不能增预算、授予别人或取得设备权限。malloc 扩容不回调 init。
- init 修改预算、全局授权和跨进程映射仍走明确管理 syscall。服务进行普通 I/O 不回调 init 取得控制资源。
- 会话/组/终端前台关联由内核保存受限机制状态，init 配置策略；tty 持终端信号授权直接 sigsend，不经过 init RPC。
- sigsend 从终端授权解析当前前台组并校验关联代次，不接受 tty 任意指定 PID；组及前台状态变更有内核原子提交点。
- 会话/组创建与成员变更、终端关联/前台设置、sigaction/sigmask/sigsend/sigreturn 都采用明确 syscall，分别检查管理授权、组关系或当前进程权限；不复用普通 notify。

验收：fs 延迟或失联时同时提交 spawn、进程退出、SELF_ALLOC、Ctrl-C；控制有进展，操作超时不重放写请求，未归还区仍保留且有配额。

### 结果确认与跨服务操作

- 内核 Life 保存可领取退出结果，父直接 wait；init 只收取自身孩子及已接管孤儿，不复制第二份退出表。
- 普通 wait 改为父直接向内核领取，方案以一次原子交付消费结果，不保留旧 init RPC/waitack；输出故障及信号顺序见 [wait 交付](03-process.md#父直接-wait-与结果消费已冻结)。
- fs/tty操作以原RPC取得唯一结果，连接/序号匹配原槽；信号后仅查询原RPC，read数据留原槽到复制/保存。服务reply后不再维护等待业务ACK的结果表，不能以新Rq重发找回结果。
- 序号耗尽关闭连接不回绕；Rq/共享槽未释放形成有界背压，客户端退出按强制终结及实际收尾清理。不承诺跨新Rq的通用去重，准备token/已提交全局关机等对象仍按其生命周期幂等，不是另一张I/O结果表。
- 服务崩溃后的判定取决于持久化：未记录持久结果的写只能报告 UNKNOWN，不声称 exactly-once，不自动重放；业务结果恢复不得伪造成通信成功。
- spawn/继承/连接/前台切换使用操作序号和 PREPARED→COMMITTED/ABORTING→DONE 状态；发布前逐项逆序补偿，发布后按退出/收尾处理，不能直接销毁运行实例。
- prepare 在各服务绑定完整实例及发起者；获权协调者操作超时显式 abort，参与者死亡由同一代次清理，重复 commit/abort 幂等，不依赖分布式无限等待。

验收：每个执行/回复/确认边界退出或信号取消，wait 结果不丢、close 不误关、read 偏移不重复推进；崩溃写保留结果不确定性。

### spawn 的文件动作与继承（已确定）

原生启动与 POSIX 包装共用准备/发布流程。取得父进程 fd 一致快照并固定继承引用，在不可运行子进程中配置描述符；File 及偏移按继承规则共享，本地 Handle 必须由授权建立。
文件动作按提交顺序执行，后续动作观察前面修改后的子进程描述符表；动作完成后按标准处理仍带 FD_CLOEXEC 的描述符，不能在动作前直接丢弃所有 CLOEXEC 源描述符。
所有描述符、权限、启动内容和必要关系准备成功后才 start；描述符表跨进程表示由既定继承协议与 Boot 交付，不复制父进程用户指针。
文件动作的路径、权限按子进程目标凭据、继承 cwd 和 umask 执行；init 管理身份不能绕过这些检查，服务不信任普通客户端自报凭据。
失败撤销本次创建实例、授权、引用与共享资源，不保证撤销已产生的外部文件副作用；已创建/截断文件不能承诺恢复原内容。已启动实例失败按终止/退出流程处理。
POSIX 文件动作/属性支持集合逐项列于兼容清单，具体标准错误返回与发布阶段须一致，不以原生 spawn 名称替代 posix_spawn 语义。

### posix_spawn 准备中断与发布返回（已冻结）

确定父进程捕获信号本身不使 posix_spawn 返回 EINTR，也不因 SA_RESTART 重做创建。先使本次快照/文件动作进度和库表对 handler 安全，运行 handler；正常返回后仍按已接受快照推进同一个未发布孩子。固定输入前的版本一致性检查保持既有规则；接受后不混入 handler 改变的新 fd/cwd/参数。已经执行的文件动作只查询原结果，不从第一条重做，特别是不再次创建/截断文件。

发布前真实失败时，先禁止发布、补偿本次引用，再按 posix_spawn 自身形式直接返回正错误号；文件动作已产生的外部效果不承诺回滚。发布成功固定唯一孩子 PID 及成功结局，随后信号、子退出或父 handler 的 wait 不将它改成“未创建”；外层完成原结果输出，不再分配另一个孩子。PID 输出故障的副作用契约仍须单独冻结，不因复制失败便谎报未发布。

STOP 不隐式取消、恢复后重查原阶段/既有期限；父死亡/镜像替换则发布前清理，发布后保留孩子合法引用。子进程程序启动故障与父调用错误如何对应既有发布点、退出状态127及可观察时序，仍列入兼容审计，不把本段当作完整 POSIX 保证。父准备需可被信号打断不表示 posix_spawn 可在 handler 内任意重入，公开异步安全范围另行审计。

例子：文件动作已完成 O_TRUNC 打开日志，父 handler 随后写日志。恢复时继续该打开结果之后的下一步，不再截断；若后续另一动作失败，返回相应正错误号且没有已发布孩子，但此前文件变化可以保留。

### spawn 快照与接受点（已确定）

libsys 在提交前复制路径、argv/env 和文件动作，固定 fd 引用与描述符标志；不将可被调用者后续修改的指针作为长期输入。
本地表的固定/发布使用短暂信号屏蔽，不在临界段复制大块参数或等待 IPC；大块内容须在有界私有暂存中形成稳定请求。
调用者准备时固定可信目标凭据、cwd/umask、会话/组与信号配置，以及操作预算/必要引用。跨服务状态使用稳定引用及版本校验，不仅传路径字符串。
本地 fd 快照与管理状态不能任意混合：接受前检查参与快照的源实例、状态版本及继承前提仍一致；不一致则安全释放后重取或明确失败，重试有界。接受点的提交不等待外部服务。
接受后使用固定快照推进，不重新读取父进程当前状态；快照保留的 File 本身偏移/共享状态仍依既定语义变化，固定引用不等于复制 File 内容或冻结其偏移。
父进程退出与子进程发布按明确先后提交：尚未发布则取消创建并收尾，已发布则使用孤儿规则；不以回复是否送达判断发布与否。

### 迟到回复、超时与发布（已确定）

跨服务操作保存发起进程完整身份、参与服务实例、操作序号、当前阶段和相关 fd/上下文代次；回复须与预期参与者及阶段匹配后才能推进，不只检查服务名或消息操作码。
取消后的操作不因迟到成功回复复活；若回复证明旧操作创建了资源，只按该操作原身份补偿，不按当前 fd、服务名或当前上下文释放。参与服务须按操作序号保留可查询结果和幂等补偿记录。
操作超时不等于提交失败。提交前确认取消则补偿，已提交则查询同序号结果，提交状态不明则保持待确认并限制冲突操作；不能先当作失败重新执行副作用。
操作槽/相关缓冲在必要结果确认和参与者收尾完成前不得复用，仍占配额；服务永久失联时按实例撤销/退出和设备安全协议终结或隔离，不能无限重试。

#### 示例：旧恢复回复迟到

sh 发起 R1，等待中超时；init 先查询/取消并确定 R1 的发布状态。只有确认 R1 已取消或已与后续状态安全隔离，才允许冲突的恢复 R2 开始；状态不明时 R2 明确等待/拒绝，不直接覆盖。
R2 提交后若收到 R1 的迟到成功回复，不能安装 R1 的 cwd/标准流。旧回复只推进 R1 的结果确认/资源补偿，校验原服务实例及资源身份，不释放 R2 的新引用。
若查询发现 R1 其实已经提交，应返回 R1 的既有结果并继续其协议，不能先重做一遍 R2 再假装 R1 从未发生。代次防串线，阶段状态机防重复发布。

### fork/exec 与现有启动事务（范围调整）

fork/exec 的正常协调改由调用者 libsys 与内核/资源所属服务完成，不新增 init 代办职责；保留预付准备/回滚记录和明确提交点，不把父进程所有在途业务排空当作 fork 的无期限前置。
fork 从父执行现场延续，不能调用普通 configure 将孩子置到 _start；exec 不创建新PID，不能调用只接受未启动实例的 configure 重写正在运行进程。需专门的克隆/镜像替换机制，共享内部校验/页表/发布逻辑，而非放宽现有接口状态检查。

### sh 自有作业准备屏障（已冻结）

方案不新增 jobstart syscall，也不让 init 持有作业 READY 请求；用已有 fork、setpgid、终端前台接口和普通管道组合。进程组权限参考 [setpgid](https://man7.org/linux/man-pages/man2/setpgid.2.html)，前台关系参考 [tcsetpgrp](https://man7.org/linux/man-pages/man3/tcsetpgrp.3.html)；以下管道握手是本项目 sh 的实现方案，不声称是这些接口自动提供的原子作业事务。

1. sh 先检查作业成员/管道/暂存容量，创建数据管道和本作业专用的 ready、gate 两条控制管道。它们是普通 File，不新增内核对象类别；所有控制端点不进入目标命令，内部临时端点标记 CLOEXEC并显式关闭。
2. fork 各成员，首个孩子 PID 作为 PGID。父在 fork 后立即 setpgid，子在自身准备代码中也 setpgid，并核验结果一致；不把全部错误当可忽略，已退出或错误组成员须按实际状态处理。内核保持同会话、合法父子关系与 exec 边界检查，不靠可信 sh 防止越权。
3. 子设置重定向、关闭多余数据/控制端点、恢复目标所需信号配置，向 ready 写一个有界身份/结果记录，再关闭自己的 ready 写端。各记录不超过 PIPE_BUF，父按字节流累计完整记录，不假设一次 read 返回一整条。子只保留 gate 读端并读取一个明确放行字节；未取得放行字节的 EOF/错误表示取消，直接退出，不能把 EOF 当成功广播。
4. sh 核验全部成员 ready、仍处于本次合法作业状态；前台作业先用终端接口把前台组切到目标 PGID，再向 gate 写入每成员一个放行字节并关闭 gate。每个子只读一个字节即关闭自身 gate 端，然后 exec。后台作业不取得终端前台。方案限制成员数使放行字节总数不超过 PIPE_BUF及配置容量，但不承诺所有成员同时被调度。
5. sh 关闭多余数据端点，按组/成员收取停止、继续和退出状态；全部未退出成员停止或全部退出后，按终端契约恢复 shell 前台及模式。fg 先恢复前台/模式再 CONT，bg 只 CONT。

控制管道只由 sh 与本次 fork 的准备代码持有。所有孩子必须关闭 gate 写端；否则 sh 死亡后写引用泄漏，其他成员不会看到 EOF。孩子发完 ready 后关闭 ready 写端，父关闭自己不用的写端，避免缺失一个记录时仍因无用写引用永远等不到 EOF。业务数据管道同样关闭所有不需要的引用以保证 EOF。

准备中成员提前退出、停止或重定向失败，sh 取消尚未放行成员，并用有权限的信号处理已运行孩子，再 wait 收取；不使用发布前已失效的管理 Handle 调用 terminate/destroy。准备阶段用有界 poll/截止与非阻塞 wait 检查成员状态，不无限阻塞读 ready。SIGCHLD 提示与 poll 之间的竞态不能靠偶然再次到信号解决；至少以有界等待保证重查，轮询片段50ms、总准备10秒，不引入尚未纳入范围的 pselect。

前台切换成功后 gate 写失败，sh 重新核验自身会话与关联代次，恢复可恢复的 shell 前台、取消剩余成员；若已有成员取得字节并执行，只能按正常信号/退出处理，不承诺撤销已写文件或外部副作用。Ctrl-C/STOP/KILL 可发生在各阶段，gate 放行不清除 STOP/EXIT，也不重新发送已处理信号。sh 死亡时尚未放行的成员收到 gate EOF 退出；已放行成员按会话/终端挂断和孤儿规则处理。

终端切换是受权限检查的单项提交，管道放行是后续同步；没有全局“全部成员同时开始”的承诺。正确性要求是每个目标命令在执行前已完成本成员准备，前台命令在放行前已有目标前台组，而不是让内核理解 shell 作业协议。

#### 示例：cat input | grep word

sh 建数据管道和 ready/gate，两个孩子进入同组，安装各自 fd并关闭多余端点，写 ready 后等 gate。全部准备成功则 sh 切前台、写两个放行字节，孩子各消费一个并 exec。若 cat 的重定向失败，sh 不放行 grep，关闭 gate 使其退出并收取两个成员；若失败发生在已放行之后，则作为运行中作业失败处理。目标命令不继承控制端点。

## 首版启动清单与作业协议（已冻结）

启动顺序：内核进入init→serial→tty→blk→fs→sh；无存储配置在fs前明确只用启动包/tmpfs，不伪造磁盘功能。init内部dev解析受信设备清单、匹配驱动、分配既定Set/预算与设备权；普通程序加载/fork/exec/wait不经init。初始init死亡panic/halt，不复用PID1。服务create使用SERVICE创建权，init显式持该服务持续CONTROL（含INSTALL），对已运行服务grant仍须该固定目标INSTALL和独立源GRANT；普通父只持发布前CONSTRUCT CONFIG。监督观察也传该目标CONTROL QUERY，不以init身份跳过basis。

init控制协议words=[opcode,seq,arg0,arg1]：READY=1、LOOKUP=2、SHUTDOWN=3、STATUS=4；READY带启动清单服务编号及自身image，由内核source验证，普通应用不能自称服务；READY期限由init在该受管服务成功start时另设绝对10秒；到期可凭固定CONTROL取消/终止并记录阶段。此为清单服务监督策略，区别于发布前PREP_NS，不施加于普通fork/exec/spawn进程，内核不计时等待execready。LOOKUP仅返回按策略允许的后端CALL资源reply，不授予设备/全局管理；重复seq只返回原业务状态/EALREADY，资源结果从原RPC/稳定返回现场恢复，不重复安装资源。基本服务之间的静态CALL/NOTIFY在构造期grant，动态文件连接按10两次交付。

spawn属性只支持SETSIGMASK、SETSIGDEF、SETPGROUP、RESETIDS；RESETIDS仅将有效值设为已有真实值，首版固定凭据要求合法，否则拒绝，调度/setsid扩展flag不静默接受。文件动作OPEN/CLOSE/DUP2按顺序，PATH查找至多32项/总4096字节，空分量表示cwd，遇EACCES继续其他项后择优报告，ENOEXEC不执行sh脚本替代。参数/动作先快照，最多128动作；准备失败正错误返回且无已发布孩子，文件外部效果不回滚。

spawn发布前检查pid输出初始可写，关键发布结果仍用寄存器；后续复制FAULT是已发布副作用扩展，不能二次创建。所有可预见加载/动作/预算错误尽量发布前报告；发布后新csu本地初始化失败用127退出、父保留成功PID；远端按需接入失败由当前操作报错，不自动结束进程，异步KILL则真实信号退出，不伪装127。父handler先wait收取也不改原成功。

sh首版最多8条管道成员，同组ready/gate方案固定：每成员ready记录24字节[完整PID,u64 stage,s64 result]，单条<=PIPE_BUF；父累计完整记录，所有成员准备成功后切前台，向gate写每成员一个0x01字节。EOF/其他字节均取消，不能把EOF当放行。准备总期限10秒，poll等待片段最多50ms并排空wait，保证即使SIGCHLD与poll错过一次提示仍有界检查；不承诺50ms硬实时。取消关闭gate，未放行孩子退出，已放行孩子只能合法信号/wait，前台按SID/终端代次恢复，不使用失效构造Handle。

## 执行与验收

- [ ] ready/gate 全部父子端点按角色关闭，控制端点不进目标程序；缺失ready、部分记录、准备失败、成员STOP/KILL及sh死亡均不永久挂起。
- [ ] 父子setpgid不同执行顺序、首成员提前退出、前台切换失败/成功后gate失败、Ctrl-C和组停止覆盖，不能用过期组号恢复他人前台，不要求原子同时启动。
- [ ] gate每成员消费一次明确字节，EOF表示取消；父死亡前后部分放行按真实阶段处理，已运行成员只走合法信号/wait路径，外部副作用不承诺回滚。

- [ ] 普通 fork/spawn/exec/wait、作业控制及既有权限内连接不经过 init RPC；在 init 管理循环暂停处理普通请求时仍能完成，特殊身份/超额操作拒绝或明确请求策略授权。
- [ ] 在每个 prepare/commit 边界终止调用者，未发布孩子和服务准备引用最终收尾；已发布孩子不重复发布，exec 提交后不依赖旧镜像继续执行。
- [ ] 退出、孤儿转交及服务生命周期通知重复/合并/延迟时不丢结果、不误清理新实例；准备容量耗尽先拒绝，不临时依赖无保证分配。

- [ ] fork成员在准备阶段可运行但目标命令须等屏障；具体屏障拒绝错误身份/成员，不把任意阻塞请求当准备完成。
- [ ] 中途fork/重定向/READY失败、成员STOP/KILL及容量不足正确处理，sh前台和管道EOF无泄漏；已运行成员不走destroy。

- [ ] 普通 fork/exec 不经 init RPC，服务管理期间 init 仍可处理退出/控制，失败可补偿；fork 不从 _start 开始，exec 不改变 PID 或放宽 configure。

- [ ] serial/fs 故障按各自恢复协议处理，READY 依赖不造成无条件级联重启；挂断会话/旧 fd 不因新实例上线复活。
- [ ] 反复失败触发退避、次数及隔离额度限制，仍可诊断；可选服务故障不停止有效串口环境。

- [ ] 包条目/装载段越界、溢出、冲突、坏入口/权限及缺失程序拒绝；主机工具产物与两架构内核描述解释一致。
- [ ] 内核仅装载 init、init 装载 serial 等服务，BSS/最终权限正确；整包不默认可执行，可写进程数据不修改包内容。

- [ ] 重排准备/提交/取消/查询回复，复现 R1 超时和迟到回复；状态不明时不发起冲突 R2，旧补偿不修改新上下文。
- [ ] 覆盖参与服务退出、重复 commit/abort、操作槽耗尽及调用者退出；已提交结果不因超时改写为未执行，收尾记录有界且不提前复用。

- [ ] spawn 准备中注入信号修改 fd、cwd/umask 或组状态，验证取得一致版本或明确失败，不使用悬空指针/混合状态。
- [ ] 按上述方向验证信号后继续原 spawn 及文件动作进度，已完成 O_TRUNC 不再执行；发布前错误不留可运行孩子，发布后 handler 先 wait 仍保留原 PID/成功结局，输出故障及子启动127策略冻结后单独验证。
- [ ] 在接受/发布/回复各边界终止父进程，未发布子实例回滚，已发布实例正确托管；固定引用不错误冻结共享 File 偏移。
