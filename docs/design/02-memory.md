# 内存、地址空间与预算

[设计总览](00-overview.md) · [实现状态](../status.md) · [执行与验收](#执行与验收)

状态：2026-11-17已接普通内存/共享/封存及局部原生授权，现接COW承诺、费用结算和可信逻辑页分支组的双架构验证；Mem/PTE COW、写故障、fork/exec及DMA仍未接。实际边界见status与文末，未完成全系统、性能或CI验收。

## 内存与预算

已确定移除用户可见 Untyped/Retype；采用可回收物理页分配器和管理者配置的进程预算。
私有页计入所属进程，退出统一释放；共享内存单独记录映射引用，最后解除引用时回收。
设备页只能来自启动发现的授权资源，普通 RAM 不能伪造硬件权限。
不用通用内核堆：控制结构用有上限的专用池，页表和数据用页分配器。

已确定的 DMA 边界：用户态设备驱动可使用专用 DMA 缓冲和设备可访问地址；普通服务不获取 DMA 地址。
不提供通用的任意虚拟地址转物理地址接口。内核负责 DMA 页的分配、固定及安全回收条件，驱动负责设备请求与完成处理。
设备可访问地址不保证等于 CPU 物理地址，接口应允许未来接入 IOMMU。
无 IOMMU 时设备驱动属于可信组件；仅限制返回的地址不能阻止驱动向设备提交其他地址。
驱动退出或通信失败不代表 DMA 已停止，必须完成请求或确认设备安全停止/复位后才可回收相关页。
DMA缓冲按[设备同步契约](09-devices.md#维护粒度队列与发布顺序)隔离完整维护单元；同Mem内不同请求/CPU状态也不能共用正在交接的缓存行。所有别名属性兼容并服从同一所有权；已有清零脏行须经BEFORE交接，完成及AFTER前不复用接收缓冲。

### 计费与分配（已确定）

预算以页为单位，limit 是上限、used 是实际计费，不表示预留物理页；分配同时检查预算和实际可用量。
私有镜像/栈/数据及所属页表计入进程；共享数据页计入创建时指定出资方一次，各映射的页表分别计费。
DMA 页计入驱动预算；固定内核表使用有上限的系统池并单独统计。
共享区出资方与映射者可以不同，首版不自动转移出资方；出资方退出后尚未释放的共享/DMA 页保留账目直至最后安全释放。
该保留账目使用独立 Acct 池记录，生命周期不得依赖可复用的进程槽；不能因 slot 复用把旧费用计给新进程。
分配/映射事务先检查和取得资源，全部成功后发布；任一步失败回滚本次变化，账目与页占用回归原值。
新页映射前清零，普通页不要求物理连续；DMA 连续性、对齐及设备可寻址范围另行指定。
首版无交换及文件按需调页；fork 已纳入设计，私有内存复制策略按下文单独冻结，不再将“无写时复制”作为架构前提。大额分配/清理采用有界分段，未完成事务保持不可见，取消时仍可回滚。

### 放弃引用与物理回收（已确定）

free 放弃指定内存管理 Handle 持有的引用，成功后该 Handle 立即失效；不强制解除既有映射、不删除其他授权，也不承诺底层物理页已归还。
Mmap 独立持有 Mem 引用，已有映射不因创建者 free 而失效；最后管理/映射/在途使用引用及 DMA 固定条件解除后，才归还物理页并结清 Acct。
unmap 按目标地址空间与起始 VA 解除完整 Mmap，检查自身地址空间权限或管理者授权，不要求原 Mem 管理 Handle 仍存在；完成页表/TLB 更新后才释放映射引用。
revoke 撤销指定授权、禁止其新操作，不自动解除已有映射或释放物理页；terminate 启动进程退出清理，不表示设备 DMA 已停止。
普通进程放弃自身引用与管理员强制隔离是不同操作；完整停止由 init 协调，不能把 free 当作强制销毁其他进程映射的入口。

### 退出后的独立账目（已确定）

Acct 状态为 ACTIVE → CLOSING → FREE。创建进程时预先取得账目记录，创建失败回滚；账目池有独立编译容量上限，不随进程槽复用而重置。
ACTIVE 允许预算内新增支出；进程退出时原子关闭新支出并进入 CLOSING，已取得的共享页、DMA 页和在途预留继续计费。提交中的操作须按阶段完成既有收尾或回滚，不能借清理申请新业务资源。
Mem 和在途操作直接持有稳定 Acct 引用，释放时结清原账目，不通过旧 PID 查找当前进程槽；内部引用必须在账目回收前解除。
退出记录收取且进程自身清理满足条件后，进程槽可回收，不等待其他进程解除全部共享引用；这些引用只保留 Mem/Acct 等必要记录。
不自动转移出资方，其他进程继续使用旧共享页仍计入原 Acct；新增申请使用活跃账目，不能向 CLOSING 增加新支出。
仅当关联进程已解绑、实际占用/在途预留全部结清且内部引用归零，Acct 才能进入 FREE；页数为零本身不足以证明安全回收。
DMA 未确认停止时保留页、固定引用及账目；账目池耗尽时明确拒绝新建进程，不提前回收旧页或将费用归给新实例。

### 物理页分配器：伙伴系统（已确定）

采用伙伴系统统一管理普通页、页表、共享区及连续 DMA 页，不采用纯位图分配或独立预留 DMA 池方案。
以页为最小单位，每阶维护空闲块；分配拆分大块，释放时只合并同阶且确实空闲的伙伴。
多个 RAM 区间及保留区必须正确处理，不能跨物理空洞或保留范围合并；分配器元数据自身纳入系统保留与统计。
分配记录包含足以验证块起点、阶数和占用状态的元数据，拒绝重复释放、非块首地址释放和错误阶数释放。
多页连续申请向上取整为 2 的幂块，预算按实际占用页计费，释放按原块阶数结清，不隐藏内部碎片。
普通多页映射可由多个块组成，不强制整段物理连续；必须记录各块所有权，支持中途失败完整回滚。
DMA 分配同时满足连续长度、物理对齐和设备可寻址范围，越界或无法满足时失败，不退化为非法地址。
各阶拆分/合并的复杂度及范围受配置限制；DMA 受约束搜索须有界，不因使用伙伴系统宣称不存在碎片或恒定时间。
首轮实现即包含以上约束及测试；具体元数据布局、最大阶和函数参数在实现前确定，不将必要 DMA 约束推迟。

伙伴分配器采用每页元数据与每阶双向空闲链表。元数据区分保留页、空闲块首、已分配块首和块内部，块首保存阶数。
链表用页索引，已知空闲伙伴可直接摘链，不扫描整个同阶链表；初始化将可用区间拆成物理对齐的合法块。
分配从合适阶取得符合地址/对齐要求的块并拆分，释放验证后逐阶合并；受约束搜索不承诺 O(1)。
命名遵循 style.md：Page 为页元数据，Pgblk 为块首/阶数描述，Pglim 为地址范围及对齐约束。
内部接口为 `pgalloc(u32 order, const Pglim *lim, Pgblk *out)` 和 `pgfree(Pgblk blk)`，不使用 page_alloc/PageLimits 等命名。
普通单页使用零阶及默认限制；返回物理块仅供内核使用，不作为用户可任意取得物理地址的接口。
伙伴层负责物理块状态，上层负责预算、映射及共享引用；调用失败归还本次取得的块，不重复维护矛盾的释放状态。

### 多进程总预算（已冻结）

普通 fork 不能复制出新增系统额度。方案在独立 Acct 之上加入 init 配置的平坦进程集合总限额，孩子留在原集合；实际页、严格 COW 预留及退出后滞留费用均纳入总计费，集合生命周期独立于父进程。具体约束、例子与冻结字段见 [普通创建权限与总预算](03-process.md#普通创建权限与总预算已冻结)。

### 内存管理记录（已确定）

Acct 保存预算上限、实际占用和进程存活关联，独立于可复用进程槽；其出资内存全部结清后才可回收账目。
Mem 保存内存物理块集合、出资 Acct 及管理/映射/使用引用；Mmap 保存目标地址空间、VA、长度及权限的一次映射。
解除 Mmap 不必释放 Mem，删除某资源句柄不自动解除其他映射；仅所有相关引用及安全固定条件解除后归还伙伴块。
页表页由地址空间管理并计费，不为每个页表引入用户可见 Mem。
DMA 区在驱动使用期间固定，驱动退出不自动解除固定；内核引用计数不证明设备停止，须可信管理者确认停止/复位后解除。
首版共享区直接创建为共享内存，不提供任意私有页转共享接口；不改变栈/镜像等私有内存的隐含所有权。
三类记录使用有编译配置上限的专用池，不引入通用方法表、派生关系或逐类型系统调用，池耗尽返回错误。
测试包括出资方退出后账目保留、进程槽复用不串账、最后引用结清、多个映射解除和 DMA 未停止禁止释放。

### map/unmap（已确定）

映射指定 Mem、区域内偏移、目标 VA、长度及权限；偏移/地址/长度须页对齐，长度非零，并检查范围及整数溢出。
授权范围与物理分配块大小分开：伙伴取整产生的额外页不能因此自动获得用户映射权限。
目标已有映射则冲突，不覆盖；请求权限超出授权则拒绝，不静默降级。失败撤销本次新增内容，不改变原有映射。
unmap 按起始 VA 定位并解除整条 Mmap，首版不支持中间挖洞/隐式拆分；不同生命周期从创建时分为不同映射。
代码 Mem 使用 LOADING→SEALED 单向状态：加载可写但不可执行，移除所有用户写别名、完成缓存同步并封存后才可 RX。
SEALED 禁止再次授予用户写映射，不允许与 DMA 区混用；普通数据/共享区不可执行。同物理页设备缓存属性保持一致。
设备缓存属性来自授权资源，不能伪装为普通内存。
加载器写入可执行内容后，HAL 完成架构要求的指令/数据缓存同步；不能只改变映射权限便直接执行。
unmap 完成顺序为撤销 PTE、必要屏障和 TLB 失效、释放映射引用和可回收页表页，之后返回成功。
CPU 映射解除不证明 DMA 停止，物理块仍须满足其他引用和固定条件才可释放。

### alloc 调用契约（已确定）

alloc 使用绑定出资 Acct、预算和允许种类的分配授权，接收非零字节长度和用途/约束；不允许以任意 PID 指定出资者。复杂约束经有界定长结构一次快照，具体布局在 ABI 中统一。
用途包括 DATA、共享内存、待加载代码与 DMA 等已授权种类；种类字段不授予权限，不允许普通进程自行取得 DMA 或执行权。设备 MMIO 不由普通 RAM alloc 伪造。
按页向上取整并检查溢出，按实际取得的伙伴块页数计费；连续/对齐/地址范围按 DMA 授权及约束检查，不能退化到越权物理范围。
成功在独立结果字段返回本地 Mem 管理 Handle，状态字段为 0；失败返回负错误码，不发布 Handle，归还本次页/记录/预留并撤销扣账。页面在用户可见前完成清零。
alloc 不选择 VA、不隐式 map；libsys 的用户地址管理与 map 单独负责映射。malloc 在 libc 中批量取得并切分用户内存，不为每个小块执行 alloc/map；C free(pointer) 不等同原生放弃 Mem 引用。

#### 示例：普通进程取得 16 KiB

进程持有 SELF_ALLOC 对应授权和自身地址空间授权，先 alloc 16 KiB DATA，得到 Mem，再 map 到选定合法空闲 VA。map 失败时由运行库放弃这次不再需要的 Mem，不能把两个独立调用当作内核自动回滚的一次事务。
Mem 未映射时仍占预算；撤销分配授权禁止新分配，不自动释放已取得的 Mem。

### map 调用契约（已确定）

逻辑参数为 map(space, mem, offset, address, length, prot)。space 与 mem 都是调用者本地资源表中的授权 Handle，分别限制目标地址空间和源 Mem 的范围/操作；不以 space=0 暗示自身。
自身与跨进程映射使用同一机制，普通进程只获指向自身的受限地址空间授权，init 只凭未发布目标CONSTRUCT配置其地址空间，首版不提供任意存活他主体SPACE入口。offset 为相对 Mem 的字节偏移，不是相对授权窗口重新起算；超出授权子范围拒绝。
实际 ABI 可一次复制定长参数结构；目标 VA 由调用者明确指定，成功返回状态 0，失败返回负错误码并完整回滚，不返回映射 Handle 或额外地址。映射以地址空间与起始 VA 定位。
页表及 Mmap 记录计入目标资源预算；运行中目标的修改沿既定 VM_BUSY/有界 Op 协议完成，目标不在半更新页表上运行。
原生 map 不是 POSIX mmap；未来 mmap 的地址选择可由 libsys 管理，本阶段不因此承诺文件映射/部分 unmap 等尚未纳入的语义。

#### 示例：授权窗口与返回值

Mem 有 16 页，B 的 mem 授权仅覆盖第 4～7 页且只读。B 指定 offset=4页、length=4页、prot=READ，并选择合法空闲目标 VA，可以成功返回 0；offset=0 或申请写权限均失败。
成功后使用传入的目标 VA；失败不留下本次部分映射，已有映射不变。相同范围的解除映射不需要原 Mem Handle 仍存活。

### unmap 调用契约（已确定）

逻辑参数为 unmap(space, address)，space 为调用者持有的目标地址空间授权，address 必须精确匹配完整 Mmap 的起始 VA。不接收长度、不隐式拆分，中间地址或不存在的映射失败。
返回状态 0 或负错误码；先验证授权/映射并取得所需稳定引用，再按 VM_BUSY/有界 Op 撤销 PTE、完成屏障/TLB 失效，最后释放映射及可回收页表引用，之后才能报告成功。
不要求原 Mem 管理 Handle 存活；成功只解除该 CPU 映射，其他引用或 DMA 固定仍有效。与其他映射事务/退出交错依既定状态拒绝或安全串行，不把失败解释为可忽略的重复解除。
解除自身正在执行的代码/栈不保证用户态返回可继续执行；libsys 避免此用法，管理者撤除目标活动区域可能导致随后用户异常，内核仍须安全完成而不在用户页上保存自身关键执行状态。

#### 示例：只接受映射起点

一次 map 在 0x400000 建立 4 页 Mmap，则 unmap(space, 0x400000) 解除完整记录。传入位于其中的下一页地址不会解除部分记录，返回错误且原映射保持完整。

### 虚拟地址布局与用户访问（已确定）

用户空间与高地址内核空间分离，不沿用低 4 GiB 长期恒等映射；具体地址/上限由架构布局定义，公共核心不写硬件地址规则。
用户范围覆盖程序、私有/共享数据、Boot 和栈；空地址附近及用户栈/信号栈/内核栈边界保留未映射 guard 区。
内核代码 RX、只读数据 R、数据/栈 RW；RAM 直接映射仅覆盖实际 RAM，不混入 MMIO 或物理空洞，直接映射不成为用户授权。
启动临时恒等映射完成地址切换后解除，不长期遗留额外别名；代码封存的受信内核直接映射例外遵循[全局设计与冻结条件](00-overview.md)，不暴露用户写接口。
Boot/ABI报告01规定的两架构共同用户地址窗口；底层页表编码及内核地址转换仍由各HAL实现，不再有另一套用户地址数字。
用户复制统一检查地址/长度溢出、映射/权限及普通内存属性，拒绝 MMIO 参数缓冲；不能直接解引用未检查用户指针。
长 Op 复制参数并固定必要引用，不保存可被后续修改的用户输入指针作为权威状态。

- [ ] 两架构实际验证用户访问内核、写 RX、执行 RW、栈 guard、空指针和跨边界用户复制，错误不破坏其他进程或内核。
- [ ] 检查临时映射已解除、RAM 空洞/MMIO 属性正确及非法范围不能绕过授权。

内存长事务使用[全局设计与冻结条件](00-overview.md)的 Op 记录与有界续执行。内部C成员布局受03槽宽度上限约束，配置默认值和错误数字以01/06为准，不改变上述协议。不得同时维护新旧两套用户内存模型。

### 物理别名、代码封存与 DMA 属性

- Mem内容状态LOADING/DATA/SHARED/SEALED保留至最终回收，managers=0独立表示退役并禁止新管理/映射引用；LOADING可由授权加载者写但不能执行，SEALED可按授权RX，不可用户写且不能重新转为可写。
- seal 是明确管理 syscall，使用 Op 检查所有用户写别名与在途写引用，存在则拒绝，不自动拆除映射；完成 HAL 缓存同步后原子封存。存在外部不可撤销写者则失败。
- Mem 元数据记录写映射/执行映射状态，跨进程也检查；SEALED 不授予 DMA 固定，不允许通过普通写入辅助接口修改。
- 内核受信实现可能有特权直接映射，但不得通过用户 syscall 暴露写入 SEALED 的路径；不宣称防御恶意内核或无 IOMMU 的恶意设备驱动。
- 设备资源携带不可变的物理范围/缓存属性，所有别名一致；DMA 内存另标一致性属性并执行设备要求的缓存维护。

验收：父 RW/子 RX 别名、seal 时写引用、封存后重新 grant/map 写、设备缓存别名、DMA/执行混用均拒绝；正常 ELF 不依赖常驻 RWX。

### seal 调用契约（已确定）

seal(mem) 校验调用者的本地 Mem Handle 及专门封存权限，普通写权限不足以封存；只允许待加载代码，普通 DATA/共享数据或 DMA 内存不能由此改成代码。
通过有界 Op 进入内部封存过渡状态，阻止新写映射/写入引用、冲突授权及管理操作；已有用户可写映射或未结束写入操作使封存失败，解除过渡并保留 LOADING，不自动拆映射。
DMA 固定或其他无法确认停止的写入者使封存失败；检查通过后执行所需缓存同步，最后提交 SEALED，才允许执行映射。失败不发布半封存状态，退出/取消按 Op 规则回滚或完成已提交状态。
有效权限是授权与 Mem 状态允许操作的交集。SEALED 不可逆，旧授权写位也不能恢复写入、转授有效写权或重新映射 RW；不要求逐个改写所有授权表项，但每个访问/授权入口必须检查资源状态。
已 SEALED 的 Mem 在重新校验身份与封存权限后重复 seal 返回成功，不重新开放修改窗口；成功状态返回 0，失败为负错误码。

#### 示例：父进程遗漏 RW 别名

加载器 alloc 待加载代码，map 为 RW，写入 ELF 并清零 BSS。若父进程还留有 RW 映射，seal 失败且不自动解除该映射；加载器显式 unmap 所有用户写别名后再次 seal，成功后才能给目标建立 RX 映射并 start。
封存成功后，用旧 Mem 授权请求 RW 或向另一进程转授写权限均拒绝，不能通过另一地址空间绕过 W^X。

### 配额、预付与资源耗尽

- 创建进程一次预付请求槽、信号上下文/帧预算、退出记录、Op、基本授权/映射记录；不足则创建失败回滚，不在退出/信号时申请关键元数据。
- 服务启动前预付defer执行表、控制收尾记录和共享槽数量；结果只在原Rq/原槽，不预付第二张通用I/O结果表；DRAINING/未确认结果继续计费且占配额，不能通过取消绕过占用限制。
- 普通伙伴页分配不得消耗配置的系统恢复低水位；恢复使用同一伙伴分配器的受权保留额度，不另建独立 DMA 池。
- 内核终止/解除等待/回收/退出确认不需要新的分配；init 的事件循环缓冲及元数据常驻预付。
- 恢复预算包含所需页、进程/请求/映射/账目记录，无法重建时保持明确断开并释放可释放部分，不无限尝试。
- 未停止的设备 DMA 资源进入受限保留状态，达到上限后停止该设备的新分配/请求并报告；不为恢复而提前回收，不承诺硬件失联仍能无限重启。

验收：逐池耗尽与全页耗尽，KILL、退出结果收取、解除引用仍完成；恢复成功或明确失败，未归还资源有上限且可诊断。

### fork 地址空间复制（已冻结）

fork 后私有可写内存逻辑独立，显式共享内存继续共享；SEALED 代码/不可变只读数据可共享物理 backing，子进程有独立页表和映射记录。不能将所有 Mem 简单加引用当作 fork。
首版已选定带严格预留的页级COW：私有逻辑可写页的父子 PTE 暂时只读并带内部 COW 标记，写故障分离 backing；真正只读/SEALED 写入仍是权限故障，不能因 COW 自动变可写。发布前完成父 PTE/TLB 同步，子进程不可见半更新状态。
__sys_copy 等内核代用户写入也必须遵循逻辑写权限/COW 分离，不能绕过 COW 改到父子共享 backing。一个进程内的私有别名保持相互一致，父子各有逻辑 Mem 视图，私有 Mem 管理授权须对应子视图而非继续指向父可写对象。
DMA/MMIO、外部写者和运行库 staging 不能盲目纳入普通私有 COW：DMA 绕过 CPU 写保护，协议槽有独立所有权。必须先分类继承/排除/重建规则，无法保持语义时在发布前拒绝，不暗中跨父子共享私有数据。
COW 的页级引用、原伙伴块释放及 Acct 出资规则是冻结前置：不能把多页 Pgblk 中任意一页直接 pgfree；不能给共享 backing 重复计物理占用，也不能把父页费用串到子进程复用槽。
不得只写“COW 更快”便视为设计完成，未实现/验证前不能宣称 fork 后写入已获保证。

#### 示例：私有变量与共享区

父进程 x=1，fork 后孩子写 x=2，父仍看到1；显式共享区 s 则按原共享语义互相可见。若使用 COW，分离的是私有逻辑页，不能让 __sys_copy 写入孩子 x 时改掉父 x，也不能把 shared 当作 PRIVATE 分离。

### COW 计费与严格预留（已确定）

本节确定以严格预留承诺既有私有页分离的方案，尚未实现。普通共享区/DMA出资不自动转移的规则不变；只有受控 fork 私有页共享组采用下述专用结算。
每个私有逻辑页有分支视图，多个 Mmap 别名不重复计分支。同一物理 backing 在共享组中只由一个分支 Acct 实际出资，其他分支各持一页 COW 预留；其预算承诺为 used+cow_reserved+其他预留，不超过 limit。
fork 每新增一个私有可分离分支，子账目取得一页额度，系统同时保留一页可兑现物理容量。预留不要求立即分配/复制页面，但所有普通页/页表/DMA分配都不得消耗全局已承诺 COW 容量；系统恢复低水位另计，不重复许诺同一容量。
fork 前预付子页表/视图/共享链接及故障收尾元数据，复制分离时不临时申请关键元数据；只保证已纳入承诺的继承页，不保证后续 malloc、新映射或硬件错误永远成功。物理承诺/元数据不足在孩子发布前失败，回滚父 PTE/引用/账目并完成 TLB 同步。

#### 写入与出资结算

非实际出资分支写入时，用自己的预留取得新零阶页，复制后原子切换其逻辑页及全部相关别名；自身 reserved→used，原 backing/出资者不变。
实际出资分支先写时，选择一个仍引用旧 backing 的预留分支，将旧页实际费用交给该分支（其 reserved→used），原出资者在同一事务内将自己的实际费用移到新复制页。两者 used+reserved 均不增加，不要求原出资者再有一份闲置预算。
这不是任意账目间赠送内存，而是 fork 时已接受、等额预留的私有分离结算；共享组记录稳定 Acct 引用，不按可复用进程槽查询出资者。退出阶段只兑现/撤销既有承诺，不增加新业务额度。
分支退出/解除最后逻辑引用时，若只是预留者则释放其预留；若实际出资者离开且仍有其他分支，则将旧费用转给其中一个已有预留者，释放相应全局预留。最后分支消失才回收物理页；仅剩一个分支时无需复制即可恢复其合法写权限。
所有费用转移、分支摘挂、PTE切换/失效通过既定 VM_BUSY/Op 的短提交点完成，旧数据在新页完整复制前保持稳定。中途失败不能既释放预留又保留两个实际页，也不能恢复出资者写权限而遗漏其他分支。

#### 示例：父先写与子先写

初始父 A 独占一页，A used=1。fork B 后：共享一个物理页，A used=1，B reserved=1，系统还保留一页未兑现容量。
若 B 先写：B 的 reserved变used，新页归B，旧页归A，双方各used=1。
若 A 先写：旧页费用转给B并消耗B预留，新页归A，仍双方各used=1；不能先要求A used变2而让预算恰好为1的父进程写入失败。
若 A 未写就退出：旧页转给B，B reserved变used，取消不再需要的全局额外页承诺；A账目不因该私有COW页继续悬挂。显式共享/DMA不采用这条转移规则。
再次 fork 按同一共享组新增预留，分离/退出可任意交错；每组满足“实际物理页1份+预留分支数=逻辑分支数”，不能按 PTE 别名数量重复预留。

#### 页粒度及代写

可fork私有 backing 从伙伴分配器取得零阶页，避免在COW中拆开原多页块再非法逐页释放；连续DMA/明确共享块仍按原Pgblk规则，SEALED只读共享另保留稳定引用。不同时维护两套矛盾释放账目。
用户写故障与 __sys_copy 等代写共用逻辑写检查及分离，真正只读/SEALED不走COW。一个分支的所有别名指向其当前页，不能只改故障PTE；Mem管理授权也对应该分支逻辑视图。
严格预留牺牲可承诺的进程数，换取既有私有页分离不依赖事后碰运气取得内存；fork可能在实际页尚未耗尽时因承诺不足失败。不引入超卖/事后OOM的第二套默认策略。

### exec 常规与峰值预算（已确定方向）

Acct 保持原身份，常规 limit 与受限 exec_limit 分开；后者仅允许当前镜像替换事务准备的新镜像及确定可回收旧镜像短暂占用，不向普通 malloc/alloc 开放，也不通过换新Acct逃避旧费用。
同一进程一次活跃替换事务。检查旧/新数据、COW实际占用与预留、页表/Boot/新通道及其他预付记录；峰值额度不等于已预留物理页，实际容量不足提交前回滚。
提交前核对新镜像加无法随替换释放的旧共享/请求/DMA资源符合常规limit；外部访问者尚持有的资源不能无限挂在临时exec额度中。只有内部有界Op即可确定释放的旧资源可短暂保留峰值，回收后归还额度，不阻塞于设备/服务外部完成。
普通新分配不得消费替换专用额度，旧资源未实际回收仍如实计费；再次exec须协调已有替换回收，不叠加无限峰值。具体预算字段/分类/提交检查在ABI与资源账目中冻结。

#### 示例：100页常规、160页峰值

旧镜像60页，新镜像70页，准备期130页可容纳。若旧60页中40页可由内部回收、20页仍被外部引用，新稳态90页可提交，内部旧页分批归还；若旧保留40页则稳态110页超常规，即使峰值仍够也在提交前失败。

### 集合总额与并行 exec 峰值（已冻结）

方案为每个平坦进程集合配置常规上限 limit 和共享峰值上限 exec_limit，后者不得小于前者。峰值是集合的总占用上限，不是每进程额外可领的一笔额度；各 Acct 自己的常规/峰值检查仍同时执行，子进程不能自行新建集合、提升上限或转移旧费用。

集合总占用包含所有相关 Acct 的实际费用、严格 COW 预留、未发布新镜像及尚未安全回收的旧资源；共享物理页按既有单出资规则计一次，COW 承诺按既有预留计费。它是物理页及承诺的账目，不能把多个映射重复算页，也不能把软件结果记录当用户页混算；专用记录池和实例数仍单独受限。

准入规则方案采用两个阈值，不另建逐进程峰值借贷表：普通新增费用要求增加后的集合总额不超过 limit；仅本次受权 exec 准备/确定内部旧镜像回收允许达到 exec_limit。所有类别仍核对真实可用资源和已经兑现的全局物理承诺。只转换既有 COW reserved→used 而未增加费用的写分离继续兑现，不能因当前处于 exec 峰值就拒绝已经承诺的分离。

因此，集合在峰值期间其他进程的普通新分配可能暂时失败，即使它自己的 Acct 尚有空间；不承诺普通分配有独立保底。这个取舍换取直接的总量约束，不通过免计新镜像来暗中让普通分配占用峰值。控制/退出清理依靠事先预付记录与资源，不在峰值期间临时申请必需元数据。若后续确需普通分配保底，须明确另作预算策略，不能在本规则里隐含超额。

exec 提交必须同时检查本 Acct 和集合稳态：当前总额减去本次切换后确定可由内部有界回收的旧费用，仍须不超过对应常规 limit；外部服务、共享、请求、DMA 持有的旧费用不能扣掉。其他进程正在准备的镜像仍计入，不预支它未来可能回收的页，因此并行提交可能保守拒绝；不得把多个事务各自预测的回收额重复承诺。检查和提交对同一集合账目原子排序，不持锁等待服务。

提交后内部旧页实际释放前仍计总额，全部并行准备/回收合计不超过集合 exec_limit；再次 exec 不获得新的一份峰值。准备失败/取消只返还真实解除的引用和预留，外部仍持有的资源继续计费。每进程一次活跃准备不等于只允许集合一个 exec；可并行到共享总额或固定记录池先耗尽为止。

#### 示例：共享峰值不随并行进程数放大

示意集合 limit=256 页、exec_limit=384 页，当前总额220页。A 准备新镜像增加80页后总额300，若自身上限和物理容量也满足则可继续；B 此时再增加100页将达400，必须拒绝或撤销该次新增，不能因B有自己的 exec_limit就接受。A 若切换后确定回收旧90页，则集合稳态210页可提交；实际释放前仍如实记300页，此期间普通新增分配不能使用峰值空间。示例省略的页表、Boot等真实开销在实现中必须纳入。

## 首版账目和内存参数（已冻结）

平坦集合名为Set，仅启动清单建立、init POLICY可调整；不提供子进程迁移或递归预算。Set字段为limit、exec_limit、charged、instances/max_instances、refs；Acct字段见03。默认普通实例memlimit=4096页、exec_limit=6144页，普通应用集合limit=32768页、exec_limit=40960页、max_instances=48；系统服务由启动清单划分其余集合/资源，不与恢复低水位重复出资。上限不是预留页承诺，实际RAM/元数据/池同时准入。

所有页账用u64，扣账前检查加法/舍入溢出。charged=sum(used+reserved)，跨Acct共享页只在实际出资者计一次；COW按逻辑分支计，不按PTE别名计。普通新增须同时满足Acct.limit与Set.limit；exec准备新增可用对应exec_limit。COW兑现只转换reserved到used，不新增charged，不因正在峰值而拒绝已承诺分离。出资者先写时，从已有预留分支按稳定最小Acct索引选择旧页新出资者，原子转移旧页费用并消耗该分支预留，原出资者只支付新页；不会临时双扣同一分支。

execcommit前计算当前charged减去本次确定可立即释放的内部旧页/预留；不计外部Mmap、Rq、共享MEM及DMA预计释放。提交后的净额必须回到常规limit；不满足返回LIMIT并保留旧镜像。不能借“以后会收尾”长期占峰值；同时exec共享同一峰值。所有准备失败按原Acct释放，旧source进入CLOSING后只允许兑现已承诺收尾，不新增业务费用。

伙伴最大阶16（256 MiB），分RAM区初始化；Page记录state/order/head、空闲prev/next、owner，块内页不重复挂链。Pglim为minpa、maxpa_exclusive、align三个u64；普通零阶不受设备窗口额外限制，受约束DMA搜索每32候选检查调度/取消，搜尽合法空闲链明确NOMEM。新暴露页清零，页表/内核栈计实际页，固定表不逐槽重复计RAM。

alloc输入Allocarg=48字节：bytes@0、kind@8、align@16、minaddr@24、maxaddr@32、reserved@40，均u64。kind DATA=1、SHARED=2、CODE=3、DMA=4；普通前三种align/minaddr/maxaddr要求0，DMA同时受授权设备域约束。map输入Maparg=48：mem@0、offset@8、address@16、length@24、prot@32、reserved@40；space独立寄存器输入。READ=1、WRITE=2、EXEC=4；未知位和WRITE|EXEC拒绝；Mmap总长页对齐非零，offset相对Mem本体，设备缓存属性不可由prot修改。

全空间VM_BUSY仅由同一内部事务持有，其他修改返回BUSY；目标暂停用户执行，但IRQ/无关进程继续。长map/clone/seal预取必要元数据，逐批构建不可见状态，最后提交；unmap先撤入口与TLB后放引用，取消不能恢复已提交解除。内核后台清理每次最多32项，记录独立于原C栈。用户copy最多64 KiB，先检查全部页、别名重叠、权限/普通内存并取得必要COW分离承诺再复制；COPY不新增用户固定令牌，也不允许MMIO/SEALED代写。

例子：集合charged=32760页，普通alloc16页被LIMIT拒绝；exec新增可在共享峰值准入，但commit若不能确定释放到32768以内则仍失败；其他进程已承诺的COW分离继续兑现。KILL某进程后DMA仍在访问8页，这8页继续计原Acct/Set，不因Proc槽空闲而消失。

Page采用state/order/head/prev/next/region六个u32及owner一个u64，共32字节。状态区分保留页、空闲块首、已分配块首和块内部；只有有效块首的head/order具有权威性，内部不维护逐页可释放引用。初始化遍历全元数据并排除保留区；分配/释放只更新拆分/合并涉及的块首，不为大块逐页重写归属。owner当前保留为0，尚无进程/Acct身份；它不构成授权或DMA固定证明。

Pgblk为pa(u64)、order(u32)、reserved(u32，必须0)；Pglim为三个u64，min包含、max不包含，align为非零2的幂，实际块同时满足其阶数自然对齐。NULL限制表示完整物理地址范围。调用者已经按真实占用阶数请求；将字节长度取整、扣预算及限制授权窗口仍由未来Mem层实现。pgfree只接受真实已分配块首和原阶数，重复、块内部、未对齐、非RAM、错误阶数及非零reserved均失败，不修改池。Pgblk是内核内部拥有者记录，不是带代次的用户Handle，调用者仍须维护唯一释放责任。

pginit先只读核对RAM/usable/保留关系、对齐、容量和低水位，再发布元数据；有未归还块时拒绝重置。元数据数组由启动层预留并独占，调用者保证存储覆盖capacity个Page。普通分配保持256页恢复低水位，恢复特权入口及全局COW承诺扣留尚未接入。约束搜索至多遍历有限空闲链，尚无调度/取消；未来接入调度时必须落实每32候选的检查点，不能据当前单核中断关闭启动循环声称运行期有界延迟已满足。

正常镜像只初始化并报告META/PAGES，不自动运行压力测试。独立CASE=pages镜像对可用各阶块每页首尾进行写入/读回，检查错误阶数和重复释放、限定地址/对齐选择、零阶耗尽至保护低水位、所有块无别名及全部归还后的阶链恢复；测试链存放在已分配页自身，不引入大型测试常驻表。裸pgalloc不清零、不映射；本轮没有用户可见页，上层映射前清零的要求仍待实现，不能把诊断写回零当作通用清零保证。

#### 阶段04第三个切片：稳定账目与普通预算（2026-11-15）

- [x] 固定16个Set/256个Acct池，普通支出同时检查单账目和集合常规上限，used/reserved均计入charged；所有加法在上限差值内进行，拒绝零申请与溢出。
- [x] Acct ACTIVE到CLOSING后禁止新增预留，已有预留仍可转实际占用或撤销；只有进程绑定、所有引用和实际/预留费用全部归零后才回收槽。
- [x] 普通acctalloc把实际2幂块页数先预留、取得物理块并标记归属，再转used；预算、约束或物理不足时回滚本次引用/预留/页，失败不改输出。acctfree先验证块与账目归属，安全归还后才结清费用/引用。

kernel/acct.c的Set实际48字节、Acct56字节，均受64字节上限断言；池共15104字节，已在内核BSS整体保留内，不对每个活槽再虚扣物理页。Set保存常规/峰值上限、charged、实例上限/数量及引用，Acct保存集合索引、常规/峰值、used/reserved、state、refs和bound。峰值字段仅储存既定配置；当前没有exec准入通道，普通支出不能借用它。所有状态是内部记录，不新增用户可见Handle或管理权限。

Acctid/Setid为内部索引加非回绕代次，输入保留字段为0。首次分配代次1，回收后再次分配递增；上限2^56-1的槽不再复用。Acct存Set索引期间持有Set引用，Set不能在旧Acct或Life名额仍存在时复用。create给Acct一份进程/构造引用，hold/drop供独立资源使用，unbind只在CLOSING解除绑定并交出原引用；零页但仍有引用不能腾槽。原Acct释放后旧代次不匹配新账目，不通过PID或Proc槽查找当前出资者。

### 构造期分配授权与出资（2026-11-15已确认）

用户已确认准备期ALLOC方案。CONSTRUCT/EXEC_VIEW权限新增ALLOC=0x10，原MAP=0x01、CONFIG=0x02、PUBLISH=0x04、ABORT=0x08不变。alloc的authority可为自身ALLOC或本次有效构造/执行准备的ALLOC授权；仍不接受任意PID出资。后者从目标Acct取得DATA/CODE，结果是在创建者本地表中的临时加载MEM权，不是孩子表里的SELF_ALLOC整数。

临时加载权绑定本次准备及创建者完整PID/image、资源表绑定代次；只允许本次目标和创建者的临时映射，不得转授到第三个空间、带入fork/exec或变成普通跨Acct DATA共享。子目标可按CONFIG安装永久MEM引用，权限/子窗口只能缩小；私有永久引用可设置FORK，临时加载权自身始终不可继承。子表安装仍要验证本次目标CONFIG，不能以ALLOC、MAP或源GRANT替代目标安装权。

每条创建者临时Mmap独立持有Mem和Prep引用，保存完整准备代次并计入temporary计数。目标映射及其页表按原规则由目标出资，创建者临时页表由创建者出资，物理数据页只在目标Acct扣一次。普通map的同Acct检查保持，只有经准备验证的临时映射可跨这两个Acct；不能把这个例外推广为无条件跨Acct map。

### SHARED分配、授权与独立出资接续（2026-11-16）

SHARED只有R/RW/GRANT授权，没有EXEC或SEAL；Mem自身的可映射/封存校验与Local安装再次核对，不能凭伪造rights让共享页执行或封存。固定CONTROL INSTALL或本次准备CONFIG仍是grant目标准入，源另需GRANT并检查减权和页对齐子窗口，复制失败不增引用。无GRANT的接收者只能使用本地授权，不能继续转授；显式FORK/EXEC继承标记允许用于SHARED，但仅是资源策略，真实fork/exec仍待接。

跨Acct/跨Set共享按创建时Acct付物理页费用一次，各接收者仅为自己成功创建的页表付费。每个Local独立持管理引用，每个Mmap独立持映射引用；撤销或free最后Local不解除已经提交的映射，不把它当DMA停止或全体进程访问已经结束。无管理引用时Mem进入既有RETIRING，不能再装授权/新映射，现有RW映射仍按原权限访问；最后unmap才释放物理块并结清原Acct。映射/授权从不迁移出资，创建者退出/被收取并不使共享页转到接收者账目。

已有合法接收Local且原Acct已CLOSING时，仍可把这份已存在共享对象映射到活接收者；新的接收方页表只计其自身Acct，原CLOSING Acct不新增物理支出。原创建者的运行资源和父结果释放后可仅剩旧共享费用，旧Acct保持无bound的CLOSING直到最后引用消失。资源身份/Acct代次不能随原Proc槽复用改绑。

### 全局 COW 物理容量承诺基础（2026-11-17）

伙伴分配器新增内部Pgcredit及pgreserve/pgcancel/pgredeem，预留数量与恢复低水位独立；pgreserved查询当前总承诺，不改变既有Pgstat字段或用户ABI。每份Pgcredit为8字节，归未来COW分支/事务唯一拥有，必须零初始化、不复制活记录，在所属分支/准备槽复用前兑现或撤销。它是受信内核内部拥有记录，与Acctblk相同地依赖调用者生命周期，不是防伪用户Handle；持有任意正整数不构成用户分配权。当前没有生产fork创建这些记录。

### COW 额度与稳定账目结算基础（2026-11-17）

### 原出资者替换页的结算基础（2026-11-17）

### 私有 DATA Mem 克隆接入（2026-11-17）

新增可信内部memclone(source, target_acct, out)，将整份普通私有DATA Mem按逻辑页克隆为目标Acct的独立Mem视图，未增加syscall或用户发权入口。原始页首次进入共享组时接管原Acctblk；再次克隆已共享视图则沿原Cowid增加分支。目标必须活Acct/同Set，源不能有可写映射或忙操作；只允许DATA/RAM，LOADING/SEALED/SHARED/MMIO与同Acct目标拒绝。已有只读Mmap可保留源引用，managers=0的退役源也能由可信持引用者参与准备，不复活源管理权。

memwrite对涉及的逻辑页先全范围检查，再处理COW分离，全部分离完成后才复制输入字节；未映射分支可使用已预付承诺复制成独占页。当前Space尚无PTE COW权限及全部别名替换，因此若某涉及页仍共享且Mem存在Mmap/Op引用，memwrite在任何修改前返回BUSY，防止页地址改变后旧只读PTE滞留。仅剩单分支时pa不变，已有只读别名仍可观察受权内核写。真正只读/SEALED继续拒绝写入，原生__sys_copy尚未接逻辑COW fault，不能绕过该分阶段边界。

映射准入同时收口：共享中的私有逻辑页不能新增RW映射；源已有RW映射时clone拒绝。只读映射正常建立，全部相关页独占后才可RW。该检查是当前内核阶段的强制限制，不是最终fork语义；后续Space事务必须保护原RW父PTE、维护逻辑写权限/COW标记并提交全部别名，届时才能允许已保护的逻辑可写映射参加fork。不能以先克隆再依赖用户不写的方式跳过保护。

例：父Mem两页P0/P1，两个R别名存活。clone到孩子后，孩子预留2页。孩子无映射地write P0后仅该页分离、P1继续共享；写P1后两页独占，可以为孩子建立RW映射，孩子修改不影响父两个R别名。父管理句柄可提前free，最后两个别名unmap才销毁父Mem/逻辑分支；若父是实际出资者则按组规则转交费用，而不是错误地free孩子仍用的物理页。若另一个两页孩子只获1页额度，第二页准备失败时第一份分支及预留回滚，旧父及已有孩子数据/账目不变。

### 已有页表叶的原位替换（2026-11-17）

HAL新增hal_vm_replace(vs, va, expected_hpte, new_pa, new_prot)，只替换一份已存在的4KiB叶，不创建/销毁中间表或分配物理页。调用者持有已初始化且存续的root、底层页及全部相关别名责任，并串行禁止目标VA在break期间使用；目标不能覆盖正在执行的代码、栈或walker/页表访问路径。它是可信机制，不是新的用户mprotect或COW权限入口。

先完整检查canonical/对齐/40位PA边界、READ及W^X、root用户/内核范围、expected present/权限/属性。expected来自lookup并须重编码后逐位等于当前原始叶，防止旧快照或未识别软件/保留位被覆盖；失败不写表/不失效。新叶继承原普通/Device属性和root规定的USER位，调用者不能在new_prot指定USER、改变内存类型或令Device可执行。同叶no-op不失效。全部编码在break之前计算，避免目标恰含编码器会读取的只读常量时在失效期间访问它。

成功顺序为旧叶清0→现有hal_vm_commit→写新叶→hal_vm_commit，两个阶段之间没有可失败的分配或回调式外部业务；表页数/费用不变。ARM继续使用dsb ishst/tlbi vmalle1/dsb ish/isb，RV继续使用sfence.vma zero,zero；当前UP/无ASID、ARM缓存关闭配置下保守全局失效。参照[TF-A v2.12.0 xlat工具的BBM说明](https://github.com/ARM-software/arm-trusted-firmware/blob/v2.12.0/lib/xlat_tables_v2/xlat_tables_utils.c)及[RISC-V Privileged 20240411](https://docs.riscv.org/reference/isa/v20240411/_attachments/riscv-privileged.pdf)核对清旧描述符/失效/新描述符的顺序，未复制其实现。没有新增面向多核、非一致表缓存或目标真机的保证，代码同步仍由已有seal/调用者负责。

host新增三组真实ARM/RV编码检查，提交钩子读取实际槽，确认第一次commit见0、第二次见新叶；核对失败/旧快照/未知位/no-op的无修改与无维护、零alloc/free，以及用户高半区/特权/Device属性限制。元数据/编码mock不替代真实TLB验证。

spaces两架构场景在活动内核root上添加独立普通VA，先触发实际RW翻译，再64次交替指向两份真实物理页并变更R/RW，逐次读新pa内容、写新页及检查旧页未变，物理及页表用量全程不增加，最后unmap/free回基线。rodatawrite另先把已存在rodata页改RW、真实读写相同值以预热可写翻译，再replace回R；最终汇编store必须在原vm_fault PC因权限故障失败，不能因缺页或仅靠lookup而通过。主机同时核对PTEREPLACECHECK/PTEPERMCHECK及最终导出的完整页表。

### Space 克隆准备中的全部别名保护（2026-11-17）

HAL内部新增VM_COW=16：只允许普通内存、用户root、R且无W/X的4KiB叶；RV使用RSW bit9（bit8仍表示Device），ARM使用软件bit55，decode会在Hpte.prot报告标记。位选择核对[RISC-V Privileged 20240411](https://docs.riscv.org/reference/isa/v20240411/_attachments/riscv-privileged.pdf)与[Linux v6.12 arm64软件PTE位定义](https://github.com/torvalds/linux/blob/v6.12/arch/arm64/include/asm/pgtable-prot.h)，只参考可用软件位事实，未复制实现。HAL map/replace均拒绝kernel/Device/可写/可执行COW组合，替换仍遵循前节BBM。用户Maparg/Local权限仍只接受原1/2/4，不把软件标记当成应用可选权限。

Mmap.prot低3位继续保存逻辑权限，高位内部MAP_PROTECTED表示该记录的全部逻辑W叶已硬件只读/COW保护；另有只在准备事务内存在的MAP_NEW_PROTECTION，用于失败时只撤回本次降权。Mem新增cowmaps计数，为writes的子集（writes仍按逻辑W映射计）；利用原对齐空隙，Mem仍72字节、Mmap仍64、Space仍64，不增加固定映射池或全局表。memclone只在所有逻辑W映射均已保护时接纳共享，而不是把只读PTE误当作失去逻辑写权限。

可信内部spaceclone(source_mem, target_acct, out)首先遍历全部Space/Mmap，检查匹配源Mem的每个别名（包括R别名）。若任一Space仍active或busy、存在准备期加载scope、出现未跟踪写引用/计数不一致、PA/权限/属性与元数据不符或原始叶有未知位，整个准备在修改前拒绝。每叶借HAL replace的同值no-op核验完整编码，不只检查解码结果。准备期遍历有SPACES/MMAPS/MEM_PAGES编译上限，当前为可信串行冷路径，不在写故障路径扫描全局池，也未做延迟/性能验收。

全部预检通过后，对涉及的Space标busy，将所有尚未保护的逻辑RW别名逐叶降为R|COW并完成失效；普通R别名不添COW或W权限。每个完整降权的Mmap增加cowmaps并记录本次新保护，随后调用已实现memclone取得孩子分支/承诺。成功只清除临时NEW标志、保留保护；失败先由Mem撤销本次页分支，再把NEW映射恢复原RW及计数，已有COW映射保持原状，最后解除Space busy。提交阶段不分配页表页；预检后的描述符/计数矛盾属违反串行不变量，不能静默留下半保护。

spaceunmap按记录逻辑权限与COW硬件权限分别核验：保护叶须仍指向该Mem当前页且为R|USER|COW，逻辑W责任只在完整PTE解除后解除，并先减少对应cowmaps。由此free最后管理句柄后，受保护映射仍持物理/分支/账目，最后unmap才结束真实引用；不能因硬件只读就漏计逻辑写者，或因解除保护计数而恢复已共享页的W权限。

例：同一DATA Mem在空间A/B分别有RW别名，A另有R别名。准备时A/B的RW叶均为COW只读、writes=2/cowmaps=2，R别名保持R；孩子取得一份独立Mem逻辑视图。若孩子额度只够第一页，失败后四个新保护叶恢复RW、cowmaps=0；若A/B本来已COW保护，再次失败不会恢复其W。若其后出现独占页上的新增普通RW别名，下次失败也只撤回该新增别名的保护，原两个COW别名继续保持。
