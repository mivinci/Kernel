## 时间与故障观测

内核提供单调时间、定时等待/唤醒；墙上时间和时区不是首版必需。
sleep 的定时唤醒不等于 IPC 超时；不能把超时当成磁盘请求或 DMA 已取消。
提供受控进程快照：身份、父进程、名称、状态、阻塞目标、CPU 用量、内存用量和控制终端。
用户异常按信号策略处理，默认只终止故障进程并记录原因/故障地址，合法处理函数可处理可捕获故障；内核 panic 必须输出可定位的信息。
早期诊断不依赖 fs/tty 正常工作，正常日志可先走 tty，不新增 log 服务；dis 为显示服务，已替代旧 print，不另设打印/输出服务。

- [ ] 实现单调时间、sleep、ps、内存用量查询和故障记录。
- [ ] 限制查询和调试接口权限，不泄漏内核指针或其他进程私有内容。

## 可用工具和持久化闭环

sh 支持参数解析、引号、外部命令、退出码和基础重定向，不要求完整脚本语言。
最小工具集：echo、cat、ls、pwd、cd（sh 内建）、mkdir、rm、ps、kill、sleep、内存用量查询。
工具可共享实现，但首版至少有一个从磁盘加载的独立可执行程序，不能全部由 sh 内建冒充程序加载。
文件系统写操作要有明确崩溃一致性和 flush 语义；未完成的写不能自动重放。
退出系统前停收新写入、完成已提交事务并同步；关机/重启由授权管理者发起。

- [ ] 明确磁盘格式和最小恢复策略，验证断开服务后重新挂载；不直接把旧 KFS 视为已移植。
- [ ] 提供 sync、受控 shutdown/reboot 及对应固件操作。

## 第一版验收与后续边界

### 观测与诊断（已确定）

不新增必需日志服务：普通输出走标准流，内核/关键诊断进入有界记录缓冲，致命内核错误走最小早期控制台并停止。
内核提供受授权的结构化进程/资源查询，供 init、ps 和 proc 类 VFS 后端展示，不通过任意内核地址读取实现。
查询包含完整身份/父子/会话/组、运行或阻塞原因、CPU 时间、实际/预付/收尾内存及请求/映射/资源槽用量、退出故障原因。
普通进程只查自身及授权目标，管理者可管理查询；枚举并发变化时每条记录自带完整实例身份，过期跳过/重查，不串复用槽。
日志记录时间、来源、级别和内容，容量可配置，满时明确覆盖/丢弃策略并记录丢失量，不在高频 IRQ 中直接串口打印。
用户异常按 [信号设计](11-terminal.md) 递送或默认结束故障进程并保留诊断；内核异常保存必要现场、输出并停止，不能恢复执行掩盖内核故障。

生产serial与最小早期控制台的寄存器所有权交接尚未实现。2026-11-18用户已确认显式debughandoff及panic独占接管，调用号/权限、顺序及限制集中记录在[07](07-boot.md#生产uart与早期诊断交接2026-11-18已确认)；不以永久关闭panic串口替代本篇要求，设计确认不代表实现或验收完成。
普通查询不泄漏内核地址、他人私有数据或任意寄存器，用户可控日志文本安全显示，不作为终端控制指令执行。
必须能关联等待链、Rq 阶段/持有服务、共享区/DMA 固定和资源预算，不能只输出模糊超时。

- [ ] 日志洪泛、缓冲满、VFS 不可用及读取权限拒绝时仍有界，报告丢失数且保留独立故障诊断。
- [ ] 进程槽复用、请求取消收尾及设备隔离场景，查询结果可对应真实完整身份和资源账目，不产生新的引用泄漏。

### 最小诊断快照（已确定）

受权查询至少覆盖进程完整身份/运行等待状态/CPU时间、Rq 两端身份/阶段/终结及消费收尾释放标志、Acct 上限/实际/预留/共享DMA保留、Life 退出原因/剩余清理/隔离及失败阶段。
读取权限与管理权限独立，观察不授予终止/重配。内核报告实际身份及等待关系，init 补程序名和服务语义；不使内核理解 fs/blk 操作码。
单条记录一致快照，批量枚举有上限，不冻结全系统；跨条目不承诺同一时刻，身份/代次和时间用于识别消失/复用，避免拼接不同代对象。
普通查询不暴露内核指针、完整寄存器或他人私有数据；固定池、在途预留与退出隔离资源分别统计，不只计活进程页数。日志有界并报告丢失计数，IRQ 热路径不做大量格式化输出。

查询显示调用者结果已消费、server_finished 为假、跟踪未释放且共享/DMA保留非零，可判断旧槽仍在合法收尾而不是简单内存泄漏。等待链可显示应用→fs→blk，由 init 解释名称，设备侧实际完成再用 trace 观测。

### 关机与重启（已确定）

init 协调关机状态机，普通进程只提交请求，最终固件关机/重启由内核授权操作执行。
顺序为进入关机、停止新增程序/会话/业务、通知应用结束并收取状态、fs 排空并同步、驱动停收/排空并确认设备安全、输出结果、调用固件。
停止业务不能封死 close/确认/取消/收尾通路；fs 同步时仍能处理这些操作，blk 必须在 fs 最后同步后才能停止。
应用先 TERM 并有界等待，超时可 KILL，但服务侧请求及 DMA 仍按真实完成条件收尾；tty/serial 保留较晚以报告故障。
正常关机仅在同步和约定设备停止成功后报告，失败明确阶段，授权者可重试或选择强制；不自动降级强制。
强制关机明确可能丢数据，不伪报安全落盘；设备失联有界进入隔离/离线处理，不无限挂起管理流程。
重复请求关联同一关机操作，不启动并行流程；进入不可逆阶段后不承诺恢复正常业务，阶段和失败原因可查询。

- [ ] 覆盖写入中关机、应用拒绝退出、服务失联、设备不完成、同步失败及重复请求。
- [ ] 正常关机后同镜像重启核对已承诺数据，并核对实际 flush/服务停止顺序，不只匹配退出标记。
- [ ] 未授权关机拒绝；失败仍有诊断，强制模式不得显示为正常同步成功。

- [ ] 两架构启动至 sh，终端行编辑和输入输出正常。
- [ ] 从磁盘启动带参数的程序，继承标准流和控制终端，父进程取得退出码。
- [ ] 完成 ls/cd/cat、创建/写入/读取/删除及输出重定向，重启后数据符合持久化承诺。
- [ ] 一个程序忙循环或异常时，其余进程仍可运行，能查询并终止目标。
- [ ] 连续启动/退出及失败加载不泄漏页、句柄、会话或退出记录。
- [ ] fs 崩溃取消等待、按用户态策略重建；旧身份无效，失败写不重放。
- [ ] 运行格式检查、针对性 host 测试及两架构 QEMU 场景，再建立性能基线。

本轮包括基础 uid/gid/rwx/sticky 权限；单用户运行不等于不检查权限。

### 关机操作的提交与调用者退出（已确定）

init 使用预付全局关机状态推进接受/停止新业务/应用退出/FS同步/设备停止/固件操作，不将关机任务存活绑定某个调用者 Rq。提交前完成权限/参数/状态准备，失败不改变系统运行状态。
提交后发起者退出、被信号打断或取消 RPC 仅放弃等待，不取消已开始的系统操作；同目标重复请求关联原操作，关机/重启等冲突目标明确拒绝，不偷偷替换。
停止新业务不封闭 close/取消/确认/清理路径，等待外部服务时 init 控制循环仍运行。各阶段有进度/截止/失败原因，失败不自动转强制；授权者显式选择强制时报告未完成持久化/设备收尾。
最终固件关机/重启由持专门内核授权的 init 执行；内核不协调 FS/普通设备业务。不以所有进程退出替代数据同步与设备安全条件。

#### 示例：发起关机的 sh 先退出

sh 请求关机，init 验证并提交后 sh 因信号退出，原 Rq 可取消/收尾，但全局关机继续。FS 同步失败则记录并停在明确失败阶段，可经仍可用控制/诊断通道查询，不无提示强制断电。

## 板端验收与硬件矩阵（2026-11-18）

QEMU 不是目标平台，验收须在无 QMP、无 `pmemsave`、无主机页表审计的条件下成立。

- **观测降级**：以串口转储为准；程序自身输出结构化摘要（计数、状态、FNV-1a64 一类校验和），主机只做文本比对，不逐字节导出内存。
- **自检优先**：每个场景须能自证关键不变量（页与费用账目回基线、会话数归零、摘要匹配），不依赖主机读内存。
- **显示类场景**：真机没有 `screendump`，改为绘制后读回并计算摘要、同时打印串口；QEMU 侧保留 `pmemsave`/`screendump` 作交叉验证。
- **硬件矩阵**：每块板记录 SoC、内存、固件版本、DTB 来源与哈希、可用与不可用外设；不可用项写入 status，不以“未测试”代替结论。
- **CI**：QEMU 继续作为主 CI；板端回归采用串口脚本加自检摘要的半自动方式，逐步过渡到可复现刷写流程。当前没有板端 CI，不得以 QEMU 结果冒充板端结果。

`pages` 试点：先用 `make build ARCH=<arch> CASE=pages` 构建，再运行 `python3 tools/smoke.py --arch <arch> --case pages --serial-only`（RV64 另传 `--firmware` 指定 OpenSBI）。QEMU 直接启动，只采集 UART。测试镜像在物理页写读校验、耗尽、COW 预留与释放、合并和账目自检完成后输出 `PAGECHECK`，再输出 `READY pages-restored`。主机校验完整且唯一的摘要、前后页数、预留归零和耗尽计数；普通 QMP 路径保留用于交叉验证。物理地址参与读回校验和，内存布局不同的环境不要求该值或可用页数相同。

stage283：ARM64、RV64 各通过一次纯串口与一次 QMP `pages`；同一架构的完整摘要一致。从实测日志移除或重复摘要、篡改预留计数、截断结束行及附加 PANIC，均被校验器拒绝。

stage284：同一命令可将 `pages` 换成 `ipc` 或 `cow`，构建和运行须选同一场景。`ipc` 校验真实阻塞轮次、两个进程的退出和费用回收；`cow` 按顺序校验 Mem、Space、分支、映射快照和用户写故障五份摘要。三种场景均以串口 `VM` 行的页表数为初始分配基线，拒绝摘要缺失、重复、乱序或最终页数不符。ARM64、RV64 各运行三个场景的纯串口与普通 QMP 路径，12 次通过；同架构各场景两份摘要一致。16 项 smoke 主机检查通过，真实板卡复验待执行。

## 首版推进、期限与冻结验收（已冻结）

未发布fork/spawn/exec构造准备10秒，普通open未交付fd的接入准备10秒，init清单服务自成功start起另设READY监督10秒；普通已发布镜像无通用启动/接入强杀期限。控制即时查询1秒，sh就绪检查片段50ms，设备复位3秒；关机应用TERM宽限3秒、FS同步10秒、设备停机3秒。所有deadline为绝对单调时间、重查不重置，固定表清理工作每次32项。超时标记由相应所有者推进：内核管构造/替换资格，服务管自身准备/业务，init管监督/全局关机，CPU安全出口管内核回滚，不把已STOP/死亡的发起者当唯一推进者。

关机控制mode NORMAL=0/FORCE=1，只init SYSTEM可最终调用固件。NORMAL失败停在明确FAILED阶段，控制/诊断/取消继续可用，不自动变FORCE；FORCE显式报告未同步/未确认DMA，不称正常成功。日志固定64 KiB覆盖最旧完整记录，记录丢失计数；单条内容最多256字节，IRQ只入紧凑记录、不阻塞串口。

本轮设计静态验收要求：共享结构大小/偏移用host构造检查；调用号/类别/选项不重复；文档所有本地链接有效；按小容量枚举Rq终结/确认/服务收尾和准备提交/撤销/死亡/超时，验证唯一结局、无复活、资源不早收；实际栈深、TLB/cache、IRQ顺序、两架构QEMU与CI仍是实现阶段待执行验收。不能把设计枚举标记为内核单测或QEMU通过。

### 有界内核诊断日志前置（2026-11-18）

kernel/klog.c提供内部64 KiB定长存储，227条288字节记录及160字节零填充；记录含单调sequence、纳秒时间、来源、有效字节数、级别/标志和256字节内容，布局由include/klog.h断言锁定。满时只覆盖最旧完整记录，丢失量饱和计数；序号耗尽不回绕，后续写返回OVERFLOW并记丢失。读取0选最旧记录，旧序号STALE、未来/空WOULD_BLOCK；错误不修改输出，未用内容/保留位始终零。

现有putstr/puthex在单CPU屏蔽IRQ范围内组装同一行，遇换行或256字节提交一条完整记录，同时保留原串口输出；长行按256字节拆分，不将本次碎片长度冒充完整文本长度。来源0表示内核，不记录内核指针为来源；clockmono不可用时显式清时间有效标志和时间值。panic先屏蔽IRQ、提交先前半行，随后以ERROR级记录自身诊断并停机。日志核心无分配、设备访问、调度调用或用户态依赖，IRQ可直接入紧凑记录但不应调用轮询打印。

此点只是已确认控制台交接的日志前置：普通诊断仍同步串口，尚未接debughandoff及panic恢复UART，也没有用户日志读取syscall/伪造SYSTEM权限。内部读取接口不是任何主体可查所有日志的授权；对外结构化诊断和高频IRQ日志路径另行实现。屏蔽IRQ保护记录提交不等于已证明最坏打印/IRQ延迟，早期轮询输出有界化仍随交接实现推进。

6项host专项在O0/O2验证二进制内容/元数据/清零、非法输入不修改、完整记录多轮覆盖与cursor缺口、缩小序号上限后的耗尽不复用、碎片+hex组行、600字节长行及早期无时钟状态；假HAL核对记录/输出发生在IRQ屏蔽且调用后恢复。两架构normal/fault实际运行已通过，smoke独立导出真实64 KiB BSS记录并核对布局、连续序号、级别、零填充及每条内容存在于串口，fatal须有ERROR PANIC记录。完整回归进行中，证据归build/host/stage108-kernel-journal/，无CI/真机/性能验收。

### UART交接与致命诊断恢复（2026-11-18）

已接原生0x74及libsys私有__sys_debughandoff。权限检查在幂等检查之前：必须为精确初始PID1/image1的有效SYSTEM CONSOLE，uid0、裸PID及普通CONTROL不能替代；余参数非零INVALID，错误及成功均无业务输出。初始SYSTEM保留QUERY并另授CONSOLE，不新增GRANT/继承。普通生产init尚未调用此入口，实际serial装载/READY仍待接。

HAL在首次受检UART初始化时保存固件分频/字符格式和控制配置；NS16550临时选择DLAB读取两份分频后清DLAB，PL011保留IBRD/FBRD/LCR_H和启用后的CR，不猜时钟或写死波特率。PL011完整访问窗必须覆盖DMACR，NS32位访问的步长必须逐寄存器对齐，DTB/console首次访问前一致拒绝不合法布局。寄存器访问通过架构侧有序设备屏障完成，公共控制台没有架构寄存器条件分支。

交接仅一次读取TX状态，须同时满足FIFO和移位寄存器空；BUSY不改归属、由init稍后重试，不在内核等待排空。成功后即使再次调用、用户改变DLAB/波特率或释放设备句柄，普通hal_debug_putc也不再读取或写入UART；日志继续保存诊断，不依服务退出或IRQ解绑自动恢复。diaghandoff提交现有半行并固定日志边界。

panic先屏蔽IRQ且不再调度，提交待写诊断，再独占恢复UART。NS屏蔽IRQ、恢复分频/字符格式并清FIFO；PL屏蔽IRQ/关闭DMA请求与UART，最多4096次观察BUSY清除，恢复分频和字符格式、关硬件流控/回环并启用最小轮询输出。恢复成功只回放日志边界之后仍保留的至多227条记录，再输出ERROR PANIC并halt，不恢复用户驱动。设备不可排空时返回TIMEDOUT并保持普通输出静默；每个轮询输出字节最多4096次尝试，第一次超时后停止继续碰设备，丢失输出字节饱和计数，内存日志保留。观察次数上限不是纳秒延迟保证，关闭UART DMA请求也不证明外部DMA引擎已停；此致命路径不回收DMA内存或重启服务。

主机专项覆盖FIFO空但移位忙、幂等及交接后无MMIO（重定位到不可访问地址仍可静默调用）、PL固件配置恢复/IRQ和DMA请求屏蔽、坏设备有界失败及输出丢失统计；授权专项拒绝普通镜像即使可信测试强行加CONSOLE位。原生包PID1另验证错误授权、未用寄存器/零输出、BUSY重试与重复交接，之后故意改坏NS的DLAB/分频或禁用PL并改分频/格式，最终真实PID1 exit触发panic恢复与日志回放。两架构用例已通过，保留完整PTE/Acct/日志及唯一BOOT/INITEXIT/PANIC审计，不以静态标记或只读写寄存器模型替代运行。

### 本地运行证据保留与清理（issue011，2026-11-18）
