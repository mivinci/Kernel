## 权限与资源

每个进程包含地址空间、调度/IPC 状态、事件位图和有上限的扁平资源表。
init 配置系统策略及初始授权；普通进程可按受限创建权限创建自己的孩子，并使用预算内自身内存权限，不能扩张权限或任意修改他人空间。普通服务只使用已授资源。
表项记录类型、对象标识和权限；用户只能传整数句柄，不能传内核指针。
句柄须识别代次，防止槽位复用导致旧句柄访问新资源，耗尽不得回绕复用。
删除 CNode 用户对象、两级 CSpace、Copy/Mint、badge 派生、通用跨类型IPC能力传递及通用 INVOKE 框架；连接建立的请求绑定单资源回复交付单独按受限契约讨论。

### 统一标识类型（已确定）

进程实例身份、本地资源句柄、请求标识统一使用 `typedef int64_t Handle;`，不采用 32 位 HANDLE。
统一的是整数表示，不是权限或生命周期：进程身份用于识别，本地句柄用于授权访问，请求标识只允许接收服务回复对应调用。
编码保留类别、槽号和代次/调用序号，各入口检查预期类别、有效性及所需权限；不同类别不得因数值碰巧匹配而串用。
本地资源句柄只在所属进程资源表中解释，不能跨进程直接当作同一授权使用。
fork 是专门的受控继承例外：对允许继承且应用可见的 Handle，子资源表需在对应槽/代次建立合法的独立引用，保持被复制内存中的数值有效；私有内存授权重定向到子逻辑视图。非继承授权/请求不得占用同值形成越权别名，保留/失效槽规则随 fork 资源表规格冻结。普通 grant 仍不允许直接复制整数。
编码确定为：最高符号位固定为 0，其后 4 位类别、43 位代次/调用序号、低 16 位槽号；有效 Handle 必须为正数。
`0` 为无效 Handle，类别值以06固定表为准；有效类别不能与无效值混淆。
槽号可编码 65536 个位置，但实际进程表、资源表使用更小的编译期上限，每个入口都必须检查实际边界。
进程身份的槽号索引全局进程表，本地资源句柄索引当前进程资源表，请求标识索引全局有界请求表，而非调用者进程槽；请求记录分别保存完整调用者与接收者身份。
代次不得回绕，请求代次须跨请求槽复用保持不重复，43 位耗尽后拒绝继续复用对应槽位。
64 位是 ABI 整数宽度，不是指针宽度要求；ARM64/RV64 可通过单寄存器传递，未来 RV32 可拆为高低两个寄存器。
未来 32 位端口须明确寄存器顺序、跨边界结构布局和并发访问保护，不假定 64 位内存读写天然原子。
当前不因此新增 RV32 实现。

### 有符号 Handle 与 POSIX 身份（已确定）

Handle 与 pid_t 使用相同的有符号 64 位表示；进程 PID 直接使用正的 PROCESS_ID Handle，不新增独立 PID 编号或转换表。
0 为无效 Handle；0、-1、负进程组编号等选择语义仅在明确规定的 POSIX 接口中成立，普通资源/IPC/映射接口拒绝非正句柄。
负错误码仍通过 ABI 的状态字段返回，不能把选择器、身份和操作状态混为一个未注明的返回字段。
编码/解码先转换为 uint64_t 再掩码/移位，不对有符号值做位编码；解析负组号先查范围，拒绝 INT64_MIN 等不可安全取负的值。
POSIX 进程组号/会话号沿用组长/会话首进程的进程身份；内部 GROUP_ID/SESSION_ID Handle 仍独立，由关系记录保存其对外编号，不能只替换类别位构造对象。
组长退出不使仍存在的组号失效，所有权限及引用继续验证完整身份。

初始 init 的 PROCESS_ID 固定保留为 1，是普通类别编码的唯一身份例外；0 仍无效，其他身份遵守已定编码。1 不分配给本地资源/请求，不参与槽复用；初始 init 退出为致命错误，不通过重启复用 PID 1。
身份类别识别和有效性检查使用统一辅助入口，先识别保留值 1，禁止各处直接移位推断其类别；认可身份不等于授予管理权限。编码语法现唯一实现于abi/base.h的handlekind，内核handletype转调；用户库可用它区分参数类别，但存活/会话关系/授权仍由内核裁决。
PGID 等于创建组的组长 PID，SID 等于创建会话的首进程 PID；内部关系记录独立存活并保存完整对外身份。组长退出且退出记录收取后可复用其进程槽，新代次不与旧组号冲突；组/会话按成员及管理引用清零条件回收。

### 会话与进程组操作（2026-11-16用户确认）

getpg(0) 查询自身，其他正PID只允许查询同会话的构造中、存活或尚未收取退出结果的进程，返回实际PGID/SID。认识PID或持有CONTROL不绕过该接口的会话边界。

setpg(pid,pgid) 中pid=0表示自身，pgid=0表示目标PID；只允许修改自身或尚未成功exec的直接孩子，调用者与目标必须同会话。会话首进程不能改变组，即使请求原组也拒绝。新组的PGID只能为目标PID；否则必须加入已有的同会话组。负选择器及非进程类别拒绝，uid 0不绕过关系检查。检查/分配失败保留原关系。

setsid仅作用于自身；若任一仍保留的组以调用者完整PID为PGID，拒绝建立新会话。成功时SID=PGID=调用者PID，原组其他成员保持原关系。系统服务在启动流程显式setsid隔离，不能靠uid或名称获得隔离。

构造阶段预占组的进程引用，发布时转为活跃成员；取消解除预占。退出解除活跃成员，未收取结果继续保留原组，收取后解除该引用；单独持有旧CONTROL不继续保留成员关系。组/会话管理引用与进程引用分别计数，组保留所属会话。初始init使用SID=PGID=1，但关系记录不是模拟init进程。

例：sh在会话S内创建尚未exec的A、B，setpg(A,0)建立组A，再setpg(B,A)加入。A先退出并被收取，B仍持原完整PGID A；A的运行槽复用后，新PID不能重定向这个组。B退出并被收取且管理引用清零才回收组。若B先setsid成功，sh随后setpg(B,A)因跨会话失败；若分配新会话或新组时容量不足，B仍在原组，不留下半建关系。

- [ ] 两架构检查 Handle 为 8 字节有符号类型，所有有效编码为正，43 位代次耗尽拒绝回绕。
- [ ] POSIX 正/零/负选择器、INT64_MIN、非进程类别、陈旧 PID 和组长退出均覆盖；原生接口拒绝负句柄。

### 编译配置容量（已确定）

容量由简单编译配置生成公共配置头文件，不写死在实现中，首版不引入 Kconfig 或运行期扩表。
配置项包括 CONFIG_MAX_PROCS、CONFIG_RESOURCES_PER_PROC、CONFIG_PENDING_CALLS；默认值和固定槽预算以01/本篇首版表为准，实现仍须核对真实sizeof。
最大进程数和每进程资源槽数不得超过 Handle 的 16 位槽号范围，计算数组和内存大小须防溢出。
CONFIG_PENDING_CALLS 为每服务已接收未回复 CALL 的编译上限，至少保留一个即时分发名额；长期 defer 只能占其余名额。
全局 CONFIG_REQUESTS 不超过 65536；每进程创建时预付其 CONFIG_OUT_REQUESTS 请求槽，含服务异步请求和信号上下文预留。
构建及创建检查请求池总量、系统预留和已预付之和；CONFIG_OUT_REQUESTS 至少覆盖普通同步上下文和 CONFIG_SIGDEPTH 的独立预留。
每服务异步执行表、原Rq/共享槽及收尾容量也须匹配，不另设等待业务ACK的通用结果表，可少接收新业务但不能借用取消收尾、信号及控制专用预留。
一个进程可有多个异步/收尾请求，但每执行上下文只阻塞在一个同步等待上，请求上限不再按进程数直接推导。
init 在启动前可下调服务接收上限，不得超出编译配置或该服务用户态暂存表容量。
创建中实例占运行槽；方案将待收取退出结果保留在 Life，而非继续占完整运行槽。运行槽、Life 池和集合实例限额分别检查，容量耗尽明确失败；不能仅复用运行槽就绕过未收取结果的限额。
不同硬件可选不同容量配置，Handle、固定短消息及协议 ABI 不因此改变。
构建应报告或便于核对固定表内存开销，测试覆盖容量边界、超额拒绝和释放后复用，不假设固定 64/16 上限。

类别集合与自有/全局管理边界按[全局设计与冻结条件](00-overview.md)固定；类别数值、编译配置默认值及配置文件语法在共享 ABI/构建配置中分配。
授权撤销和对象销毁必须分别定义，不把代次检查当作资源回收协议。

### 文件凭据与内核授权（已确定）

init 在进程创建时配置真实/有效 uid/gid，内核保存权威记录，首轮运行期保持不变；普通子进程继承，不支持运行期身份切换、setuid 文件和补充组。
文件权限由 fs 根据真实 IPC source 对应的可信凭据检查；内核资源操作由本地 Handle 授权检查，两者不能互相替代，uid 0 不自动成为内核管理者。
cwd/root/umask 归 fs 的进程上下文；与凭据的继承和快照协作见 [启动设计](07-boot.md) 与 [文件系统](10-filesystem.md)。

### 授权内容与范围（已确定）

本地资源表项保存稳定资源引用、子类型、允许操作及适用范围；范围使用经检查的偏移/长度等明确表示，不能用溢出的末地址绕过检查。
grant 由具备相应授予权和目标配置权限的调用者发起，在接收方建立新的本地 Handle 并取得资源引用；不自动映射内存，不直接复制源 Handle 整数，普通进程只能在明确获准的范围委托，不能扩大权限。
内存授权限制可访问子范围及读/写/执行属性；map 同时检查授权、范围、目标地址空间权限及 Mem 状态，伙伴块取整后的额外页不自动获授权，SEALED 禁止重新授写。
IPC 发送/调用、内存映射属性、进程管理和 IRQ 确认分别定义所需权限，不用单一读写执行掩码代表所有资源操作；不引入通用方法分发系统。
CALL/SEND及notify授权绑定完整目标实例/镜像，不随目标exec自动改绑；管理授权跨exec存活另按专门契约。队列及旧请求处理见 [目标镜像绑定](04-ipc.md#call授权绑定目标镜像语义收口)。
失败不发布半成品表项且撤销本次引用；撤销后的资源表项不再提供访问路径，底层资源仍由有效映射/在途操作等引用维持。

### grant 调用契约（已确定）

逻辑参数为grant(target, source, rights, offset, length, inherit)：target是在调用者本地表解析的CONSTRUCT/EXEC_VIEW CONFIG或固定进程CONTROL INSTALL；source是调用者本地源资源授权，必须另有bit63 GRANT。rights为授出子集，offset/length为Mem本体范围，inherit为允许的保留标记。源可转授与目标允许安装是两个独立条件。
非范围资源要求范围字段为零；复杂参数使用 ABI 定长结构，保留位和未知权限拒绝，不静默忽略。内存窗口沿用 Mem 相对偏移，不能超出源授权或绕过 Mem 状态。
目标自动选择空槽，不覆盖已有表项，容量不足失败。
成功状态为 0，结果字段返回目标资源表中的新 Handle；该结果不属于调用者自己的资源表。管理者可写入目标 Boot 或按控制协议交付，不可直接在自身上下文用作资源授权。
grant 增加独立资源引用，不建立派生树；释放源 Handle 不自动撤销目标，撤销一项不级联撤销其他独立授权。失败完整回滚引用和目标表项。
安装与目标进入退出状态原子排序：先退出则安装失败，先安装则纳入该实例退出清理；固定完整目标身份，不能安装到复用后的新进程。

有效CONSTRUCT/EXEC_VIEW的CONFIG另允许只读query RESOURCE枚举其精确准备表，用于发现目标SELF Handle；其他query种类拒绝，准备发布/取消/超期立即失效。该观察不将目标Handle变成调用者本地授权，也不授予持续CONTROL QUERY。

### 目标表安装权限（第2项审查修订）

CONTROL各低位固定为QUERY=0x01、TERMINATE=0x02、BUDGET=0x04、IRQ=0x08、REVOKE=0x10、CONNECT=0x20、INSTALL=0x40。新增INSTALL只允许grant向该CONTROL绑定的单一进程资源表安装引用；不会授予configure初始CPU现场、改运行中寄存器、map他人空间、预算调整或撤销权。已有位号不移动。bit63 GRANT允许把该资源本身减权转授；用于CONTROL connect时，还限制产物能否包含GRANT，不代替目标INSTALL；即使target CONTROL同时有QUERY、CONNECT、GRANT而没有INSTALL，也不能安装。

| grant的target | 必需权限/绑定 | 可修改的表 |
| --- | --- | --- |
| CONSTRUCT | CONFIG=0x02；调用者PID/image仍为本次构造者，目标未发布且未撤销/超期 | 该孩子本次构造资源表；不保留发布后的修改权 |
| EXEC_VIEW | CONFIG=0x02；仅本主体当前镜像持有且替换准备仍有效 | 本次目标准备资源表，不是正在运行的旧表 |
| CONTROL | INSTALL=0x40；绑定单一完整进程Life，目标仍有可接受安装的当前运行镜像 | 该Life当前镜像的资源表；已终结Life没有可安装表 |
| PID、CALL、SOURCE REQUEST、SYSTEM、集合/域CONTROL | 不接受为安装目标 | 不按数字或“管理员身份”猜目标表 |

有范围的集合/域CONTROL仍可用于其明确的查询/预算操作，但grant没有另一个目标PID参数，因此必须传入单一进程CONTROL，不能隐式扫描授权表找目标。init同样遵守此规则，使用SERVICE创建返回或已有合法授权的固定目标CONTROL，不增加按任意PID派生配置权的入口。持有INSTALL的人只可安装自己另有GRANT的合法源，不能制造新权限。

grant在发布前校验两个本地句柄、目标类型和阶段、源GRANT、授出权限/继承子集、Mem窗口/当前状态和目标容量；非Mem的offset/length必须0。成功只增加一份独立目标引用，不覆盖表项。若检查和提交之间允许调度，固定目标Life、具体镜像/准备身份及授权代次；提交时全部重查。构造发布/撤销先发生则不安装；活目标切换镜像或退出先发生则拒绝旧尝试，不把已取得的旧表指针改绑新表。失败不消耗目标槽或泄漏源引用，普通错误输出清零。

revoke(target, target_local_handle)的target同样必须明确：活目标用固定进程CONTROL REVOKE=0x10；自己的有效CONSTRUCT/EXEC_VIEW用CONFIG=0x02修改本次准备表。INSTALL不隐含REVOKE，QUERY/GRANT也不隐含REVOKE；resource只在该精确目标表内解释，不能操作同号新实例。普通父关系不授予运行后INSTALL或REVOKE。

示例：init有B的CONTROL INSTALL及M的READ|WRITE|GRANT，可以把M的受限READ引用装到B。监督者S仅有B的CONTROL QUERY，即使S另有M的GRANT，grant仍DENIED，B表不变。父以孩子CONSTRUCT CONFIG安装后，start先发布使构造权失效；迟到grant不能继续向运行中孩子塞引用。若旧B镜像在检查后被exec替换，本次grant失败且不写新镜像表，init可以针对新状态另行发起一次明确操作。

### grant/revoke 的目标边界（审查收口）

| 场景 | 目标权限 | 源权限及效果 |
| --- | --- | --- |
| 普通创建者给未发布孩子安装资源 | 本次CONSTRUCT CONFIG，且目标仍未发布 | 必须有该资源的可授予权，操作/范围只减不增；结果是孩子本地Handle |
| init等管理者给运行中受管服务安装资源 | 绑定该单一进程Life的CONTROL INSTALL | 同样检查源授予权和目标容量，不凭uid0豁免 |
| 普通客户端/服务给已运行对端共享资源 | 仅有CALL权限或知道PID不足 | 当前grant契约不覆盖，必须另有接收方同意的受限交付路径；不得借给对方完整管理权解决 |
| 撤销目标的一项授权 | 固定进程CONTROL REVOKE，或本次准备的CONFIG | 使该项旧Handle失效，不自动撤销独立副本、现有映射或DMA |

普通孩子发布点关闭所有依赖其构造权的安装路径，不仅是configure/start的原Handle；已经在途但尚未提交的grant/map必须重查目标阶段，不能靠提前取得引用延续发布后的修改权。已成功安装的独立引用不因父准备权结束而消失。

对source的READ/WRITE等使用权不等于授予权，减权后能否继续授予也须单独获准；非继承的构造/监督/IRQ权限不能被普通grant转给孩子。释放source只放弃本地引用，不是级联撤销；revoke也不提供跨独立授权树回收这一未设计能力。

#### 运行中服务连接的受限交付（已选定）

普通fork/spawn和open不经init后，现有要求目标管理Handle的grant不足以建立所有共享区/后端调用授权。已选择04的单资源reply补齐这条路径，仍必须验证接收方同意、资源种类/范围、单次容量及取消后的归属，且不能使客户端取得FS管理权，或使FS能向任意客户端表中塞资源。

方案细化见 [单资源回复交付](04-ipc.md#call-绑定的单资源回复交付已冻结)：同意接收的CALL预留一槽，受限SharedMem/后端CALL权随reply原子安装，Handle占回复words[0]，QUEUED取消或机制强制终结先提交则不安装，ACCEPTED协作取消保留接收槽。选项/描述符见06，连接补偿见10，不新增通用Handle类别或任意对象转移。

#### 示例：不能把FS当成未运行孩子

A已获FS的CALL权限，并拥有共享Mem M。A不能拿FS的PID或调用Handle当grant目标管理权，把M强行安装到FS资源表；反过来FS处理A的open请求也不自动拥有A的管理权。先定义双方同意且绑定真实请求的交付契约，再实现这类连接；现有grant只适用于前表明确有目标配置权的场景。

#### 示例：向 B 安装只读授权

init持有M的READ|WRITE|GRANT及B的固定CONTROL INSTALL，将第4页起的4页以READ授予B。返回的是 B 本地 Handle，B 可据此请求合法只读映射；init 用该整数在自身表中访问不构成同一授权。
随后 init 放弃自己的源 Mem 引用，不影响 B 已取得的独立引用；B 的授权撤销/退出及映射解除按各自协议收尾。

### 本地资源引用的放弃（已冻结）

为覆盖单资源回复交付，方案复用free(handle)释放调用者自己的本地RESOURCE引用，首轮明确支持MEM/CALL/SEND/NOTIFY及固定进程CONTROL引用；对应私有桩仍为__sys_free，不导出与C free(pointer)混用的裸函数。PID、RPC、REQUEST不是该入口可释放的本地资源；其他有专门生命周期的资源须各自定义，不因该入口存在就泛化成任意对象销毁。

| 本地资源 | free成功后的效果 | 不包含的效果 |
| --- | --- | --- |
| Mem | 表项失效、代次推进、放弃这份引用 | 不解除独立Mmap，不释放其他主体引用，不证明DMA停止 |
| 后端CALL授权 | 本地入口失效，不能再用该Handle提交新请求 | 不关闭服务端File会话，不取消已提交Rq，不终止后端 |

free只解析调用者自己的表，其他主体同值整数不产生权力；失效旧值不能释放复用槽的新引用。正在使用的映射、已提交Rq及后台清理必须保持独立稳定引用，不允许表项释放后继续从复用槽取源身份。放弃CALL入口与revoke取消该来源排队请求的管理语义分开，主动取消仍用rqcancel。

连接关闭顺序由libsys持有的原连接/会话身份协调：先禁止新业务，确定在途请求/共享槽已安全收尾，再解除本地映射、放弃不再需要的Mem/CALL引用，并通知服务释放其会话/源引用。必要关闭RPC须在最后一个可用CALL入口释放前发起并登记责任；单独free不能替代close协议。服务失联则按实例失败清理，不按同号新Handle重发。

若资源已回复交付但包装尚未安装，运行库仍负责这份引用；必须先将其保存到有代次的进行中/清理记录，再确认异步结果。调用者死亡时内核清理资源表不依赖这一步完成，其他主体/映射持有的费用仍按既有Acct规则保留。handler fork/_Fork时未安装结果的归属和子修复还须覆盖此类引用，不仅保存整数。

### 授权撤销（已确定）

撤销禁止新操作；send/call 尚未被接收时从等待队列取消，返回授权撤销错误。
接收是分界点：已接收的 CALL 允许该次回复，后续新调用拒绝；已交付 SEND 不追溯取消。
服务退出仍取消其未完成调用，撤销不能使旧句柄在重新授权后恢复有效。
在途调用必须记录其授权来源，不能只按目标进程取消通过其他有效授权提交的请求。
撤销映射权限只禁止新映射，已有映射由管理者显式解除；完成页表更新和 TLB 失效后才算解除完成。
撤销句柄不自动解除映射或释放内存；引用和 DMA 安全条件仍须满足。
free 放弃对应内存管理引用并使该 Handle 失效，独立 Mmap 仍持有内存；具体规则见 [内存引用与回收](02-memory.md)。
完整停止服务的策略由 init 执行：禁止新请求、停止或终止、确认退出、清理连接和映射、按回收条件释放资源。

### revoke 调用契约（已确定）

revoke(target, resource)的target在调用者本地表解析，要求固定进程CONTROL REVOKE或本次有效CONSTRUCT/EXEC_VIEW CONFIG；resource 在目标实例资源表解析，必须核对完整类别/槽/代次，不能按调用者主体解释。
先原子使授权失效并阻止新操作，再通过有界 Op 处理该授权来源的排队请求和必要引用；被接收的 CALL 保留既定回复/取消收尾路径，已交付 SEND 不追溯撤销。
返回 0 表示授权失效且本次撤销必要的内核状态处理已完成，不保证关联映射解除、服务业务停止或 DMA/物理资源回收；不能只置标志就遗留无人推进的队列清理。
目标不存在、权限不足、陈旧授权返回对应负错误码；重复撤销旧 Handle 不影响同槽新授权，不将陈旧身份视为可直接操作当前槽。
撤销期间记录及授权来源引用保持稳定，等相关操作不再依赖后才能复用槽并递增代次；已接收请求所需权限快照不因授权表项失效而丢失。

#### 示例：撤销 B 本地授权

init以B的CONTROL REVOKE和先前grant返回的B本地h调用revoke。h 立即失去发起新操作的资格，已存在 Mmap 不变；要移除 CPU 访问还须 unmap，DMA 则另行确认安全停止。
若 B 已将原授权清理且同槽出现新代次，init 再撤销旧 h 只得到陈旧身份错误，不能误伤新授权。

## 进程生命周期

创建中 → 就绪 ↔ 运行；运行可阻塞，完成等待后就绪。
任一存活状态 → 退出中 → 已退出 → 回收；阻塞原因独立记录。
配置完整前不得入运行队列；退出后拒绝新请求；取消等待后再拆资源关系。
在明确的内核调度/清理安全点拆除用户执行资源与地址空间；退出结果不能因进程槽复用而串线。退出者不能释放正在使用的栈。
生产启动调度循环每轮在CPU调度栈/内核root且没有current时执行既有procwork(1)/prepwork(1)有界清理，再选就绪进程；idle仍可推进清理。运行结果可先被wait收取，但不能以始终有READY进程为由无限推迟运行资源拆除。2026-11-18真实启动配置用例发现并修复此问题，715项host/格式/167份最终源码匹配的两架构QEMU通过，证据stage106；不能据此称全部清理延迟有硬实时保证。
共享资源按真实引用回收，设备 DMA 未停止不能回收相关页。
用户态管理者决定重启和重新连接；不自动重放失败的文件写操作。

已确定每执行线程独立内核栈加每 CPU 调度栈，首轮一进程一线程；不实现公共栈调度路线。完整用户现场、显式等待原因和请求归属仍分别保存。
方案首轮只在显式阻塞点、长循环检查点和安全返回出口调度，不在 IRQ 打断的任意 C 深层强行切换；不持临界区保护或临时不可恢复状态睡眠。长操作必须有界到达检查点，中断嵌套、调度现场及栈布局待硬件契约冻结。
跨服务启动事务、停止/继续和退出结果重试/确认采用本篇及 [启动事务与结果确认](07-boot.md) 的协议；下面保留基础创建、退出和孤儿规则。

### 独立生命周期记录（已确定）

管理 Handle 引用独立 Life 记录而不是仅索引可复用进程槽。Life 保存完整实例身份、运行资源关联、退出阶段及未完成清理关系，create 时由有界专用池预付，池耗尽明确失败。
进程存活时关联运行记录；运行资源清理且退出结果已稳定保存在 Life 后，方案允许运行槽回收而不等待父 wait，Life 保留旧身份、结果及清理关系，不保留无须继续使用的完整寄存器、地址空间和调度资源。
退出后的管理 Handle 只允许该阶段的查询/清理，不允许再次 start/configure，也不能作用于相同槽号的新代实例。最后清理完成且所有管理/内部引用释放后才回收 Life，代次不回绕。
Life 负责实例管理与清理责任，Acct 独立负责费用，两者不合并；普通 IPC 不强制增加 Life 间接访问，不新增用户可见通用对象体系。

#### 示例：旧 fs 管理授权跨槽复用保留

旧 fs 为进程槽 7/代次10，退出后槽 7 可分配给代次11的新 fs。旧管理 Handle 仍引用旧 Life，可枚举旧收尾请求及 rqclean；新实例管理授权不能完成旧请求，旧授权也不能重配新 fs。

### 普通创建权限与总预算（已冻结）

普通创建授权仅允许调用者创建自己的孩子；fork 来源固定为自身，spawn 目标是本次新建未运行实例，不能借创建配置任意已有进程。孩子继承内核确认的凭据，不允许普通 config 改 uid/gid。

预算不能随 fork 复制成新增额度。方案采用同一受管进程集合共享总限额，集合由 init 配置，孩子默认留在同一集合；每进程独立 Acct 和单进程上限继续保留。总限额不是父进程 Acct，也不随父退出消失；普通进程不能新建、切换或提高集合总限额。首轮不引入递归预算树或逐代父子额度借还协议。集合记录是内部计费关系，不是用户可调用的通用对象。

检查同时满足单 Acct 上限、集合总限额、系统实际资源及固定池容量。总计费涵盖现有实际页和 COW 物理预留，页表及其他有界记录按对应页/池计数；同一费用不能因多次映射重复计算，也不能漏算准备中及清理中的占用。

进程数量限制包含未发布孩子、存活进程及尚需保留的退出记录；退出结果与运行槽分离后分别限制池容量。Acct 因共享/DMA 尚未结清而保留时，内存继续占原集合额度，不必永久占一个已结清退出结果的运行槽。进程数量、请求预付和内存分别检查，不能以一个页数限制替代全部资源限制。

孩子只继承明确允许继承的资源及操作范围；创建权限自身是否可继承由 init 预设，普通调用者不能扩大。设备授权、全局预算配置和任意目标管理权限不隐式继承；普通委托还需独立的可授予标记及目标绑定，具体 grant 契约另行修订。父释放其独立引用不等于孩子引用失效。

#### 示例：多代 fork 不扩大总额

示意集合总内存上限为 256 页、最多 8 个待发布/存活/待收取实例，单 Acct 上限为 128 页；数字仅用于说明，不是默认配置。A 实际私有页占 80 页，fork B 需严格 COW 预留 80 页，暂计 160 页，再加真实页表和其他开销。B 再 fork C 同样需要检查集合剩余额度，不能只看 C 的独立上限；第 9 个实例即使几乎不占用户页也拒绝。

A 退出而共享内存或 DMA 仍占 20 页时，这 20 页仍计入集合；最终安全释放才返还。创建失败只退还本次真实取得且已安全释放的页、记录和预留，不恢复虚构的父额度，也不把仍被服务引用的资源当已释放。

Set/Acct、创建权和发布失效已在本篇首版规格与02/06确定；本节不表示已实现。

### 发布前后的创建者权限（已冻结）

普通创建者取得的目标授权是本次构造权限，不是终身完整管理权。不另增用户可见 Handle 类别，沿用进程管理授权及明确操作范围；内核还必须检查目标实例、构造归属和当前阶段，不能只检查表项中的旧权限位。专门授予 init 的服务监督权与普通创建权分开。

| 阶段/关系 | 允许 | 不自动允许 |
| --- | --- | --- |
| 新建且未运行的孩子 | 按授权配置初始现场、构建映射、安装可授予资源、发布或放弃创建 | 改身份、增预算、安装父本来没有的授权、操作其他实例 |
| fork 尚未发布的孩子 | 按专用继承协议准备、提交或撤销 | 用 configure 改成任意现场、用普通 start 绕过 fork 提交 |
| 普通孩子已发布 | 父依父子关系 wait；按信号及作业关系规则请求合法操作 | 继续配置/映射孩子地址空间、任意撤销其资源、直接 destroy 或强制管理终止 |
| 另获授权的服务监督者 | 按显式范围观察、停止、恢复或管理清理 | 以观察权消费父的 wait 结果、凭裸 PID 获得全部权限 |

普通构造权限在 start/forkcommit 的发布点失效，与目标可运行原子排序；不能先让孩子运行，再由用户态删除权限。先完成的配置纳入发布校验，发布后到达的配置拒绝。该构造授权不允许普通复制/转授/继承，不能通过副本跨过失效点；若后续确需委托加载器，须另行定义受限协作方式。加载器当前为调用者库内代码，不需独立管理进程。

start 失败且没有发布时保留有效构造权限，允许修正或撤销。发布成功后旧构造 Handle 不再授权任何操作，调用者可本地清除保存值；内核同步回收该表项并推进代次。PID 在创建时已可取得，父子关系与退出记录不依赖这个 Handle 存活，不能要求发布后再用失效 Handle 查询 PID。重复发布使用旧 Handle 必须安全拒绝，错误细分随 ABI 冻结。

父进程死亡与发布在内核有明确顺序：死亡先提交则禁止发布并进入准备清理；发布先提交则保留已发布孩子并转交孤儿关系。正常返回前孩子已退出也不丢 wait 结果。exec 替换同一实例及镜像代次后，旧准备操作不能继续作用新镜像。

这里的权限失效不级联撤销孩子已合法取得的独立内存/IPC 引用；构造时创建的临时写映射、加载别名和暂存授权须在发布前按封存及继承规则清理，不能借它们保留对孩子私有内存的后台写入路径。明确共享的可写内存按共享契约保留，不声称发布后父对共享内容绝无影响。

#### 示例：spawn 成功后父不能继续改孩子现场

A 创建 B，取得 B 的 PID 和仅供准备的管理 Handle，加载镜像并配置入口。start 发布 B 的同一原子点使准备权失效，即使 B 随即运行、退出，A 仍按父子关系 wait。A 以旧 Handle 再 configure/map/destroy 均失败；A 可否向 B 发信号取决于独立信号权限，不因曾创建 B 而获强制终止权。

若加载阶段失败，B 尚未发布，A 可撤销准备；若 A 此时死亡，则由内核和参与服务的记录收尾，不依赖 A 再运行。init 对服务的明确监督授权独立保留，不套用普通构造权的自动失效规则。

### 普通构造接口的权限与提交表（语义收口）

普通构造权不是监督权，不因父子关系获得发布后任意配置权限。

| 操作 | 所需权限与目标 | 成功提交 | 失败后的状态 |
| --- | --- | --- | --- |
| create | 本地受限创建授权；父关系为调用者，普通孩子保持原集合与可信凭据 | 预付栈/Life/Acct/结果与请求等必要记录，发布唯一身份及本次构造授权，孩子不可运行 | 不发布结果，退还本次已取得资源/额度；不能留下无人持有的半成品 |
| configure | 本次目标的准备权限，且是普通新建未运行实例 | 全量校验后替换初始入口/栈/Boot现场 | 保留原先合法配置，不改变父关系、凭据或预算 |
| start | 本次目标发布权限，且是普通新建未运行实例 | 重查必要配置/资源状态，原子撤销普通构造权限并使目标可调度 | 仍未发布，准备权保留，可修正或destroy；STOP等原因独立 |
| destroy | 本次目标撤销权限，且尚未发布 | 先关闭配置/发布入口，再有界拆除本地准备；不生成普通wait退出结果 | 参数/权限/阶段校验失败不改变目标；一旦撤销提交不能因后续清理滞留恢复可发布 |

create 的逻辑成功结果同时包含目标完整 PID 与调用者本地构造 Handle；寄存器为状态a0/x0、Handle a1/x1、PID a2/x2。PID 便于父登记关系，Handle 证明准备权限，两者不能互换。成功返回后孩子仍不可运行，运行库在短本地临界段稳定登记；若此时调用者死亡，内核已记录的构造归属负责撤销，不依赖用户态先保存返回值。

普通创建不能指定任意父、集合或特权凭据；可调整属性仅限创建授权允许范围，越权字段拒绝而非静默忽略。可信管理创建若确需另配身份/预算，仍校验显式管理权限，不凭 uid0或调用者名init豁免。配置中未知/保留字段拒绝，所有数值及容量先验证溢出和编译上限。

configure/start 不能用于 fork 的未发布克隆或 exec 准备视图；它们各有专门提交状态。区分依据是内核保存的构造来源与阶段，不是用户 config 中声称“普通创建”。需要持续监督服务时由管理授权明确建立独立范围，不能把普通构造 Handle 发布后偷偷升级为监督权。

destroy 允许自己的内核清理在独立栈上分批执行；在短提交点之外可调度，必要时把跨返回/退出责任转交预付记录。成功只表示本次构造已不可发布且规定本地拆除完成，外部持有的Mem/Rq/观察/DMA按各自条件存活，不保证物理页全部归还。服务清理不得要求内核等待外部RPC；已撤销目标的服务准备通过生命周期终结独立收尾。

所有目标操作固定完整实例和准备归属，在最终提交前重查阶段；父死亡、start和destroy原子排序。只有一个能先取得发布或撤销结局，迟到操作不作用于同槽新实例。具体无权限/陈旧/阶段错误的可见区分须兼顾信息隔离，错误名/数字不在本表提前确定。

#### 示例：start 与 destroy 竞争

A 对未发布B先调用start，成功即撤销其普通构造Handle；之后用旧Handle destroy 必须失败，不能删除已运行B。若destroy先提交，B进入撤销中，迟到start也不能发布。若start校验因Boot映射缺失而失败，没有发生发布，A仍可修复配置或destroy。三种情形都不靠用户维护“started”布尔值判断。

### create 调用契约（已确定）

create(auth, config) 校验创建管理授权，config 为有界定长创建属性，包含预算、资源容量及凭据等，不接收程序路径或 ELF；具体字段在共享 ABI 一次定义。
成功产生唯一实例身份、独立 Acct、空用户地址空间、有上限的资源表及预付请求/退出/信号/Op 记录；所有用户可见初始现场为确定值，但尚无完整入口/栈/启动环境，状态不可运行且不进就绪队列。
成功状态为 0，独立结果字段返回调用者本地的目标构造 Handle 和完整 PID；PID 不是管理授权。构造 Handle 的操作范围和准备地址空间授权关系在 ABI 表明确，不以裸 PID 替代。
任一预付池、容量、凭据或预算检查失败，回滚本次表项/页/引用/账目，不发布半成品 Handle。创建实例占配额，放弃时须 destroy。
create 后由获权创建者通过用户态加载器构建镜像/栈/Boot、配置现场、安装允许资源并准备标准流/作业关系，再通过 start 原子发布；普通与系统管理创建的权限边界不同。

#### 示例：装载失败

init create 成功取得管理 Handle，加载 ELF 时发现格式错误；该实例从未运行，init destroy 并收尾本次取得的页、授权和预付记录。若已 start 则不得使用 destroy 假装回滚创建，须按 terminate/退出协议处理。

### create 属性的最小边界（已冻结）

创建属性方案仅包含下表的定宽数值，不接路径、ELF、用户栈、fd数组、权限列表或任意父PID。具体整数宽度、字段偏移和保留空间在共享头一次冻结，不增加版本兼容分支。

| 属性 | 含义 | 普通创建约束 |
| --- | --- | --- |
| memlimit | 孩子Acct常规内存上限，以页计 | 不超过创建授权允许的单实例上限，同时服从集合总额 |
| exec_limit | 孩子Acct替换峰值上限，以页计 | 不低于memlimit，不超过授权峰值；不增加集合共享峰值 |
| resources | 可用本地资源槽上限 | 不超过授权及编译容量，足够容纳内核规定的必要启动授权 |
| pending | 可接受未回复CALL上限 | 至少保留即时分发名额，不超过授权、CONFIG_PENDING_CALLS和服务声明容量 |
| ruid/euid/rgid/egid | 初始真实/有效身份 | 必须与调用者可信身份一致；只有显式身份配置权限可选择不同值 |

身份字段不能靠值0表示“继承”：uid/gid0本来就是有效身份。普通运行库填写当前已知身份，内核仍独立核验；不能因用户填写uid0就授予内核管理权。若调用者没有身份配置权，指定不同凭据直接拒绝，不自动降级或静默继承。首轮不借此支持运行期setuid、setuid文件或补充组。

父关系由内核取当前调用者，集合及可创建权限范围由创建授权固定，不由配置传任意集合ID；管理者选择已获权的创建授权可构造受管服务，不能凭服务名绕过检查。memlimit是单实例用量上限，不是提前扣走同等物理页，也不复制出新总额度；实际栈、页表、预付资源及COW承诺仍按实际取得/承诺计费。

resources/pending用于下调可用量，不改变编译时表布局或运行期扩表。首轮出站请求及信号上下文预留继续按CONFIG_OUT_REQUESTS/CONFIG_SIGDEPTH固定预付，不增加一个可被普通创建者设成过小而破坏取消/信号进展的属性。池容量、内存页、运行槽和集合实例限额分别检查，属性合法不保证资源一定足够。

上述属性没有0取默认值的隐式规则；运行库可按本实例创建授权的明确策略填入值，字段0按实际数值校验。创建授权是否允许继承、资源可否转授、监督目标范围等属于内核授权策略，不在用户配置中接受任意权限位清单。复杂策略仍由init事先配置，普通create不逐次RPC请求批准。

#### 示例：孩子上限不等于额外总额度

集合上限256页，A与其他成员当前已占200页；A有权创建memlimit=128页的B。create仅为B预付实际需要的栈/记录等费用，不直接再承诺128页，也不使集合变成384页。B后续分配仍逐次受剩余集合额度约束；若create自身必要开销已超过剩余额度，则此次创建失败。

### 普通孩子CREATE上限（2026-11-16用户确认）

创建权低位CREATE_USE=1、CREDENTIAL=2、SERVICE=4。普通孩子获得一份绑定同一Set的CREATE_USE，清除CREDENTIAL/SERVICE/GRANT；单实例内存、exec峰值、资源槽及pending上限全部夹到本次孩子Createarg，而非保留创建者的更高上限。该动作是创建事务内的专门继承，不是运行中grant，不要求父CREATE带GRANT，也不增加Set总预算或实例额度。授权持Set的独立策略引用，源授权撤销不级联撤销已合法安装的孩子授权。

例：A的创建权为128页/256页峰值、16资源槽、pending=2，创建B时指定64/128、8槽、pending=1。B的创建权只能再创建不超过64/128、8槽、pending=1的后代，申请65页或pending=2为DENIED；B不能恢复身份配置、SERVICE或再授予位。A撤销自己的CREATE不撤销B这份授权，B退出/资源表撤销时解除自己的Set引用。三代实际分配及未收取Life仍共同受原Set限额约束，不把继承授权当新总预算。

### configure 调用契约（已确定）

configure(target, config, reserve_resources) 校验目标管理授权，仅配置从未 start 的实例的初始用户执行环境：入口 `_start`、对齐的用户栈顶、只读 Boot 地址和按启动规则确定的初始信号配置。预算/凭据/授权/作业关系不通过此接口顺便变更。
参数为一次复制的定长结构，完整检查后整体替换；失败保留上次完整有效配置，不发布半套现场。停止中的已运行进程不能用 configure 重新装载为另一程序。
内核构建规定的用户态特权状态，调用者不能直接填写特权控制位；入口首参数为 Boot 地址，其他通用及 FP/SIMD 初始状态确定且无旧数据。
configure 检查当前必要地址/类型/权限，但不运行目标、不代表服务 READY。start 重新验证执行前提，不能只信任一个“配置完成”布尔标志。
reserve_resources为0..8，连同Config整体替换，给目标镜像预付受限资源回复的保底空槽，发布前不足则失败且保留旧配置。发布后未用槽留至镜像结束、资源回复消费/归还规则见08；不是启动未完成状态，不需要execready释放。

### 初始现场的最小参数（已冻结）

确定固定输入只保留下面六项，每项用明确64位ABI字段表示；具体C布局/偏移随共享头冻结，不接受可变扩展链或任意寄存器数组。

| 字段 | 含义 | 主要校验 |
| --- | --- | --- |
| entry | 目标用户入口地址 | 合法用户VA、架构要求的入口对齐、目标当前可执行；不是内核符号或任意特权地址 |
| stack | 初始用户SP | 架构ABI对齐、用户范围、启动必需栈区可写且不可执行；不能只查SP数值本身可读 |
| boot | 目标Boot区域起点 | 目标地址空间内可读、只读映射，不能直接使用父地址空间指针 |
| bootsz | Boot区域总字节数 | 非零、配置上限、boot+bootsz不溢出，和Boot头声明总长一致 |
| sigmask | 初始应用信号掩码 | 只含支持位，不能屏蔽KILL/STOP；不是库内部临时掩码 |
| sigdefault | 要求恢复默认动作的信号集合 | 只含支持位；用于直接spawn的显式默认动作属性，不安装用户handler地址 |

entry只是经检查的用户入口，不要求内核识别ELF中的 _start 名称。argc/argv/env、服务Handle及标准流初始化信息都在Boot，不在configure重复列一份；预算、身份、fd内容、MMIO/IRQ、进程组/终端和页表配置不塞进此结构。CPU特权位、通用寄存器初值及FP控制状态由内核按架构合法初始值构造，不允许用户传一整套原始状态寄存器。

普通新建实例在create时由内核固定继承信号基线：保留源显式IGNORE，捕获动作转DEFAULT，pending为空，应用掩码从可信源现场取得；初始init使用独立默认基线。configure从这份基线计算结果，再应用sigdefault与显式sigmask，不在反复configure中累计清除动作，也不从旧地址空间复制handler指针。该基线用于直接装载新程序，不适用于fork保留handler的专门复制路径。

结构先复制到内核私有临时区，再完整校验、构造新现场并整体替换；失败不部分安装入口/信号动作。内核后续依赖的地址/长度/掩码按已复制内容保存，不保留创建者结构指针。Boot自身是用户启动信息，不能因其声称某Handle或身份就赋权；csu仍需检查内部偏移、字符串与实际资源，内核不解析FS协议或文件路径。

start提交前重新验证入口、栈、Boot映射和封存等必要条件；configure成功后unmap/revoke或更改准备资源不能靠旧校验混过去。暂不把configure的成功当整个ELF或用户程序行为正确的证明。

#### 示例：失败保留上次配置

第一次 configure 的入口/栈/Boot 有效，第二次请求的栈顶不符合架构 ABI 对齐，则第二次失败且保留第一次现场。若随后 unmap 原代码区域，即使曾 configure 成功，start 仍须拒绝。

### start 调用契约（已确定）

start(target) 校验目标管理授权，仅允许从未启动且未销毁/退出的实例。重新检查入口执行权限、用户栈必要范围/对齐、Boot 只读区域及参数、作业关系和启动事务前提；VM_BUSY/封存或其他冲突 Op 尚未结束则不能发布。
不解析 ELF/路径、不检查服务业务就绪；获权创建者的用户态加载器负责装载内容，服务 READY 独立于 start。全部检查后原子标记已启动并加入就绪队列，不能暴露半发布关系或重复入队。
成功返回状态 0，表示目标已允许调度，不保证其尚未运行或仍存活；失败保留未启动状态，管理者可修正或 destroy。重复 start 返回状态错误。
单进程 start 不隐含作业组/前台的跨服务原子提交。sh 自有作业屏障方案使用 ready/gate 管道，见 [启动与作业](07-boot.md)；不将已运行 fork 成员当未启动实例，也不预先冻结 jobstart syscall。

#### 示例：start 回复前子进程已退出

init start(child) 成功后调度器先运行 child，child 立即 exit，init 随后恢复执行。退出记录仍按完整身份保留，init 不必在 start 返回后才登记观察；既有预付记录和确认协议保证结果不丢。

### 创建与启动（已确定）

获权创建者创建不可运行实例，再按授权配置地址空间、镜像/栈/参数、现场和资源；普通创建不能自行提升预算或身份。
只有 start 验证必要配置并成功发布后，进程才能进入就绪队列及接收请求。
start 前失败可销毁未发布实例并回滚；start 后只能走终止、退出、回收协议，禁止按构造失败直接拆除。
未启动实例也占用进程槽和预算，必须有上限及放弃创建的清理入口。
start 不代表服务就绪：服务完成初始化后向 init 发送 READY，init 再发布连接、启动依赖者。
READY 是用户态协议，不增加内核服务对象；初始化失败退出并报告原因。

### destroy 与 terminate 调用契约（已确定）

destroy(target) 与 terminate(target) 均校验调用者本地目标管理授权，不能只凭 PID。destroy 仅适用于从未启动实例，terminate 适用于已运行过的就绪/运行/阻塞/停止实例。
destroy 通过有界 Op 取消/协调冲突配置和映射事务，拆除目标地址空间、授权及预付资源；完成后返回成功，不生成程序运行退出状态。仍被外部引用或 DMA 固定的 Mem/Acct 按独立生命周期保留，不以容器拆除强制释放。
terminate 原子提交 EXITING、阻止目标再返回用户态，撤离等待并进入请求/地址空间/授权清理；提交后禁止新调用/授权安装/配置。返回成功表示强制终止已提交，不等于已收取退出记录或 DMA 安全停止。
同一完整目标在 EXITING/EXITED 时重复 terminate 返回成功；必须仍校验管理授权和身份，陈旧 Handle/槽复用拒绝，不能误杀新实例。未启动实例使用 destroy，不把两接口混为通用删除。
SIGTERM 是可捕获/忽略的普通信号，terminate 是强制管理机制，不等待用户处理函数配合。

#### 示例：创建失败与运行后故障

create 后仅映射部分镜像即加载失败，使用 destroy 并确认其清理完成；若 child 已 start 后阻塞于 fs，则使用 terminate，等待内核退出记录并确认，而非 destroy。旧请求/共享缓冲或设备仍有引用时，必要记录继续独立保留并计费。

### 父直接 wait 与结果消费（已冻结）

普通 wait 直接进入内核：验证父子关系与选择条件，查找可领取的退出/停止/继续结果；有结果则交付，无结果但仍有匹配孩子则按选项非阻塞返回或登记等待，无匹配且可由调用者收取的孩子则返回ERR_CHILD=22，libc映射ECHILD；有匹配活孩子而无结果时WNOHANG成功返回PID=0且其余输出清零，阻塞调用继续等待。检查结果与登记等待在同一临界区，不能先查询再单独睡眠。观察者查询与父结果消费分开，监督权限不自动成为收取权。

方案取消旧 init wait RPC 和独立 waitack。与可能取消/丢回复的服务 RPC 不同，内核可将“选择结果、保存本次返回、消费对应状态”作为一次交付提交。优先讨论有界固定结果，包含孩子完整身份、事件种类/原因及必要状态，不把长可变列表引入 wait。多结果由调用者循环领取。

| 交付阶段 | 信号/退出的处理 |
| --- | --- |
| 仍在等待，尚未领取 | 可按等待语义中断/重启，原子摘除等待；孩子结果仍可由合法收取者领取 |
| 已提交本次交付 | 返回值保存于父执行上下文，不能再改为 EINTR 或重做消费；信号返回后继续原成功结果 |
| 父 STOP | 保留等待或已提交结果，完成事件不绕过 STOP |
| 父 KILL/退出 | 等待撤离；尚未消费的孩子关系/结果原子转交孤儿接管者，已消费的结果不再复制一份交给 init |

确定原生 wait 只交付固定寄存器结果，不接用户输出指针；内核原子保存本次返回并消费，不新增 wait 专用用户复制事务。包装层保存结果并编码标准状态后，通过既有受检查复制写入用户 status/info。waitpid 的空 status 表示忽略状态并正常收取；其他包装的空指针规则单独核对。

用户输出失败返回明确错误，但已收取结果不恢复，不自动再次 wait，也不承诺还能重新查询。允许部分用户缓冲写入后失败，不声称原子输出；受检查复制仍必须处理跨页、COW、封存和别名约束，不能用普通 memcpy 触发用户异常代替 EFAULT。原生参数或权限校验失败与此不同，不消费结果。

依据：[Linux wait_task_zombie/kernel_wait4](https://github.com/torvalds/linux/blob/master/kernel/exit.c) 普通收取路径先消费/回收，随后 put_user 写 status，写入失败可以返回 EFAULT。这不是对所有 Unix 或 POSIX 条文的结论。此前“复制成功才消费”的方案增加映射稳定、COW 及提交协调，本轮确定撤回；具体标准错误与状态编码仍待核对，不能据此宣称完整兼容。

固定逻辑结果包含孩子身份、事件种类和退出码/信号/必要标志；成功有结果、非阻塞无结果、失败分别明确表示，无结果时其余输出清零。寄存器分配及kind/code由06确定，libc按15转换wait状态，不直接用内部 enum 布局作为 ABI。

#### 示例：status 指针不可写

A 原生 wait 已收取 B 的结果，包装层向不可写 status 复制失败并返回 EFAULT。再次 wait 不再返回 B 的同一结果，不能为补救输出错误偷偷领取 C 的结果。status 为允许的空指针则忽略状态并成功返回 B 的 PID。服务观察及 B 遗留资源清理不受用户输出错误影响。

不消费观察选项若纳入范围，只读取而不收取；不能偷用“查询后独立确认”的旧路径代替普通 wait 的原子领取。停止/继续可按既定规则合并保留当前可报告状态，退出结果不能被覆盖；选择对应状态版本并交付时只消费该版本。

持久报告与实际停止位分开：每个存活Life只保存最新一份未消费的STOPPED/CONTINUED报告，WUNTRACED/WCONTINUED分别选择相应种类；不匹配选项不消费它。收取STOPPED报告只清这份报告，进程仍停止；收取CONTINUED不解除父收取责任或释放组/Set/Run引用。已经停止时再次停止、已运行时再次继续均不产生新状态版本或重复报告。STOP→CONT在父收取前合并为CONT，CONT→STOP合并为最新停止原因；最终退出总是覆盖未收取的临时报告，且必须继续可收取。

Life仍128字节，最后一字节保存stopped，存活期未消费报告使用内部reason/code（STOPPED=4、CONTINUED=5），终结期仍为EXIT/SIGNAL/FAULT=1/2/3；原生wait显式转换为既有WAIT_STOPPED/WAIT_CONTINUED/WAIT_EXITED，不暴露内部编号。QUERY_LIFE的终结原因/码在存活期保持0，不把临时报告当作终结结果。选择/消费之间不允许调度或IRQ开放，父的内核返回记录在同一临界区取得该版本；消费后新变化独立递增并形成新报告，不修改已交付副本。序号不回绕：停止/继续保留最后一个u64版本给最终退出，到保留边界时返回OVERFLOW且不变更任何状态/报告；重复无变化操作不占版本。

例子：孩子发布后sequence=1；STOP产生(2,STOPPED,STOP)，CONT在收取前覆盖为(3,CONTINUED,0)。只带WUNTRACED的父此时无新结果，带WCONTINUED取得版本3且仍保留最终收取责任。随后STOP产生版本4，退出产生版本5并覆盖它；无论父此时是否请求停止报告，最终只收取版本5的退出。若父先取得版本2副本、孩子随后继续，版本2输出不变，版本3另待下次收取。父死亡时，仍未消费的报告随既有逻辑孤儿接管转给init，旧父PID复用不能夺回。

#### 示例：孩子退出与父入睡竞态

A 调用 wait 时尚无退出结果，内核原子检查并登记等待。B 此后退出，发布结果并唤醒 A；若 B 先退出，A 在检查时直接领取，不会漏掉事件。交付成功后信号到达，A 仍返回 B 的结果；若信号先中断尚未领取的等待，B 的结果保留。父 wait 不等 FS 清理或 DMA 停止，相关旧 Life/Acct/观察引用独立存活。

#### waitpid 的信号重启（已冻结）

用户已接受：仅对尚未收取结果的阻塞 waitpid 启用 SA_RESTART。捕获信号先中断等待时，原子撤离等待而不消费任何孩子结果，先递送 handler；未设 SA_RESTART 则返回 -1/errno=EINTR，设置后重新进入内核，按原调用的选择条件和选项检查当前合法孩子/结果，再领取或登记等待。重新进入不是恢复已退栈的内核 C 续点，也不需要服务业务操作号或 RPC 收尾 Handle。

重新检查不保留独占的孩子结果名额。handler 若已通过 waitpid 收取唯一匹配孩子，外层重启后正常得到 ECHILD，不能再次交付旧结果；handler 的收取属于独立调用。原生 wait 已经原子保存并消费的结果则归外层执行上下文独占，handler 不能再次领取；handler 后只继续编码/复制原结果，不再 wait。复制 status 失败的 EFAULT 及已消费语义保持前文规则。

WNOHANG 不登记等待；检查提交时有结果则正常领取，有匹配孩子但暂无结果则固定返回0，无匹配孩子为 ECHILD。已经固定的0/成功/失败不因随后信号变成 EINTR，也不因 SA_RESTART 再次查询。SIGCHLD 仅提示，不按提示次数领取；STOPPED/CONTINUED 的消费仍针对已选状态版本，不抹掉最终退出结果。

纯 STOP 保留原等待/已提交结果，CONT 后继续；可捕获 CONT handler 的递送另按捕获信号排序。KILL 不再回用户，由现有死亡/孤儿协议接管尚未消费的结果；已消费结果不复制给 init。

示例：A 等待唯一孩子 B，尚未收取便被捕获信号中断。handler 的 waitpid 收取 B；无 SA_RESTART 的外层返回 EINTR，有则重新检查并返回 ECHILD。反之，若外层先收取 B，再递送 handler，则 B 的结果保存在外层上下文，handler 不能领取第二份；外层恢复后返回 B，即使原 status 此时非法而导致 EFAULT，也不重新收取。

pid=0固定原接受时PGID，原生返回见06；完整标准审计仍是交付验收，不冒充已经通过。

### 退出结果与回收（已确定）

正常 exit、用户异常和管理者终止汇入统一退出路径：停止接收/调度、摘除出站等待、取消指向本进程的调用、
使本进程尚未回复的请求失效，按引用及 DMA 安全条件清理资源，最后发布退出结果。
退出时不为 wait 保留整个用户地址空间；方案在既有 Life 保存完整身份、父关系、退出原因/码及是否已收取，不新增独立退出对象或 init 结果表。

运行槽在自身资源已安全分离后可复用，未收取结果仍由旧 Life 保留；不能以运行槽已是新代次就删除旧孩子结果。wait 按父关联的 Life 查找完整孩子身份，不仅通过当前运行槽查 PID；指定旧孩子 PID 仍可领取旧结果，不能误匹配同槽新实例。数据结构和有界查找成本随布局冻结。
父进程退出时由内核原子转交孤儿关系给 init，结果只能由当前合法收取者消费。
旧身份不得解析成复用后的新进程；init 自身退出视为首版系统级故障，记录诊断并停止。
退出记录收取与设备安全收尾分别定义；有未停止 DMA 的页不能因结果已收取而回收。

## 调度与性能

采用 FIFO 就绪队列和轮转，reply_recv 合并陷入；直接交接捐赠当前调度预算的剩余部分，不重置预算。
调度预算的来源及剩余值随一次直接交接链传递，消耗记到同一预算；链断开/耗尽返回普通轮转，实际运行时间另外计入运行进程统计。

已确定的调度原则：IRQ 上半段只记录并唤醒，不在处理函数中直接执行用户态驱动；统一调度出口选择进程。
仅等待接收的驱动因可交付事件变为就绪，已就绪/运行的进程不重复入队，阻塞下游的进程只保留 pending。
直接交接不能重置或凭空增加时间预算，预算耗尽回到普通轮转；异步完成仅唤醒，不附赠新预算。
驱动每轮工作量有上限，剩余工作保留本地待处理状态并让出机会；通知仍屏蔽且有工作时不得直接睡眠。
首版保留轮转，不承诺驱动响应时限；是否增加优先级由后续测量决定。
同地址空间不重复切页表，批量映射统一刷新 TLB。
ASID、多核、异步共享环及零拷贝先不做。

验收既检查正确性，也测短 RPC 往返、饱和吞吐、共享数据传输、排队公平性及内存占用。
当前用户要求先讨论，尚不运行性能测试；QEMU 数值不代表真实硬件性能。

### 单核并发与临界区（已确定）

单核不代表无并发：IRQ、设备 DMA、异步完成及信号处理分别遵循明确的同步边界。
Rq 状态/摘挂链、就绪/等待队列、引用归零与回收、事件检查与登记等待在短关中断临界区内原子提交。
函数注明调用方已保护或内部保存/恢复 IRQ 状态，不能恢复成与进入前不同的中断状态；临界区不等待、不做大额分配/无界扫描。
长 Op 在短提交之外允许 IRQ，IRQ 只置事件/请求调度，不在任意内核 C 深层切用户进程，统一安全出口执行选择。
内核陷阱入口区分用户寄存器与内核临时现场；DMA 不受 CPU 中断开关约束，独立执行屏障/缓存协议。
用户态单线程服务跨异步等待仍会交错：继续前重查节点代次/版本/操作状态，不因单线程省略生命周期校验。
File 偏移操作串行，元数据事务按节点取得修改权，不持全局 VFS 锁等 I/O；取消/回复/完成统一转换，重复完成拒绝。
运行库共享表修改短暂屏蔽可捕获信号，不持锁跨处理函数或阻塞；不为未实现 SMP 预建空锁框架，但状态归属明确。
验收受控注入 IRQ、异步完成、取消与信号交错，检查临界区不变量及最长屏蔽时间，不只测顺序路径。

- proc：构造、授权、退出与回收。
- sched：就绪队列、时间片、运行目标选择。
- ipc：调用、接收、回复、取消。
- event：事件位、IRQ 投递与确认。
- mem：物理页、预算、共享内存。
- vspace：映射、页表、安全访问。
- syscall：ABI 解码和入口检查，调用具体机制。
- HAL：硬件抽象契约；内核必需的 CPU、地址空间、定时器和 IRQ 接口位于 include/hal，不接管设备协议。
- Arch：kernel/arm64 与 kernel/riscv 实现陷阱、寄存器、页表、定时器及 PLIC/GIC 等操作；图中的 Arch 是层名，不是目录名。
- kernel/boot：解析设备树并整理启动资源；普通设备协议由用户态驱动处理。
- include/{arm64,riscv}、lib/libsys/{arm64,riscv}：架构专用头文件和用户态底层架构适配。

具体API/编号、用户地址布局和容量已在01/06首版规格固定，实现须按该规格验证。

### 浮点与 SIMD 现场（已确定）

ARM64 保存/恢复通用、浮点/SIMD 寄存器及控制状态；RV64 保存通用及目标配置启用的 F/D 状态；首轮不启用可变长度向量扩展。
编译目标/调用 ABI/CPU 能力必须一致，不支持的用户指令作为用户异常处理，工具链不得静默生成未支持扩展。
新进程全部可见现场初始化，切换、信号帧与 sigreturn 覆盖已支持扩展状态，防止串值和跨进程泄漏。
内核构建禁止浮点/SIMD 使用，含编译器自动优化及 freestanding 内存例程；首轮不采用惰性保存。
普通 syscall 不必每次完整复制扩展现场，但切换或信号快照前必须保存，HAL 明确现场所有权及有效状态。
现场/信号帧大小计入创建预付预算；汇编偏移、C 大小和对齐使用共享定义与静态断言，不能仅扩 C 结构不改汇编。

- [ ] 两进程不同浮点/SIMD 哨兵经抢占、IPC、信号恢复保持正确，SIMD 内存操作覆盖。
- [ ] 新进程现场无旧数据，CPU 特性/ABI 不匹配明确失败，检查内核产物没有非预期浮点/SIMD 指令。

- [ ] 建立启动镜像、依赖顺序、就绪握手和失败处理。
- [ ] 明确硬件资源发现、保留内存和设备授权；未知设备不授予任意物理访问。

### 有界内核操作与映射提交

长操作在独立线程栈执行并在明确检查点调度；跨调用/退出继续存活的引用、预算和清理阶段存入预付独立记录，不建立通用公开 OP。涉及活地址空间的分批映射事务须先设置 VM_BUSY，期间目标不能回用户态；完成页表/TLB 更新后提交或回滚。VM_BUSY、STOP、EXIT 独立，解除其中一个不能抹掉另一个。未发布地址空间可分批构建，临界区只覆盖短提交，不覆盖整块清零或全空间扫描。

退出/取消后清理继续有界，保留所有仍被访问的引用和预算；每步清理不依赖新分配，外部硬件无响应不阻止本地责任转交。验收覆盖最大配置操作的最长关 IRQ 段及调度间隔，逐阶段取消/STOP/退出不产生半发布映射或提前回收。

### yield 调用契约（已确定）

__sys_yield() 无参数，无额外管理权限；当前进程仍可运行，放弃本次剩余调度预算并进入普通就绪队尾，恢复执行后返回状态 0。
直接交接链中 yield 结束当前预算传递，不能重置捐赠预算插队；没有其他就绪进程时允许立即再次运行自身，不保证指定进程一定先运行。
统一调度出口仍检查信号、STOP、EXIT 及其他暂停原因，不因 yield 把不再可运行实例入队。
yield 不提供事件等待语义；驱动无完成事件、服务无请求时应阻塞于事件/recv，不通过 yield 忙轮询。

#### 示例：普通就绪队列

A 运行，普通就绪队为 [B,C]，A yield 后自身加入尾部形成 [B,C,A]，下一次普通选择为 B；若 B/C 均不可运行则 A 可再次被选中。

### 当前进程 exit 调用契约（已确定）

__sys_exit(code) 只结束当前进程，不接受目标 Handle，不要求管理权限；正常提交后不返回用户态。退出码宽度/寄存器扩展规则在 ABI 定义，不能用退出码同时携带无类别终止原因。
内核先保存正常退出原因/码并原子进入 EXITING，撤离等待、转交请求与资源清理，调度其他进程，满足自身清理条件后发布最终退出记录；独立共享/DMA 引用仍依已有协议保留。
原生 exit 不执行用户回调、stdio 刷新或 fs close RPC，libc exit 在陷入前处理用户清理，_exit 直接进入内核。服务会话由所属服务根据可靠生命周期观察清理，不依赖已退出进程继续运行。
exit 与 terminate 共用内部退出状态机，区别在目标、权限与原因。最终原因只允许首次终止提交：管理终止先提交则正常 exit 不覆盖，正常 exit 先提交也不被迟到 terminate 改写。

#### 示例：exit 与 _exit

应用 exit(0) 先由 libc 执行有界清理和退出回调，再 __sys_exit(0)，之后不再执行任何该进程用户代码；_exit(0) 跳过 libc 清理，但不跳过内核及所属服务的资源/会话清理。

### 退出完成与清理完成（已确定）

终止提交、退出结果发布、关联资源全部清理是不同完成点。退出结果在进程不能再回用户态且最终原因固定后发布，不等待其他进程解除共享页引用或设备 DMA 停止。
父进程 wait 可取得已发布结果；结果稳定保存在 Life 且满足运行资源拆除条件后即可复用进程槽，不要求 init 中转确认。剩余 Rq/Mem/Life/Acct 独立保留、继续计费，不能因此提前释放。
退出原因一经发布不可改写，后续清理失败保存在 Life 清理状态。管理查询区分已退出/清理中、隔离未释放及清理完成，不把所有情况简化为已删除。
正常关机须另行检查设备安全停止与持久化收尾，不因进程都退出而宣称安全。无法停止 DMA 可使资源保持有界隔离，但不能阻止已退出进程的退出结果交付。

#### 示例：blk 退出但 DMA 未停止

管理者终止 blk 后，内核禁止其继续执行并发布固定原因，父进程可 wait；init 随后停机/复位设备。成功后结清旧资源，失败则报告隔离页及清理状态，旧 Acct/Life 不被错误回收，也不让 blk 永远停在没有退出结果的状态。

### 退出原因与兼容状态（已确定）

原生退出记录明确区分正常退出/信号终止/用户异常/管理强制终止，分别保留退出码、信号或受限诊断原因；不能只用一个无类别整数混合表示。
正常退出按标准转换 WIFEXITED/WEXITSTATUS，信号终止转换 WIFSIGNALED 等状态。用户异常按冻结的异常分类映射 SIGSEGV/SIGILL 等，同时保留原生诊断；管理强制终止在 POSIX 层表现为 SIGKILL，原生保留管理原因。
具体异常映射及原生退出码宽度在 ABI 中一次定义，不把所有硬件陷阱映射为同一个信号。记录不向普通 wait 暴露完整寄存器、内核地址或他人私有状态。
停止/继续是独立状态事件，不是假退出；仅最终退出进入一次性退出交接。首轮不生成 core dump，不设置已生成 core 的状态位。

#### 示例：相同数值不表示相同退出原因

exit(2) 为正常退出码 2，SIGTERM 为信号终止，非法内存访问为用户异常，init terminate 为管理强制终止；四者具有不同原生原因，shell 按兼容状态区分正常返回和信号结束，诊断可查询授权范围内的原生详情。

### fork 的进程语义与发布（新增设计方向）

fork 纳入本轮设计目标：公开 pid_t fork(void)，成功父进程取得子 PID、子进程取得0，二者从同一 fork 调用之后继续；失败父返回-1/errno，不能把已发布子实例报告为未创建。fork 不经过 `_start/main` 重新启动。
子进程有新 PID/Life/Acct/资源表/页表及预付上下文，父子关系、组/会话/控制终端及凭据按继承规则建立，CPU统计从新实例起算；可运行发布前全部准备完成。
与 spawn/exec 区分：fork 继承信号动作及合法handler/trampoline、当前有效掩码，不复制父 pending；exec 才按标准重置捕获动作。父用户地址在 fork 子地址空间保留相同 VA，因此处理入口继承不是任意跨进程指针复制。
只有当前调用线程的执行延续进入子进程，不复制内核 C 栈/调度节点/父 Rq。当前仍单线程；从信号处理上下文 fork 时活动用户帧、外层被中断库状态及返回现场如何重建须明确规格，不允许丢掉上下文或误接管父请求。
父进程 libsys 直接协调 FS 继承与发布；内核检查既有创建权限/预算并提供受保护的自身克隆及提交机制，不解析文件协议。
父进程不得在快照期间修改自身地址空间或库元数据；使用短本地准备及内核安全暂停/有界 Op，而非长时间关 IRQ。发布前失败逆序补偿，发布后按正常父子退出/等待处理，不伪装为从未创建。
fork 是经授权和预算限制的专门继承事务，不赋予普通进程任意 grant/管理其他进程的权限。管理权、MMIO/IRQ/DMA及全局时钟权限不默认继承，服务/驱动 fork 的范围必须明确。

#### 示例：同一调用返回两次

应用 pid=fork()，父得到孩子正 PID，子得到0；子可先运行并退出，父仍能 wait 获取结果。孩子不是从 main 重新执行，FD_CLOEXEC 也不在 fork 时关闭；子尚未发布时继承失败，父仅得到失败且无可等待的半成品。

### 父进程直接协调 fork（已冻结）

父直接使用forkprep/forkcommit/forkabort，准确调用号和布局见06，不新增通用公开OP。

1. libsys/所适配 libc 完成 fork 前本地准备，固定允许继承的资源清单；FS 为父准备稳定的 fd/cwd/root/umask 继承快照并持有所需引用，快照令牌绑定可信父身份及操作序号。它不是父全局 I/O 排空屏障，也不冻结共享 File 偏移。
2. 父直接进入自身克隆原语。内核保存此处用户陷阱现场，在父不能执行用户代码期间有界建立 COW、子地址空间和继承资源；IRQ 与无关进程仍有进展。此阶段阻塞的是父，不是 init。失败先完成必要内核回滚，再返回错误。
3. 构建成功时父恢复到专用 libsys 返回路径，取得孩子 PID 及准备授权；孩子保存从同一原始调用返回并进入子修复路径的现场，但始终不可运行。父随后运行造成的私有页变化经 COW 与孩子隔离，不继续宣称父整个跨服务阶段被冻结。
4. 父请求 FS 等参与服务把快照中的引用绑定到这个未发布孩子，准备独立连接、传输区和子修复所需信息。请求需证明本次受限构造关系；不能凭自报 PID 为任意目标安装资源。发布前让全部必要服务状态达到可供孩子使用且仍可按未发布死亡收尾的阶段。
5. 父请求专用 fork 提交。内核重新核对父/孩子实例、准备归属和必要发布条件，原子解除孩子发布屏障并失效普通准备权；不等待外部 RPC、不在原子段分配。父在库恢复后向应用返回孩子PID；子只完成本地身份/库状态修复后返回0，首次后端操作才凭真实子source领取预付共享区。

孩子返回值的内部标志/寄存器与父准备结果必须无歧义，不能让子走父的继续准备路径。子现场不复制父内核栈、等待节点或旧请求所有权；专用 syscall 封装必须明确共享 COW 栈上的父子分支，不能让通用错误处理错误释放父资源。

父恢复后进行服务准备，不再要求整个准备期都处于内核暂停。libsys仅在短本地更新和CPU快照完整性阶段推迟用户handler，按本篇固定3层准备和08子修复执行；不得长期关 IRQ，也不得让子继承库内部临时掩码。STOP 可延迟父推进，KILL 必须触发独立清理；准备采用固定10秒绝对截止。

### 发布与清理责任（已冻结）

内核持有未发布孩子、父完整实例/镜像、准备阶段与自身回滚引用；服务持有归属明确的快照/子会话准备记录。父库负责正常提交/撤销，但不是唯一清理者。

孩子在发布前仍可能已有可用后端会话，因此“后端 ready”不等于“孩子已运行”，更不能因父暂时失联就独立决定发布。内核无需读取 FS 协议，且不能声称和服务拥有单个跨地址空间原子提交点：各参与者需要绑定孩子完整身份、准备结果及可靠的退出清理。本轮确定普通发布不引入服务就绪证明，也不要求父传 ready 布尔值；内核强制自身安全条件，服务独立负责身份隔离和终结清理。正确运行库等待全部必要服务准备成功再提交，以满足 fork 语义。

内核提交成功是孩子发布点。发布后服务不可因父退出撤销孩子合法引用；孩子自己的死亡才进入子资源清理。服务在发布后故障按普通连接失败规则处理，不能把已经运行的孩子回滚成未创建。父在库代码内尚未给应用返回不代表孩子未发布；提交结果与信号递送顺序必须确保不会重试产生第二个孩子。

#### 示例：FS 准备成功后父被 KILL

父 A 已取得不可运行 B，FS 持有绑定 B 的继承引用。若 A 死亡先于提交，内核撤销 B 的发布资格并收尾 COW/预留，FS 依 B 的终结状态结清会话；迟到提交失败。若提交先成功，B 保持已发布并成为孤儿，FS 保留 B 引用；不得按 A 的死亡清空 B 会话。两条路径都不依赖 A 再执行 abort，也不要求 init 逐次协调正常 fork。

### 普通发布不验证 FS 业务就绪（已冻结）

内核发布检查实例/镜像、构造权限、有效执行现场、地址空间/封存、预算、独立 STOP/EXIT 原因及自身事务状态等机制条件；不认识 fd 表，也不接收 FS ready 证明。libsys 负责等待必要服务准备完成并核验结果后才提交，原生提前发布不因此成为正确的 POSIX fork。

恶意或错误创建者可能提前发布一个缺少会话的孩子，后果只能是其合法授权范围内的初始化/访问失败；FS 必须拒绝无效、未就绪或错误 source 的会话，不能回退到父会话、猜测文件描述符或借用其他进程权限。若某项准备失败会导致跨主体访问或无人清理，则是该机制/服务契约的缺陷，不能用可信运行库补救。

服务成功回复前，完成其必要本地状态和清理责任登记，子实际使用所需引用可用；不以“已排队”回复准备完成。无需为得到一次 ready 再新增全局两阶段提交框架。成功回复不承诺服务永远存活，回复后到发布前服务死亡仍可能使孩子后续 I/O 失败；没有任何就绪证明能替代服务故障处理。

服务不得依赖父在孩子发布后继续确认或转交一次性准备状态才能接受孩子的首个请求。可用状态在准备成功回复前形成，孩子按可信自身身份使用；撤销/退出仍由内核生命周期清理。在服务准备过程中错误地提前发布时，不允许服务继续盲写已运行孩子的私有内存；使用普通授权和内核映射状态检查，或在调用者自己的暂存区形成结果，由受限构造路径安装，发布后安装失败并清理。

fork 发布、服务 READY 以及代码 SEALED 是不同条件：服务启动 READY 仍由 init 管理依赖，内核必须强制 W^X/封存及权限边界，不能因为 FS 就绪属于用户态就一并弱化这些条件。驱动设备就绪涉及 DMA 安全，仍按专门设备协议处理。

#### 示例：父故意跳过 FS 准备

A 已建不可运行 B，直接提交发布。若内核机制条件满足，可允许 B 运行，但 B 没有合法 FS 会话，读文件只能得到明确失败；不能自动采用 A 的会话或其他实例同号 fd。B 退出后其内核资源照常清理，不依赖从未建立的 FS 状态。正确 libsys 不走此路径，准备失败在发布前撤销并返回错误。

### fork 失败、信号与发布顺序（已冻结）

仅以孩子是否已经在内核发布区分可撤销准备与已创建进程，不以服务回复、父收到结果或应用看见返回值代替。内部逻辑状态为准备、已发布、撤销中、已撤销；它们不是新增公开 OP。发布和撤销请求在同一实例上原子排序，一方成功后另一方不能改写既有结局。

| 事件 | 发布之前 | 发布之后 |
| --- | --- | --- |
| 预算/池/FS 准备失败 | 停止发布，撤销未运行孩子及准备引用，父走失败恢复路径 | 不再作为 fork 创建失败；服务访问失败或子退出按正常语义处理 |
| 可捕获信号打断外部等待 | 固定本次阶段，先把库元数据恢复到可重入状态；按该等待的取消/重启规则处理，若决定放弃则禁止本次发布并进入撤销 | 保留已创建孩子及成功结果，恢复库状态后递送信号；不重做 fork |
| 父 STOP/CONT | STOP 不清除准备状态，不让父执行用户代码；CONT 后重查阶段/期限，不盲目重发 | 孩子不因父 STOP 自动停止；父成功结果保留，CONT 后继续返回 |
| 父 KILL/退出 | 内核禁止后续发布，孩子与服务准备独立清理，不等父执行 abort | 孩子按孤儿规则继续，父死亡不撤销孩子合法引用 |
| 准备超时 | 请求撤销并确定与提交的先后；未明确前不报告无孩子，也不另建一份重试 | 查询/保留原成功结果，不用超时伪造未创建 |
| 孩子被获权管理者终止 | 提交必须拒绝并撤销未发布准备 | 父仍取得成功的孩子 PID，随后 wait 取得退出结果 |
| 服务失联 | 未知业务结果先查询/隔离，禁止带不完整继承发布；预付清理责任仍保留 | 不回滚已运行孩子；旧连接失效，按服务故障及退出协议处理 |

正常 prepare/commit/abort 逻辑须幂等并固定孩子完整身份，不能以丢回复为由再执行一次克隆。父直接调用提交 syscall 时，提交结局及其返回结果在内核现场中一并确定；若之后插入信号处理，返回现场仍表示这次成功，而不是让库猜测是否已发布。父主动退出不要求向已经消失的应用交付结果，但不能改变孩子的发布结局。

不采用“整个跨服务 fork 期间屏蔽所有可捕获信号”的默认方案。仅短本地元数据更新允许临时屏蔽；外部等待沿用既有信号上下文及请求取消/收尾规则，handler 进入前不得暴露锁定或半更新的共享库表。子应继承的掩码取语义快照，不包含库临时掩码；父 pending 不复制为子 pending。fork 用户钩子与 _Fork 无钩子路径仍分别遵守运行库契约。

信号前已决定撤销时，先原子撤销孩子发布资格，再允许后续独立尝试；实际 FS/请求清理可在预付记录中继续，保留全部相关引用和费用，不强迫 handler 同步等待外部设备。新操作不能复用尚未归还的槽。

STOP 本身不是失败或隐式取消。已约定的准备期限若在 STOP 期间到期，可由独立内核/服务清理将事务转撤销并保存结局；这不能使 STOP 的父恢复运行，CONT 后父只读取实际结果。总准备期限固定10秒，由内核资格撤销和CPU/服务有界清理独立推进；STOP不阻止清理，也不使用户恢复。KILL 的死亡清理不依赖此期限。

#### fork 准备等待的中断返回（已冻结）

确定 fork/_Fork 不因单纯的捕获信号向应用返回 EINTR，也不以 SA_RESTART 决定是否从头克隆。安全点先固定本次准备身份/阶段并使库状态可重入，及时递送 handler；handler 正常返回且原准备仍有效时，继续同一孩子的准备或查询原服务操作。内部 IPC 的 INTERRUPTED 不直接作为 fork 的最终错误，已取消 Rq 不复活，已交付的服务操作按原序号查询/确定安全后继续。

继续原准备不表示无限等待或保证必然成功。预算不足、参与者失效、准备被撤销或既定期限届满仍按真实失败处理；先关闭未发布孩子的发布资格，再返回具体错误。已有总期限若适用，不因 handler 耗时重置；期限推进者按本篇首版规格执行。

克隆前信号只允许在快照一致性安全点交接；克隆后 handler 对父私有状态的修改经 COW 隔离，不重新生成子快照。父信号 handler 不因为尚未发布孩子而自动在该孩子执行。用户 fork 钩子不因内部中断重复运行；_Fork 仍不运行用户钩子。长克隆CPU快照阶段只在明确调度/STOP/KILL检查点切出；用户handler到完整快照或回滚端点后才递送，不留下半快照再进入handler。

发布提交成功则固定成功 PID，不受 handler 是否 wait 掉该孩子影响；外层只交付原 PID，不再创建。handler 若退出或成功 exec，外层不再恢复：未发布准备按原镜像终结取消，已发布孩子按既有父子/孤儿规则处理。

例子：A 已克隆未运行 B，等待 FS 子会话时被信号打断。handler 修改父私有变量后正常返回，外层查询 B 的原会话准备并继续，不克隆 C；B 保留原快照。若 B 发布后已退出并被 handler wait 收取，外层仍返回 B 的 PID，随后再次 wait 可无该结果，这不把原 fork 改成失败。

#### 示例：提交成功后信号到达

内核已发布 B 并保存 A 的成功结果，尚未让 A 回用户态时信号到达。A 进入 handler 前，返回路径必须处于可安全恢复的库状态；handler 返回后 A 仍完成原 fork 并取得 B 的 PID，不因信号再克隆 C。B 可能已退出，其结果仍可 wait。若 handler 直接结束 A，B 走孤儿规则。

#### 示例：父 STOP 时 FS 回复到达

A 在继承准备中停止，FS 回复可以被记录，但不能使 A 绕过 STOP 执行提交。CONT 后 A 检查原实例和保存的阶段：准备仍有效则继续，已被可靠撤销则清理后失败；绝不仅凭迟到成功回复复活已撤销孩子。

### 实现依赖顺序

服务核验/引用绑定/死亡清理见10，克隆提交ABI见06，信号端点及结构见本篇首版规格；普通发布方案不引入 FS 就绪证明。不采用 init CALL 检查点、由 init 交付父子返回或通用公开 OP。父同步等待长克隆仍需有界调度，但不再以 init 响应性为理由新增公开异步框架。

### 原生授权的 exec 策略（已确定方向）

原生资源策略与FD_CLOEXEC分开。适用共享Mem/通知等授权可由管理者明确配置EXEC_KEEP，普通进程不能自行扩大；该位是授权策略，不混同读写执行属性，具体grant结构随ABI冻结。
旧私有Mem、旧地址空间授权及RPC/REQUEST/旧执行Op不进入新镜像；自身分配/映射授权由新Boot重新配置。保留原生Mem授权也不保留旧VA映射，新镜像须显式map。
允许保留的本地授权维持约定数值/有效引用，未保留槽在复用前推进代次，不能每次exec重建零代次表使旧整数复活；在途操作即使引用EXEC_KEEP授权也仍校验原镜像上下文。
外部init管理Handle可继续引用同一Life，地址空间授权/映射事务则绑定预期镜像，不因PID不变自动转向新空间。通知目标自身exec时旧目标代次也不隐式重定向。
MMIO/IRQ/DMA及全局管理权不默认保留；未定义设备交接的驱动持活跃设备资源时普通exec提交前拒绝，不先撤IRQ却留下工作设备。更新驱动走既定安全停止/清理/新实例流程。

#### 示例：File与原生Mem分别继承

fd3无CLOEXEC、h1为旧私有Mem、h2为明确EXEC_KEEP共享Mem。exec后fd3保留原File，h1失效并按旧引用清理，h2授权保留但原映射解除；新程序重新map后才访问共享内容，不能让迟到旧map修改新空间。

### 栈路线与状态记录的分工（方向已确定）

采用每线程独立内核栈保留阻塞调用的 C 续点，减少仅用于恢复执行的游标/分派状态；代价是按线程配置并计费固定栈内存。此选择不代表已测得更高性能，不借鉴其他内核的栈尺寸作为本项目已验证值。

内部协议记录仍保存请求归属、fork发布、exec准备、预算及跨退出清理责任；不因能挂起 C 栈就删除状态机，也不由内部状态推出公开 OP 对象。

### 每线程内核栈的具体边界（已冻结）

内核栈由 create 阶段预付，固定大小由目标配置和栈深度审计决定，计入相应 Acct、集合总额及真实页占用；映射为内核专用且不可执行，并设置未映射保护页。保护页只用于越界检测，不算已分配物理栈页；页表开销另计。禁止把栈作为用户可继承 Mem 授权、放置大型可变缓冲或假设保护页能阻止所有跨越式溢出。示意64线程每栈8KiB占512KiB，仅说明容量成本，不是默认配置或测量结果。

IPC 或 wait 需要阻塞时，先原子登记等待及结果归属，再在自己的内核栈切出；唤醒后由该内核续点重查状态、释放本次引用并返回。IRQ 不沿任意用户指针/服务协议执行工作，也不在禁止调度区直接睡眠；用户寄存器仍在入口完整保存，不能用只保存内核被调用者寄存器的调度现场替代完整陷阱现场。首轮显式调度点必须受代码审查，不能依赖每个循环作者记得主动 yield。

独立栈不能删除 IPC 取消/提交状态、fork 发布、exec 准备、服务观察及异步清理记录：它们决定跨参与者的资源归属，不只是保存 C 执行位置。能留在栈上的短局部变量不必机械搬入 Op；会在调用结束、进程退出或镜像切换后继续被使用的引用仍须转交独立记录。

fork 为孩子分配新内核栈和受控首次返回入口，只复制用户现场/用户地址空间，不复制父正在执行的内核栈或让孩子从父 C 深层返回。exec 成功后在安全出口进入新用户现场，不把旧 syscall C 栈当新程序启动栈；自身内核栈是否清零重建及何时安全复用随入口布局冻结。

KILL 使阻塞中的内核等待也能因退出被唤醒并走取消清理，绝不再返回用户态；不能一边仍有挂起内核调用链持有引用，一边直接释放其栈。不可立即完成的外部清理转交预付独立记录，最终由其他安全执行上下文回收已不再执行的栈。

#### 示例：等待 CALL 时被 KILL

A 在自己的内核栈登记 CALL 后切出。KILL 撤销其用户返回资格，并使内核等待走退出路径；已经交给服务的请求仍按既定取消/收尾协议保存共享引用。A 的内核续点只完成本地退栈/责任转交，不执行用户 handler；调度切离后才允许回收 A 的栈，服务未归还的共享页仍继续固定、计费和收尾。

#### 示例：调度公平不等于 init 可响应

init 发起大地址空间 clone，内核每批处理后允许其他进程运行。若 init 仍阻塞在该次系统调用中，它就不能返回用户态处理其他退出与服务管理请求；即使其他进程正常运行，这个问题仍存在。下一步必须明确 clone 的提交者、推进者与完成接收者，分别验证系统调度延迟和 init 控制循环延迟，不能用其中一项代替另一项。

### 独立内核栈的首轮实现组织（已冻结）

针对首轮单核、一进程一线程、用户态驱动和短 IPC 的范围，采用每线程一份固定大小内核栈、每 CPU 一份调度栈；首轮不另加常规 IRQ 专用栈或独立内核工作线程。用户进程执行时中断使用其内核栈；调度/空闲阶段使用 CPU 调度栈。异常重入帧与栈溢出诊断的安全入口另由 Arch 契约定义，不能用用户 Trapframe 覆盖内核中断现场。

线程只需区分两类现场：完整用户 Trapframe 保存通用/扩展寄存器、PC/SP及受校验状态；内核切换现场保存恢复 C 调用所需的 SP、返回位置及架构 ABI 被调用者保存寄存器。内核禁止隐式使用浮点/SIMD，用户扩展现场按既有契约单独保存。切换汇编的布局、偏移、栈对齐以共享定义和断言锁定；先保存全部用户寄存器再使用临时寄存器。

调度器只管理运行/可调度的内核续点和就绪/等待关系；STOP/退出禁止回用户态与内核清理是否需要推进分别表示，不能为了处理 KILL 将停止进程恢复成普通用户就绪。内核任务切换须先切到调度栈更新当前线程、必要地址空间及入口栈状态，再进入被选线程的切换现场，不通过普通 C 函数调用在 A 的栈上执行 B 的用户返回路径。

#### 阻塞与唤醒

逻辑顺序为关闭 IRQ 并保存原状态→检查条件→条件不满足则登记本次等待并标记阻塞→切到调度栈。检查、登记和切出之间不能重新开 IRQ，避免完成已到达却仍进入睡眠；到达对方线程/安全调度出口后再按该上下文规则恢复 IRQ。唤醒只更新持久结果、摘等待和设置可运行，不在 IRQ 中直接执行被唤醒者的 C 代码。切回后在原续点重新检查结果/取消/退出，再恢复自己保存的 IRQ 状态。

首轮不引入 SMP 锁接力；上述为单核短 IRQ 临界区契约，不能把 IRQ 关闭范围扩大到外部等待、页清零、复制或大批页表扫描。调度器自身、空闲等待和首次进入线程的 IRQ 状态须分别规定，不把任意恢复点一律开中断。

短 IPC 已可完成时直接走原线程返回；确需阻塞才调度。原有直接交接是选中接收方运行的调度优化，仍通过其自己的内核栈和既定预算规则，不把双方调用链嵌在同一栈上。异步请求与退出后仍存活的 Rq/清理记录继续独立保存，不随栈回收。

#### 长操作与中断

长内存/克隆/撤销循环按有界工作批次到达显式检查点；检查点前释放临界区保护、固定所需对象引用并使局部状态可重查，若有调度请求再切出。IRQ 只执行必要的确认/事件和调度请求，首轮不从任意内核 C 深处抢占；用户态忙循环则在定时器安全返回出口调度。不可把全局“内核不可抢占”当作允许长时间不开 IRQ 或不让其他进程运行。

哪些函数可阻塞必须明确声明：分配器、页表短提交、引用归零和 Rq 状态提交内部不睡眠；等待应置于上层释放保护后的明确入口。首轮选定栈路线后审核这些调用边界，不通过任意函数隐式 schedule 扩大规则。

#### 信号必须先退出原 syscall 调用链

可捕获信号打断阻塞syscall时，先固定本次等待返回并稳定保留原RPC/缓冲归属，再沿本线程内核栈退至统一用户出口并建立信号帧。活请求稍后仍从原Rq领取结果，仅机制强制终结才转DRAINING；用户入口先到11的trampoline，不在退栈前等待业务完成。不能保留原深层 syscall C 调用链就直接进入用户 handler，否则 handler 再次 syscall 会覆盖或嵌套复用同一内核栈。用户信号嵌套使用已有 Sigctx/用户帧与预付 Rq，不为每个 handler 另分内核栈。

sigreturn 只恢复用户现场。需要重启的调用按明确 syscall/运行库契约重新进入，不跳回已经退栈的 C 续点，更不能重做已发布 fork 或已交付 wait。STOP 可保留原内核等待链；KILL 则使它走仅内核清理/退出路径，绝不执行用户 handler。

#### 栈的创建与回收

create 在孩子可见之前取得并计费栈页/必要映射，失败整体回滚。fork 构造孩子的干净首次返回现场；exec 切换后从安全出口进入新启动代码，不复制父栈、不在旧 syscall 栈上伪造用户 _start。退出者先把未完成外部责任转交独立记录，最后切到调度栈且不再恢复，由调度器安全回收线程栈；只有 Life/Acct 等小记录按既定责任继续存活。

线程栈大小应由目标配置、编译栈使用报告、最深异常/调用路径及保护页验证决定；初期不实现内核栈按需增长，不拿固定池容量或示意8KiB当已验证尺寸。测试同时记录最大实测栈深和静态未覆盖路径，不能仅凭运行一次无溢出认定容量足够。

### Life 中结果与清理的独立持有（已冻结）

Life 同时承担完整实例身份及已有生命周期责任，方案将 wait 结果直接放入其中，避免第三套退出对象。至少分别跟踪父收取关系、管理/观察引用及未完成清理引用，不用一个 done 位代表所有责任。字段/引用责任见本篇首版内部记录表，不机械增加重复计数器。

父 wait 消费结果后解除收取关系；如果仍有服务观察、Rq 清理或设备管理引用，Life 继续存在。反之，资源早已清理完而父尚未收取时，也保留小型 Life。只有所有责任都解除才归还 Life 池；Acct 按自身费用结清规则回收，不强制与 Life 同步。未发布孩子撤销不生成普通父 wait 结果，但必要清理引用仍维持旧 Life。

集合实例额度在尚未发布、存活或结果未收取时保持占用；退出结果收取后可解除该项额度，残余 Life 仍占独立池，残余内存继续占集合内存额度。这样既不会为一页滞留 DMA 永久扣一个可运行实例额度，也不会使反复创建/退出无限积累免费记录。精确槽上限/计费见01/本篇首版表；监督引用继续占Life/观察池，不延长已解除的普通实例收取额度。

#### 示例：运行槽复用，但旧孩子仍可 wait

B 位于运行槽 7/代次10，退出结果保存在旧 Life，运行资源分离后槽7可分配给代次11的C。A 以 B 的完整 PID wait，查父子 Life 关系得到 B 的旧结果；不能先解析当前槽7发现是C就误报无孩子。A 收取 B 后，若 FS 尚有待确认终结观察，旧 Life 保留到观察责任解除，不能串到 C。

### 孤儿转交与自动收取（已冻结）

首轮孤儿统一由 PID 1 的 init 接管，不增加 subreaper 配置。父进入不可恢复退出后，已发布孩子及其尚未收取结果转交 init；未发布孩子属于准备清理，禁止发布而非成为可运行孤儿。转交只改变父关系与合法收取者，不转移资源出资 Acct、集合预算、凭据或服务会话所有者，也不自动改变 PGID/SID/控制终端；孤儿进程组规则另按终端契约判断，不能把“失去父进程”直接等同于孤儿进程组。

父 wait 交付与父死亡按内核提交顺序裁决：先交付则该结果已消费，不再复制给 init；先死亡则旧父不能消费，init 接管。孩子退出与转交也按顺序裁决：退出先提交的既有结果保持不变；转交先提交时，后续退出采用 init 的当时策略。旧父已自动收取的结果不复活，已保留的历史结果不因接管者当前忽略通知而被静默丢弃。

init 对接管结果走同一 wait 路径，不另维护结果副本；主循环有界排空可领取的退出结果，通知仅唤醒而不代表结果数量。确定 init 保留正常收取策略以便诊断，不靠全局 SIGCHLD IGNORE 代替收尾。自动收取策略见 [SIGCHLD 与 wait](11-terminal.md#sigchld-策略与-wait已确定)，具体标准审计尚待完成。

大量孩子转交不能成为长时间关 IRQ 的循环。逻辑所有权改变必须与父死亡原子排序，链表迁移/逐项维护允许有界推进，期间 init 的 wait/无孩子判定必须包含待转交结果，不能先误报无孩子；不得依靠已销毁父栈继续遍历。

父死亡的清理通知不能要求所有服务退出确认后才转交孩子；孩子也不因被接管自动解除 STOP。旧父句柄、被转交结果和仍待确认观察继续按完整实例身份区分。转交本身不归还集合额度；既有结果实际收取/自动收取解除收取责任后，才按前述规则结算实例额度，残余内存/记录仍分别计费。

#### 示例：父死亡时一个孩子已退出、另一个仍运行

A 的孩子 B 已退出但未收取，C 仍运行。A 死亡后，B 的既有结果交 init 领取，C 的父关系变为 init，C 不重启、不换预算、不自动停止或继续。init 收取 B 后若 FS 尚有清理引用，B 的 Life 仍保留；C 之后退出采用 init 当时的收取策略。若 A 已在死亡前完成 B 的 wait 交付，init 不再收到 B 的第二份结果。

## 首版权限、准备与内部记录规格（已冻结）

用户于2026-11-15授权自主决定剩余项。本节把前述方向落实为首版选择；是设计规格，不是实现或测试通过。初始 init 授权以启动清单给定，不以 uid0、父子身份或服务名授予内核管理权。

### 资源子类型与最小权限

RESOURCE 子类型编号固定：1 CREATE、2 SPACE、3 ALLOC、4 MEM、5 CALL、6 SEND、7 NOTIFY、8 CONTROL、9 OBSERVE、10 IRQ_SOURCE、11 IRQ_BIND、12 TERMINAL、13 EXEC_VIEW、14 CONSTRUCT、15 SYSTEM。仅有对应子类型才解析其权限位；同一位号不构成跨子类型权限。

SYSTEM实现接续（2026-11-18）：Local已接仅QUERY的精确Image绑定及清理引用，禁止继承/GRANT，free/表关闭只释放该引用，不牵连独立设备授权；生产安装与库存只绑定初始PID1/image1，不按uid或裸PID补权。681项host/格式/167次两架构QEMU本地全量通过；实际边界、Boot布局及原生事务归07末尾，不称SYSTEM全部业务位或全局管理域已实现。

2026-11-19用户确认TERMINAL细则：QUERY=1、FG=2、SIGNAL=4、BIND=8，GRANT仍bit63。SIGNAL掩码仅INT/QUIT/TSTP/HUP/WINCH，grant的offset对TERMINAL表示缩小后的信号位集合，length必须0；去掉SIGNAL时掩码为0，不能扩位。仅QUERY/FG可标记FORK/EXEC，SIGNAL/BIND不继承。初次授权由ttycreate取得，仅经有效CONSTRUCT/EXEC_VIEW CONFIG准备期转授，运行中CONTROL INSTALL拒绝TERMINAL；句柄不是终端关联本身，继承句柄不跳过会话/前台检查。具体实现边界见11末尾。

2026-11-19用户确认首次发权：SYSTEM POLICY=0x10，只授精确初始init PID1/image1；ttycreate另要求目标固定CONTROL CONNECT，解析到目标当时PREPARING/ACTIVE的精确Image，不随其后exec重绑定。返回完整TERMINAL业务权、GRANT及允许信号全集，不带继承标记；目标资源表不自动增加该授权，后续须显式准备期grant。任一步失败不得保留新终端或Image引用；其他SYSTEM POLICY业务仍须各自实现，不能因该位存在绕过其接口准入。

所有可转授RESOURCE统一使用bit63的GRANT；表内低位仅业务使用权，MEM READ/WRITE/EXEC/SEAL/DMA依次bit0..4，CALL/SEND USE为bit0。GRANT控制普通grant源权限，并与CONTROL CONNECT共同限制connect产物的GRANT；target须是本次有效CONSTRUCT/EXEC_VIEW CONFIG或固定进程CONTROL INSTALL，不能以QUERY/CONNECT/GRANT替代。grant永不增权/扩窗口；CREATE的再授予还要求源SERVICE或init POLICY，普通CREATE不能任意传播给既有进程。grant的inherit字段仅两位：FORK=1、EXEC=2，默认0；目标子类型禁止的继承位一律拒绝。EXEC=2只适用显式共享MEM、CALL/SEND/NOTIFY、必要启动SELF/CREATE重绑定；应用私有MEM不因设置EXEC而保留旧映射。运行中resource reply只允许受限SHARED MEM或后端CALL USE，默认FORK=1、EXEC=0；fd所需exec继承由服务交接重新建立，不把旧调用权盲目改绑对端。

初始启动清单建立16个Set及各自绑定的CREATE/集合CONTROL，不提供运行时任意集合创建/迁移。create使用SERVICE权限时额外向调用者返回a3/x3=该孩子的持续CONTROL（QUERY/TERMINATE/BUDGET/IRQ/REVOKE/CONNECT/INSTALL及GRANT），普通创建该输出0；这不是构造权发布后自动升级，SERVICE只授init且不继承。connect(authority,kind,rights,bits)凭CONTROL CONNECT或本主体仍有效的未发布CONSTRUCT建立固定目标镜像的CALL/SEND/NOTIFY入口，不能凭PID建立；构造期建立的入口可在发布后使用，但不含持续监督权。NOTIFY掩码只用户位，其他kind的bits=0。请求带GRANT的产物时，输入CONTROL必须同时含CONNECT和GRANT；仅CONNECT只能生成USE，缺任一位DENIED。CONSTRUCT仅能生成USE，不能生成GRANT；SYSTEM/POLICY或裸PID不替代显式目标authority。普通USE入口不能提升。

inherit(resource,flags)仅修改本主体允许类型的FORK/EXEC保留标记，不增加对象使用权、不能设在构造/CONTROL/设备类型；MEM仅SHARED可EXEC，CALL/SEND/NOTIFY可显式EXEC且仍绑定原对端image。运行中reply默认不设EXEC，fd适配在准备保留连接时按自身授权显式标记；这是同主体继承而非向第三方grant，不要求源GRANT。fork/exec自身份空间/分配/CREATE采用专门重绑定，不复制旧私有映射。

撤销只按精确目标授权来源失效，非派生树。free允许MEM/CALL/SEND/NOTIFY/固定进程CONTROL引用放弃；SELF/CREATE等固定启动权仍用revoke/退出处理，不把free扩大为通用销毁。仍在途的Rq、Mmap、观察和清理记录各持独立引用。固定设备域的DMA收尾只由明确CONTROL及设备协议共同许可，rqclean不能伪造真实停机证据。

### fork/exec 准备的确定选择

forkprep(createcap,reserve_resources)一次完成自身快照/COW建立，reserve_resources为0..8、来自必要后端数，快照后在孩子表预付镜像内资源回复保底空槽，不足则发布前CAPACITY失败；保底槽供发布后按需接入使用，不依赖启动完成标志；返回CONSTRUCT和PID；所有commit在最终短提交重读单调时间，deadline已过即拒绝发布/切换；子保存同一原始调用返回现场，尚不可运行。克隆循环每32页到达调度/STOP/KILL检查点，允许其他进程和IRQ进展；父在这段CPU快照建立期间不执行用户handler，直到快照完整提交或回滚才递送。只暂停父的用户执行，不跨服务等待，也不屏蔽整个fork。这样不需要公开OP或在handler后修补半张快照；延迟上界由已映射页数/配置工作量决定，不声称未经测量的毫秒保证。

forkcommit(child, fixva, fixbytes)检查只读子修复区、必要引用及本次归属后发布，并撤销该准备的发布期限，不向孩子镜像延续启动计时器。父得到原PID；子从forkprep返回，status=0、a1/x1=0、a2/x2=自身PID、a3/x3=fixva；父forkprep为status=0、a1/x1=构造Handle、a2/x2=PID、a3/x3=0。私有返回桩先分支再访问父准备结果；子不执行父提交路径。forkabort先关发布资格再清理，无wait结果。普通start拒绝FORK来源。

同一父最多有SIGDEPTH+1份未发布fork/spawn准备，各归对应运行库上下文；继承快照排除所有构造/执行准备Handle。fork用户prepare钩子逆注册顺序，parent/child钩子正顺序，每次外层fork各一次；_Fork不调用钩子。钩子中递归fork由libc检测并以EAGAIN失败，不把用户任意钩子宣称异步信号安全；handler的_Fork走独立预付上下文。

每实例至多一份exec准备；嵌套execprep遇已有准备返回原生BUSY，execve映射EAGAIN并记录为本系统资源冲突扩展，外层准备不被内层失败破坏。fork/spawn/exec的未发布准备统一10秒单调期限，从内核接受准备起固定，不因handler/STOP重置；start/forkcommit/execcommit成功即结束该准备期限，普通已发布镜像没有通用交接超时或ready确认。内核每次时钟检查最多8份准备、全表游标轮转；到期先撤销发布/切换资格，清理转CPU有界清理链，每次最多32项。服务的未发布准备另持同一deadline，到期须重查目标状态：ACTIVE转普通镜像归属并保留按需接入记录，PREPARING等内核撤销后清理，ENDED直接收尾；不按旧截止撤销已发布目标。STOP不阻止内核/服务清理，但停止中的主体不执行用户代码；KILL立即撤销用户返回资格。到期中断先改资格/取消标记，活动C续点仍持临时引用时先令其仅完成安全退栈/转交，再由CPU清理链回收；不与尚在使用这些页表的C续点并行拆除。清理记录内持游标/稳定引用，不引用已退栈C局部，不增专用内核工作线程。

wait(pid=0)在原wait接受时固定调用者当时PGID，SA_RESTART沿该选择重新检查；pid>0固定完整PID，pid<-1固定完整PGID，-1为任意合法孩子。零结果/错误/成功一旦提交不重查。父死亡的逻辑接管者先原子改为init，物理链迁移分批；wait枚举同时包含迁移链，不能短暂ECHILD。SIGCHLD策略不追溯重解释已提交退出结果。

### 内部记录的字段、所有者和槽宽度

内部结构不是用户ABI；以下固定字段组/引用责任及每槽字节上限，具体内部成员偏移不跨C/汇编边界，不为未来兼容固定无用padding。实现sizeof超过上限必须修改预算规格并重新审查，不能静默加大。

| 记录/槽宽度上限 | 必需字段组 | 唯一生命周期责任 |
| --- | --- | --- |
| Proc 512 | PID、Life/Acct/Space索引、当前image、nextimage、调度/STOP/EXIT位、用户TF/Kctx指针、内核栈块、pending/event/alarm、当前强等待边、资源表、准备/信号索引 | 运行槽；不含完整Rq/退出结果副本 |
| Life 128 | 完整PID、逻辑父Life、运行槽可空、最终退出原因、状态序号、退出/停止继续的可报告版本、子链/迁移链、wait/观察/清理引用 | 独立池，所有责任解除才复用 |
| Acct 64 | 集合索引、常规/峰值、used/reserved、ACTIVE/CLOSING、进程绑定及引用 | Mem/COW实际出资，不随PID槽复用重绑 |
| Group 64 | SID/PGID、成员/管理引用、组长完整PID、孤儿/前台关系 | 组长退出不销毁有成员组 |

| Mem 96 | 类型/状态、字节长度、块链、Acct、管理/映射/在途引用、写别名/执行计数、DMA域及固定标志 | 块/页出资与可回收条件 |
| Mmap 64 | Space/Mem、VA/offset/length、prot、别名链、COW逻辑分支索引 | 一次完整映射，unmap后TLB完成再放引用 |
| Rq 192 | 代次、两端PID/image、授权来源、32字节联合消息、queue/owned双链、阶段、结果、cancel_requested、三责任位、同步临时引用、可选资源槽、等待归属 | 调用结果与服务排空分开 |

内核/用户态活动记录全部用完整身份或固定池索引加代次；链节点、回收引用与临时同步栈引用分别定义，不以三项Rq完成位代替真实引用归零。固定表池由系统保留页一次承载；运行时占用算专用池/主体配额，不能再给每个占槽虚扣一整页。线程栈和动态页表实际页另记Acct；结构内不保存跨返回的裸用户指针。

失败例：父被KILL、孩子尚未发布且旧FS仍持共享槽：Prep先ABORTING，孩子不可发布；内核页表清理按批推进，FS根据旧Image终结排空；Life/Acct/Rq仍占原池及费用。新进程即使复用了Proc槽也不能取得这些旧记录。

## 执行与验收

- [ ] 未发布准备10秒到期先关发布资格；提交先成功则取消期限，不强杀STOP超过10秒的孩子/新镜像，不依赖execready确认。
- [ ] 子fork/_Fork只完成本地修复即可返回0；原准备/父死亡和服务超时均不得删除已ACTIVE孩子的引用，未发布/已发布死亡清理分别守恒。

- [ ] 枚举CONTROL低7位组合，grant仅INSTALL允许，revoke仅REVOKE允许；QUERY/CONNECT/bit63 GRANT不能充当目标表安装权，授出源仍独立要求GRANT。
- [ ] CONSTRUCT/EXEC_VIEW仅CONFIG和有效归属/阶段可安装；发布、撤销、超期或source镜像改变后拒绝，CONTROL INSTALL不能调用configure改CPU现场。
- [ ] 集合/域CONTROL、SYSTEM、PID、CALL、REQUEST不作grant目标；检查后target exec/退出时旧尝试不写新表，容量/范围失败不占槽或泄漏引用。

- [ ] free只放弃本地MEM/CALL/SEND/NOTIFY/固定进程CONTROL引用，PID/RPC/REQUEST及陈旧Handle拒绝；Mem仍有Mmap、CALL仍有已提交Rq时底层引用保持，不能误用复用槽。
- [ ] 连接关闭先登记服务关闭/请求收尾，后释放最后本地入口；用户free不冒充服务close、rqcancel或DMA停止，失联不误关同号新连接。

- [ ] source只有使用权而无授予权、越范围/增权限、发布后旧准备授权及拿CALL句柄当目标管理权均拒绝，不改变目标表。
- [ ] grant提交与start/退出/撤销交错只有合法先后，失败不留表项或引用；source释放不误撤独立副本，revoke不冒充unmap或DMA停止。
- [ ] 在冻结运行中资源交付前，不以普通grant已实现为证据宣称FS共享连接或直达后端已可建立；补齐同意/容量/取消/消息结果契约后单独验收。

- [ ] create属性覆盖身份0、普通身份伪造、峰值小于常规、容量低于必要预留/高于编译上限；拒绝时不产生孩子或扣留额度。
- [ ] 固定集合下连续创建高单实例上限孩子，不按声明上限新增总额度或承诺物理页；创建实际开销和后续分配分别计费，出站/信号预留不能被属性削减。

- [ ] configure六项输入覆盖VA溢出、架构对齐、Boot长度不符/超限、栈权限、非法信号位及KILL/STOP屏蔽；任一失败保留上一完整现场。
- [ ] 重复configure从固定继承基线重算信号，源handler不复制到新程序地址；fork/exec分别走自身继承/重置协议，不把新建基线套到fork。

- [ ] create同时返回PID/本地构造Handle，二者串用拒绝；逐预付步骤耗尽完整回滚，返回后调用者立即死亡仍能追踪未发布孩子。
- [ ] 普通创建越权指定父/集合/凭据及超授权容量失败；configure失败保持旧现场，fork/exec准备不能假装普通create来源绕过发布。
- [ ] start/destroy/父死亡排列顺序仅一个发布或撤销结局；撤销后本地清理有界，服务/共享/DMA外部引用不提前释放，不生成未发布孩子的普通wait结果。

- [ ] 阻塞条件完成发生在检查前/登记后/切出前/切回后各边界时不丢唤醒，所有切换点 IRQ 状态符合契约，不持短提交保护等待。
- [ ] syscall 被信号中断后先完整退栈再进入 handler，handler 再 call/wait、嵌套信号和 sigreturn 不覆盖内核现场；请求 DRAINING 的缓冲不因退栈释放。
- [ ] 当前线程退出只在调度栈回收其栈；首入/空闲/内核中断/用户定时器返回覆盖上下文切换，长循环批次间其他进程有进展。

- [ ] 核对每线程栈/每CPU调度栈、守卫和页表的最大配置开销及 create 耗尽回滚，内核栈不映射到用户态。
- [ ] 覆盖阻塞唤醒、IRQ嵌套、长循环调度点、fork首次返回、exec切换及KILL内核等待，验证用户全现场/内核切换现场布局断言，栈只在切离且不再有续点引用后回收。

- [ ] 对父 wait、父死亡、子退出和 SIGCHLD 策略切换排列先后，结果只有一个收取者；自动收取不复活、历史结果不被候选新策略静默丢弃，服务观察仍独立。
- [ ] 最大配置孩子转交分批执行，IRQ/其他进程有进展，init wait 不遗漏待转交结果；原集合计费不迁移，STOP 不被接管清除，旧父 Life 不提前复用。

- [ ] 运行槽复用后指定旧 PID 和任一孩子 wait 均能找到旧结果且不匹配新实例；未收取结果不需要完整用户现场/地址空间或 init 副本。
- [ ] 分别先完成 wait、服务清理及观察确认，核对 Life/Acct/运行槽/集合额度各自回收；滞留引用耗尽池时明确背压，不丢结果腾槽，不提前释放 DMA。

- [ ] wait 检查/入睡与子退出交错无丢唤醒；交付前中断不消费、交付后信号不改成功或重复消费，STOP/KILL/孤儿转交均保持唯一收取者。
- [ ] 按上述重启方向覆盖 handler 先收取唯一孩子导致外层重查 ECHILD、外层先收取则 handler 不得重领，以及 WNOHANG 固定0后信号不引发第二次查询；检查 status 复制失败仍不重取。
- [ ] 冻结输出 ABI 后覆盖空 status、坏指针、跨页不可写、COW 及复制资源耗尽；用户输出失败不回滚已消费结果、不自动再次 wait，受检查复制不导致崩溃或越权；原生参数/权限失败不消费。

- [ ] 以发布/撤销为原子点排列信号、超时、STOP/CONT/KILL、服务回复和子退出，验证成功结局不改失败、撤销不复活、等待结果不丢。
- [ ] 信号返回不重复克隆，handler 不观察半更新库表，子掩码不含内部临时屏蔽；清理槽未归还时新操作背压，STOP 不因完成事件自动恢复。
- [ ] 按上述方向覆盖无 SA_RESTART 的准备中断仍继续原孩子、用户钩子不重复、handler 在克隆后修改父私有数据不改变子快照；handler 已收取发布孩子时外层仍只返回原 PID，handler 成功 exec/退出时不恢复旧准备。
- [ ] 冻结中断的标准错误映射、请求重启及准备期限推进者；此前不宣称支持任意 EINTR/SA_RESTART 或 STOP 期间自动超时收尾。

- [ ] 跳过/失败/延迟 FS 准备后提前发布，只影响获权孩子，不能访问父或其他实例会话；服务准备与发布竞态不向已运行子私有内存继续写入。
- [ ] 服务回复准备成功后立刻退出、父直接 KILL、孩子发布前后退出，均无等待父二次确认才可用的悬挂状态，资源按真实实例收尾；正确 libsys 失败前不发布。

- [ ] 直接克隆保存 syscall 用户现场，父继续准备但子不运行；父后续私有写入不改变子快照，子不从 _start 或父管理分支执行。
- [ ] FS 快照/子会话准备前后、内核发布前后注入父 KILL/exec、服务故障、信号及重复请求；未发布子最终收尾，已发布子不被父清理误撤销，不重复创建。
- [ ] 冻结服务准备和可靠生命周期协议后验证：普通客户端不能替任意 PID 冒领资源，已准备引用跨父死亡有明确归属，容量耗尽先拒绝。

- [ ] 对 start/forkcommit 与 configure/map/grant、父死亡和孩子立即退出排列顺序，验证发布原子失效准备权限，先失败发布可修正，先死亡不迟到发布。
- [ ] 构造 Handle 不转授/继承，失效槽推进代次；父 wait 不依赖该 Handle，监督观察不消费父结果。发布前移除临时写别名，显式共享引用不被错误撤销。

- [ ] 冻结受限创建与集合预算方案后，覆盖多代 fork、并发准备、COW 预留、重复映射、退出未收取、共享/DMA 滞留及多进程 exec 峰值；单进程与集合账目同时守恒。
- [ ] 普通创建不能改身份、扩大权限或预算、克隆他人、配置已运行目标；创建各预付步骤失败后只回收本次安全释放的资源，陈旧管理授权不能作用新实例。

- [ ] 用最大配置地址空间构建及回滚场景，分别测量最长关 IRQ 段、其他进程调度间隔、init 管理请求响应时间和额外常驻内存；在实现前只检查状态转换，不声称性能结论。

- [ ] commit发布前无新增分配，abort完整回滚后返回父失败；重复/迟到提交不产生第二个孩子，参数故障不部分发布。

- [ ] FD_CLOEXEC与EXEC_KEEP独立，保留Mem不保留VA，非保留旧值在跨exec槽复用中不复活；SELF/空间权限绑定新镜像。
- [ ] init的Life管理权跨exec仍可用，旧映射操作不能作用新空间；未支持交接的活跃设备exec提交前拒绝且不破坏原设备状态。

- [ ] 专用检查点恢复使父返回子PID、子返回0，不克隆父等待节点/内核栈；父暂停期间IRQ和无关进程仍有进展。
- [ ] 外部准备超时、父KILL/STOP、信号及回复迟到覆盖发布边界；父信号掩码不泄漏内部临时屏蔽，失败解除暂停且无半成品子进程。

- [ ] fork 父/子返回值、相同用户延续、独立身份/统计及父子组关系正确，孩子先退出仍可 wait；失败不发布可运行实例。
- [ ] 每个复制/继承/提交步骤注入退出、信号、STOP及资源不足，父状态可恢复，子资源完整回滚；普通进程不借 fork 扩大管理/设备权限。

- [ ] DMA 永不完成时退出结果仍可收取，进程槽在自身条件满足后可复用，隔离资源仍由旧 Life/Acct 持有且不超配额。
- [ ] 已发布退出原因不被后续清理失败改写；管理查询和正常关机分别验证退出状态、隔离状态与设备安全条件。

- [ ] Life 在 create 预付，池满失败完整回滚；旧进程槽复用后旧管理 Handle 仅能查询/清理原实例，不能操作新进程。
- [ ] 退出后不保留无用运行资源，Life/Acct 各自等待实际引用条件回收；反复创建/退出/清理及管理授权释放不泄漏记录。

- [ ] 多进程 yield 保持普通队列公平，不重置直接交接预算；单就绪进程可继续，STOP/EXIT 交错不将目标错误重新入队。
- [ ] 空闲服务/驱动使用真实等待，检查无 yield 忙循环导致的持续 CPU 占用。

- [ ] exit 陷入后用户哨兵不再执行，_exit 不执行用户回调而仍清理资源；退出清理不要求目标再运行或请求 fs。
- [ ] 正常 exit 与管理 terminate 竞态首次提交原因保持不变，重复清理不重复释放，初始 init 退出按致命策略处理。

- [ ] 分别运行正常退出、SIGTERM 默认终止、非法访问/非法指令及管理 terminate，核对原生原因和 POSIX 状态宏，不伪造 core 标志。
- [ ] STOP/CONT 事件不消耗最终退出记录，wait/诊断权限不泄漏内核地址或完整私有寄存器。

- [ ] 多个同时退出仅产生合并事件仍全部收取；结果表预留耗尽时创建失败，退出收取/确认路径不需新增关键分配。

- [ ] destroy 未启动实例回滚页/授权/预付记录且不生成运行退出结果；已运行实例拒绝 destroy，STOP 不恢复其未启动资格。
- [ ] terminate 在运行/阻塞/停止及清理阶段均阻止再次回用户态；重复提交幂等，旧代句柄拒绝，退出记录与外部引用/DMA 生命周期分离。

- [ ] start 检查失败不入队，重复 start 拒绝；configure 后映射/事务变化仍重新检查，组准备不能通过单进程 start 绕过。
- [ ] 子进程在管理者收到 start 结果前退出，退出结果仍可收取且只发布一次；作业屏障规格冻结后验证成员不会在必要组/前台准备前执行目标命令。

- [ ] configure 失败保持旧现场，未知/特权字段拒绝，入口参数及初始寄存器确定；已启动后即使 STOP 也不能重配。
- [ ] configure 后撤销必要映射，start 不因旧成功标记而放行；重复配置不修改预算、凭据和独立授权。

- [ ] create 成功实例不进就绪队列，空地址空间与现场确定；对每个预付/配置步骤注入失败，不发布 Handle、资源快照回归。
- [ ] create 后装载失败可 destroy 清理，PID 无法替代管理授权；在时钟抢占下半配置实例始终不可运行。

- [ ] revoke 参数在各自主体解析，授权来源不同的排队调用不被误取消；旧 Handle 重复撤销不影响复用槽中的新授权。
- [ ] 最大队列撤销使用有界 Op，标记失效后新调用拒绝、已有 CALL 可收尾，记录回收前无引用悬空；映射/DMA 不被提前释放。

- [ ] grant 返回值只在目标主体解析；源释放后目标授权仍有效，单项撤销不级联；范围/权限扩张、未知位、非零无意义范围和目标表满均无副作用。
- [ ] grant 安装与目标退出/槽复用交错，只能明确失败或被原实例清理，不泄漏引用或影响新实例。

- [ ] 将 16 页 Mem 的中间 4 页只读授权给另一进程：合法只读映射成功，越界、溢出、写/执行扩权及其他地址空间操作拒绝且无副作用。
- [ ] grant 不产生隐式映射，失败不泄漏引用，旧授权撤销不影响另一独立有效授权；未获明确委托权的普通进程不能转授，获权者只能在允许范围委托。

- [ ] 验证 getpid 在 init 返回 1；普通句柄解析不把 1 当本地资源；init 退出不发布替代 PID 1。
- [ ] 组长退出并复用进程槽后，旧组/会话仍可按原编号使用，新实例不能继承旧关系或权限。

### 阶段 06：进程、计时与公平调度

### 阶段05内核栈生命周期切片（2026-11-15）

本节落实已冻结的独立内核栈责任，不等于Proc/Life、发布协议或调度器已经实现。

- [x] 可信内核Kstack池默认64槽；每栈4个零阶物理页和专属叶页表页分别由原Acct出资。创建先取得/初始化全部页，再提交RW/NX内核映射；任一步失败保留输出、归还页/表/引用/费用及槽名额。
- [x] 每栈保留2 MiB虚拟槽，仅映射guard后的16 KiB，栈顶之后也留空；叶表不与其他栈共享，避免不同Acct之间出现“最后解除者释放另一账目的表页”。共同上层使用永久KIO父表，其费用仍属系统启动预付。
- [x] 管理引用与可恢复续点引用分开：创建得到1份管理引用，构造Hkctx前hold；挂起时持有续点引用，free返回BUSY。代码正在该栈上时drop/free均拒绝；先切离并明确废弃续点，再drop/free，不能用停止运行代替废弃续点。
- [x] 回收先核对全部页的PA/权限/属性，以及私有槽中没有外来叶，再逐页撤映射、TLB失效、释放原表/栈页，最后退Acct引用。账目关闭不改变既有栈的归属，代次复用不接纳旧Kstackid。
- [x] 用户陷阱测试改用真实计费线程栈：CPU启动栈切入独立栈，构造完整Hctx并进入U/EL0；七次同步陷阱结束后先撤用户根、切回CPU栈，废弃线程续点，再回收其栈和地址空间。

Kstackid是可信内核记录索引/代次，不是用户Handle；本切片仍串行、IRQ关闭。新HAL内部构造器`void hal_ctx_init(Hkctx*,u64 top,void (*entry)(void))`把干净内核现场设置为受控C入口，清零其余字段；调用者提供常驻、16字节对齐的栈顶与可信不返回内核入口。它补足首次进入新栈所需机制，不复制旧C栈，也不允许用户提供任意内核PC/SP。

具体区域为0xffffffc101000000起、每槽0x200000，默认64槽；硬件窗口/对齐由断言保证与永久KIO共享同一上层。Kstack当前72字节，64槽4608字节在BSS整体预付，上限按每槽80字节计入固定池预算，不按活槽另扣物理页。每个活栈费用当前正好5页：16 KiB栈和4 KiB叶表；guard无物理页。父表永久存在、不同栈均独占叶表，是本切片单一释放责任的前提，不能随意在私有槽加别名。

测试例：仅给Acct剩余0/1/2/3/4页额度，分别在第一个至第四个栈页或叶表处失败，全部回到原快照。两个不同Acct各持一栈，先关闭一个账目，释放另一栈不能结清被关闭账目的5页。挂起worker的续点仍持hold时CPU尝试free被拒绝；恢复后worker的SP/局部值保持，切回CPU并废弃续点后才归还栈。故意删除第二叶或在私有槽添加外来叶时，free预检失败，不得先删除第一叶。

主机覆盖默认算法的4槽小配置、每步额度/物理页耗尽、双账目、旧代次、池复用、全部解除预检与已存在用户根借用新内核映射；guest默认64槽实测池耗尽/回收、费用守恒、guard/PTE、续点往返及运行栈拒绝释放。`user`额外验证完整用户现场确实落在独立栈上，并在CPU栈回收。

栈审计：新栈先填0xa5水位标记，再构造干净现场；离栈后读取最深已修改位置，记录该场景的观测水位。编译器为每个内核C单元产生`.su`，汇总到镜像目录`stack-usage.json`，manifest记录路径，缺报告不命中缓存。报告仅为每函数编译帧，不包含手写汇编、完整调用链或所有可能路径；水位也不是安全上界证明。后续仍须覆盖IRQ/取消/信号/最深调用链及栈溢出注入，不能因此认定16 KiB最终足够。

CPU侧本地测试继续使用启动时已经保留且有guard的16 KiB栈保存CPU续点；尚未实现调度队列、时钟抢占、Proc创建/退出/等待或清理链，不把两栈受控切换称为这些机制验收。接续实现Local授权、Proc/Life及configure/start时须沿用上述持有责任。


本切片本地`make test-all`通过91项host、格式及42个QEMU场景，日志`build/host/stage05-stacks/test-all.log`。在当前LLVM18.1.8/QEMU11.1.3、256 MiB、IRQ关闭配置，独立C续点场景水位RV64 152字节/ARM64 160字节，用户往返场景776/1024字节；内核单函数报告最大2112字节为启动撤低映射的hal_vm_drop_low，不可将单函数帧与不同场景水位相加冒充完整路径证明。normal仍初始化后停机，无CI、真实硬件或性能结论。


### 阶段05 Local、Life与Proc可信基础切片（2026-11-15）

本节接续栈生命周期，只描述已实现的可信内核机制。未导出原生create/configure/start/grant/wait，也未以裸PID建立用户管理权限。

- [x] `include/abi/base.h`定义有符号64位Handle、固定类别及21个错误；编码/类别检查使用无符号位运算，先识别保留PID 1。句柄语法有效不等于存在对应对象或拥有权限。
- [x] Local为48字节，保存本地43位代次、完整对象代次/索引、子类型、rights、offset/length、inherit与来源类别；每次发布才递增代次，清理保留代次，耗尽不回绕。当前仅支持SELF SPACE、ALLOC和同Acct DATA/CODE MEM。
- [x] Local分别检查目标SPACE与MEM权限，按Mem本体偏移检查授权子范围；普通复制引用要求GRANT、使用权/继承标记子集及当前Mem状态。封存后的旧WRITE位不能用于写入、RW映射或再次授写。删除MEM授权不撤销独立副本/既有Mmap；整条unmap只需SPACE UNMAP，不依赖旧MEM Handle。
- [x] Local关闭先禁止新操作，随后每次至多处理32个槽，独立释放对象引用；这里只实现表机制，`localcopy`/`localrevoke`的目标选择来自可信调用者，不是省略INSTALL/CONSTRUCT检查的原生grant/revoke。
- [x] Life独立保存完整PID、父身份、运行槽可空、第一份终态/故障快照，以及结果、CONTROL、观察、清理责任。已结束且切离运行槽后仍可保留结果/旧引用；收取结果解除集合实例额度，残余清理/观察继续占Life池。未发布撤销没有wait结果，切离后解除实例额度。
- [x] Proc按自身运行槽43位代次发出唯一PID，Life只消费该可信身份，不充当授权或发号器。构造时先预占运行槽，再取得Life、Acct、用户根、计费内核栈和本地SELF授权；失败逐项回滚，且不发布PID。槽0保留给后续独立启动的初始init，normal不创建模拟init。
- [x] 可信configure完整快照六字段，校验入口对齐/RX、整个64 KiB RW/NX用户栈及guard、只读Boot范围和头部长度/格式，成功才替换干净Hctx；失败保留原配置。publish重查映射与Boot，不信任旧configured位，再将Life发布并只入FIFO一次。

### 真实Run停放与继续（2026-11-19）

可信procstop/proccontinue现连接Life报告与真实Run。就绪目标从队列摘除，阻塞目标保留原C等待续点，两者均进入内部PROC_STOPPED；当前Run只登记延后停放，在安全checkpoint/yield/sleep或专用forkyield边界切出，返回用户前必须经过停放。CONT按保存的可恢复状态恢复，重复操作不重复入队或生成新报告；停放前的CONT可抵消当前Run的未执行停放，但不擅自清除独立调度请求。未发布构造与退出目标不接受停止/继续，错误发生在队列变更之前。

Proc仍512字节：原phase单字节改为显式状态判别联合体，EXITING用cleanup、STOPPED用resume，RUNNING可保存待停放标记。原state/configured/phase/wait_cursor位置不变，联合体大小及相对偏移有静态断言；Procinfo只在EXITING报告清理phase，不把恢复状态冒充清理进度。所有终止提交重置cleanup=0，避免从原resume编号开始跳过释放。Life仍128，未增加池、内核栈或运行时分配。

停止期间，通知/IRQ、闹钟到期、请求完成、孩子结果与sigsuspend的可递送信号仍按持久状态推进；wakeone只把保存的BLOCKED转换为READY、清除已结束的强等待边，不把停止Run入队。CONT可恢复已就绪C续点，或恢复阻塞并重查真实条件。保留未完成请求的真正等待边，不因STOP取消Rq/共享缓冲；已完成请求则不能因STOP留下假边。固定CONTROL query可见PUBLIC STOPPED=6及仍持有的wait种类/选择器，已完成等待的waitpid为0；这不是用户已经执行了返回。CPU停放不撤销资源或证明设备已停止。

固定CONTROL terminate现可直接终止停止目标，不等CONT，并归还被放弃C续点持有的Rq/prep/组wait引用；服务/Acct/观察/独立请求收尾仍走原协议。停止父仍按既有动作/策略接收真实退出SIGCHLD到pending，但不会因此执行用户代码。本轮不产生停止/继续SIGCHLD，也不新增NOCLDSTOP或普通阻塞handler中断。
