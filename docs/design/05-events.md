# 事件、中断与时间

[设计总览](00-overview.md) · [实现状态](../status.md) · [执行与验收](#执行与验收)

状态：2026-11-16时钟、内核/用户timer IRQ、准备期限、原生notify/alarm和消息/事件接收已局部实现，见末尾/status；外设IRQ、CHILD/LIFE提示、信号/运行库仍待接，不称完整事件系统、性能或CI验收。

## IRQ 与事件

IRQ 仅投递给已授权接收者，事件位可合并，不当作次数计数。
控制器认领/屏蔽/完成留在硬件层；驱动清设备状态后确认，按硬件要求重新开放。

### 中断上下半段（已确定）

内核中断上下文为上半段：HAL 按控制器要求认领、必要时屏蔽/完成，事件层记录 pending 位并唤醒授权驱动。
用户态驱动为下半段：读取设备状态、处理完成队列、清设备状态、ACK 并按协议重新开放通知。
不额外引入内核设备工作线程或通用软中断层，不在硬中断中执行设备业务或动态分配。
默认采用屏蔽后通知、驱动处理后开放；它不是所有设备的固定策略，高频网络设备可采用有界批量轮询后恢复中断。
事件表示需要检查设备而非完成次数，驱动扫描实际完成队列；屏蔽期间的边沿与重开窗口须按设备协议处理。
每轮批处理必须有上限，不能因设备持续繁忙无限占用 CPU；不能把拆分本身当作已测得的性能提升。
首版一条设备 IRQ 绑定一个驱动，由 init 配置，初始屏蔽、驱动就绪才开放；驱动只可 ACK 获授的中断。
驱动退出或授权撤销时屏蔽并解除投递，屏蔽不代表 DMA 停止。

### 事件位图与授权通知（已确定）

事件为 64 位可合并位图。recv 返回 EVENT 时 words[0] 为事件位；含 TIMER 时 words[1] 为到期代次，否则为零；words[2..3] 置零，source/request 为无效 Handle。
内核事件包括 IRQ、请求取消、退出记录待收取及定时器到期；用户通知用于共享队列/连接状态变化。
内核保留位不得由普通用户通知置位；内核/IRQ/用户位段及位号在共享ABI统一冻结，容量配置只能限制可用数量，不能移动位段、重用保留位或改变已有位含义。
获权配置者授予通知句柄，表项固定目标进程实例/镜像及允许掩码；notify(handle,bits)不允许自选PID或越过允许位。动态连接若需要新增通知权，其交付必须另有已定义授权路径，不从CALL权限隐式获得。
notify 校验句柄类别、代次、通知权限及目标存活后置位，必要时唤醒；不分配消息，不等待目标接收。
多个通知源可合并，EVENT 的 source 不表示用户发送者；服务按启动配置解释位，并检查实际队列/状态。
同一连接可共享状态变化位，具体 RX/TX 状态由共享区表达；事件不是次数，不能替代需要逐条保留的 SEND。
目标退出、授权撤销和句柄复用遵循身份及授权规则；不能凭猜测整数通知无权限的目标。

### notify 调用契约（已确定）

notify(target, bits) 的 target 是调用者本地通知授权，绑定目标完整实例及允许掩码；bits 必须非零且全部属于该授权允许的用户位，包含越权/内核保留位时整体失败，不部分提交。
短原子提交执行目标 pending |= bits 并检查已登记的匹配等待，必要时唤醒；与等待登记协调以避免丢唤醒。操作不分配消息/Rq、不等接收者，返回 0 仅表示提示已提交，不保证处理完成。
重复位合并，不承诺通知次数；实际队列/共享环保存持久业务状态，发布数据须先完成既定内存顺序再通知。目标不处于匹配事件等待则保留 pending，不强行打断同步 call/send。
撤销授权、陈旧目标或退出状态拒绝，不能通知复用进程槽中的新实例；信号、IRQ 和强制终止不通过普通 notify 伪造。

#### 示例：serial 通知 tty

serial 先将收到字节发布到共享环，再以获授 RX_READY 位通知 tty。连续十次置位可合并成一次提示，tty 依据环状态消费数据，而不是把一个事件位当作一个字节或一次完成。

### 非阻塞接收（已确定）

普通消息/事件交替、合并提示后的多批推进和主循环避免睡眠空窗见 [接收公平](04-ipc.md#接收公平与服务推进的边界语义收口)。一次EVENT不等于所有实际记录已被业务处理，服务须保留未完成批次的本地标记。

recv 使用操作选项 RECV_NONBLOCK；默认无可交付内容时阻塞，非阻塞模式返回 WOULD_BLOCK。
长期 CALL 满额不阻止保留名额接收即时请求；无匹配事件和可交付消息返回 WOULD_BLOCK。
若服务尚占即时 CALL 未 reply/defer，再 recv 返回 BUSY 而非覆盖该请求；失败不消费事件或摘走消息。
驱动可有界处理本地工作、非阻塞接收请求/事件、仍有工作则 yield 并继续；无本地工作才阻塞 recv。
检查与进入阻塞保持原子性，不能将非阻塞检查加后续单独睡眠当成安全等待协议。

### 事件筛选与 sleep（已确定）

recv(options, event_mask) 可指定接受的事件位；未选中的 pending 保留。默认接收普通消息及全部事件。
RECV_EVENTS_ONLY 只接收匹配事件，不接收 CALL/SEND；可与 RECV_NONBLOCK 组合，无匹配内容返回 WOULD_BLOCK。
检查匹配事件与登记等待仍在同一临界区；筛选与非阻塞不能消费未匹配事件或不可接收的消息。
普通程序由用户态定时器管理层注册绝对截止，内核唯一闹钟用于最早截止；提前到期的 pending 直接交付。
服务主循环应接收所有相关事件并用 TIMER 推进状态，不以长期 sleep 代替事件循环。
每进程一个硬件闹钟，由用户态运行库独占管理并为有界逻辑定时器复用；sleep 使用逻辑定时器，禁止库直接覆盖别人的闹钟。
事件筛选不授予投递权限，不屏蔽异步信号与强制终止；event_mask 使用 recv 的 a1/x1，选项使用 a5/x5。

### IRQ 与时间接口（已确定方向）

init 绑定启动发现的 IRQ 到驱动及独占事件位，不能用任意整数创造硬件权限；绑定后保持屏蔽。
驱动持本地 IRQ 授权句柄 ACK，首次开放，后续在取得事件并处理设备状态后重新开放。
已开放时重复 ACK、事件仍未取走时过早 ACK 均返回状态错误；控制器操作顺序由 HAL 保证。
解除绑定/驱动退出时屏蔽并清理该绑定事件，IRQ 位不与其他 IRQ 或用户通知共用。
不建立通用 IRQ 消息队列；若具体设备的信息不可查询且不可合并，须单独设计有界快照/计数等必要机制。
时间查询统一使用 clock_gettime 的秒/纳秒表示；运行库检查溢出后转换为逻辑截止所用的单调纳秒，不等于纳秒精度，也不以调度 tick 充当时间。
每进程一个一次性定时器槽，使用绝对截止时间；新设置替换原定时器并清除旧 pending，到期置专用 TIMER 位。
过去的截止时间立即置位；取消清除定时器及其 pending，退出自动取消。不新增用户可创建的定时器对象。
定时事件不直接打断同步 call/send；异步服务事件循环可据逻辑截止发起取消，取消仍不等于设备停止。闹钟与取消协议见[全局设计与冻结条件](00-overview.md)。

没有 IOMMU 时设备驱动属于可信域；设备重启需要单独的停止/复位协议。

### 事件、IRQ、时钟与共享环

- 64 位事件是提示而非一源一位：保留内核汇总位、用户汇总位，用户连接以有界待处理表/共享环保存持久状态，recv 后扫描所有相关源。
- IRQ 使用编译配置的独占位段，超出数量在绑定时拒绝；驱动可分进程承载更多设备，不静默截断或让两个 IRQ 非法共享独占位。
- IRQ 记录保存绑定代次及 DISABLED/ARMED/DELIVERED 状态；ACK 验证专属 Handle、目标身份、当前状态和事件已取走，过期 ACK 不打开新绑定。
- 每进程唯一闹钟由运行库定时器管理层持有，set/cancel 递增代次；TIMER 事件同时在 words[1] 返回到期代次（对仅 TIMER/混合事件均有效），其余保留字为零。
- 运行库比较代次并按 clock_gettime(CLOCK_MONOTONIC) 的安全纳秒转换处理逻辑最小堆，重新设置最早截止；旧事件不执行新任务。逻辑定时器表有编译上限，signal 中不重入修改该堆。
- 采用秒/余数等不溢出换算单调纳秒，明确分辨率及上界；过去截止立即到期，禁止倒退。
- 共享环使用单调索引、容量边界校验和 release/acquire；即便单核，设备/编译器顺序也不能依靠普通变量假设。
- DMA 同步明确 CPU→设备提交与设备→CPU 完成两向；非一致平台执行 cache clean/invalidate，配合描述符/门铃所需屏障及 MMIO 属性。

验收：超过事件位的连接扇入、旧绑定 ACK、旧 TIMER 与重设交错、共享环满/空/重排及 DMA 可见性，全部有界且不丢实际状态。

### irqbind 调用契约（已确定）

irqbind(target, irq, bit) 中 target 为调用者本地目标驱动管理授权，irq 为受信硬件中断资源授权而非任意中断号，bit 为目标配置的 IRQ 专属事件位编号。
检查绑定管理权、目标实例存活状态、中断源独占、合法位段及位冲突、驱动资源表与绑定池容量；禁止两个绑定共用 IRQ 专属位。
成功返回驱动本地 IRQ 确认 Handle，状态 0；安装与目标退出按原子先后处理，绑定后保持屏蔽，驱动完成设备初始化后首次 irqack 才开放。
失败不发布半成品句柄/绑定、不泄漏位或引用；只回滚本次新绑定操作，拒绝操作已有绑定时不得屏蔽/破坏其他有效所有者。新取得中断源保持安全屏蔽，控制器步骤由 HAL 执行。
确认句柄绑定完整驱动身份和绑定代次，不能用旧 Handle 重新打开解绑后或其他代绑定。

#### 示例：serial 初始化后才打开 IRQ

init 授予 serial UART 设备窗口并 irqbind 到合法 IRQ 位，将返回的驱动本地确认 Handle 交付。serial 配置 UART、缓冲和设备中断状态后首次 irqack，才开始投递；绑定成功不代表设备初始化完成。

### irqack 调用契约（已确定）

irqack(binding) 只接受当前驱动本地确认 Handle，校验完整目标/绑定代次。状态为 DISABLED → 首次确认 ARMED → 硬件投递 DELIVERED → 取走事件并确认 ARMED。
内核上半段认领/校验绑定、屏蔽源、按 HAL 顺序完成控制器处理并置对应事件；不能把控制器 EOI 等步骤交给任意用户驱动直接执行。
驱动取走事件后处理设备队列/清除中断条件，再 irqack。内核检查事件已消费及状态，不宣称验证设备协议处理完；驱动对硬件收尾负责。
返回 0 表示重新开放已提交；ARMED 重复确认、事件未取走、已撤销/退出/陈旧绑定均失败，不误开新绑定。
驱动可在屏蔽时有界分批处理并让出机会，仍有待处理且无其他唤醒源时不能睡眠；重新开放后剩余状态依具体设备触发方式及重查协议保证不丢失。

#### 示例：一次 UART IRQ

serial 收到 IRQ 事件时源已屏蔽，先从设备排空本轮允许数量的数据并发布共享环；若仍有本地工作则继续有界处理。完成设备条件处理后 irqack，不能 recv 事件后立即确认却把设备清理无限推后。

### irqunbind 调用契约（已确定）

irqunbind(target, binding) 校验调用者本地的目标驱动管理授权，再按目标主体解析 IRQ 确认 Handle；完整身份/绑定代次必须匹配。
先使绑定不可再确认，屏蔽中断源并完成必要控制器同步，再清理该绑定 pending、解除关联并使旧确认 Handle 失效。成功返回 0，保证旧绑定不再产生新投递/重新开放，不保证设备停止。
正在进入/处理的上半段与解绑同步，不允许旧投递在事件位分配新绑定后继续置位；位及绑定槽只能在相关内核处理结束后复用，旧代 ACK/解绑不影响新绑定。
解绑不取消设备队列/业务请求、不证明 DMA 已停止；MMIO、共享区及 DMA 页继续按设备安全协议保留/清理。新驱动取得设备所有权前还须排空/复位并确认旧访问结束。

#### 示例：未消费 IRQ 时解绑

旧 serial 的 IRQ 已置 pending 而尚未 recv，init 解绑后旧提示清除、旧确认 Handle 失效；新绑定使用新代次，不能接收到晚到旧投递。旧设备队列及 DMA 则仍须单独停止，不能据解绑成功复用物理页。

### 单调时间与实时时间（已确定）

单调时钟由硬件计数转换，启动后从确定起点递增，供调度、sleep、服务超时和性能计时；校时不得改变已有单调截止时间。
实时时钟为单调经过时间加墙钟基准，使用 Unix 时间表示。内核保存时钟机制及基准，init 管校时权限和策略；具体 RTC 设备访问仍在用户态，网络校时可复用同一授权更新入口。
无 RTC/外部可信来源时，实时时钟从 Unix 纪元开始推进；原生时钟状态查询明确报告未校准，不伪称真实日期。文件时间戳取实时时钟并继承此限制。
更新墙钟基准与读取必须取得一致快照，单次查询不能混用更新前后值；允许实时时钟前后跳变，不允许单调时钟倒退。
内部及 ABI 的秒/纳秒或基准差值表示须有界且检查溢出，不假定所有实时时刻都能装入有符号 64 位纳秒；POSIX timespec 秒类型及纳秒范围统一定义。
首轮睡眠和服务超时使用单调时钟。绝对实时时钟等待不因有 CLOCK_REALTIME 查询而自动视为支持；加入时须单独定义校时重新计算与唤醒规则。

### clock_gettime 调用契约（已确定）

公开接口为 time.h 中的 int clock_gettime(clockid_t clock, struct timespec *time)，底层入口为 __sys_clock_gettime，不保留 clock_now/clockget 同义接口。
首轮支持 CLOCK_MONOTONIC/CLOCK_REALTIME，查询不需管理权限或 init RPC。内核状态在 a0/x0 返回 0 或负错误码，有符号 64 位秒在 a1/x1、规范化纳秒在 a2/x2；纳秒为 0..999999999，其余输出按 ABI 初始化。
库将定宽寄存器结果填入公开 timespec，成功返回 0，失败返回 -1 并设置 errno；公开 C 布局与内核定宽 ABI 分开定义，不把 long 隐含带入跨边界结构。
无效时钟编号拒绝，一次取得一致快照；纳秒字段不代表纳秒精度，分辨率/校准状态另查。逻辑截止仍使用已有单调纳秒表示，转换溢出明确失败。

#### 示例：同一查询表示两种时间

应用 clock_gettime(CLOCK_MONOTONIC, &ts) 得到确定单调起点后的经过时间；CLOCK_REALTIME 得到 Unix 时间，未校准时遵守前文纪元起点策略。校时不得改变前者或已设置的单调截止。

### clock_getres 与 clock_settime（已确定）

公开接口沿用 time.h 的 clock_getres(clock, res) 和 clock_settime(clock, time)，状态转换采用 POSIX 0/-1 加 errno；底层入口按 __sys_* 规范，定宽输入与公开 timespec 分开。
clock_getres 无需管理权限，返回内核/HAL 声明的实际时间分辨率，不等于调度时间片或唤醒精度，不能因纳秒字段而固定声称 1ns；不支持的时钟明确拒绝。
clock_settime 只允许 CLOCK_REALTIME，调用者须持明确校时授权，uid 0 不自动获得；libsys 使用已获授授权，没有则权限失败，不隐式请求 init 代办。
设置前检查秒范围/纳秒规范及溢出，原子更新墙钟基准，不改变单调时间或现有单调截止；来源/可信度由原生管理状态单独记录，设置成功不自动声称已与可信源同步。

#### 示例：RTC 提供初始墙钟

用户态 RTC 驱动取得日期，init 校验来源与策略后通过校时授权设置 CLOCK_REALTIME；设备驱动不因此直接改内核时钟，普通应用也不能只凭 uid 0 绕过授权。

### alarmset/alarmcancel 调用契约（已确定）

原生 alarmset(deadline)、alarmcancel() 仅操作当前进程唯一闹钟，不接受任意目标 PID。deadline 为绝对单调纳秒，过去截止立即到期，0 不充当取消标志。
每次成功设置/取消递增不回绕代次并返回新值，设置替换旧截止且清除未交付旧 TIMER；取消阻止旧截止产生新的有效提示。参数/代次检查失败不修改原闹钟。
TIMER 在 EVENT.words[0] 置位，words[1] 返回到期代次，混合事件也遵守同一格式；已交付快照不能撤回，运行库比较代次忽略旧提示。
libsys 定时器层独占设置内核闹钟，以有界逻辑最小堆复用 sleep/RPC 超时/维护任务；普通调用路径统一经过该层，信号处理不重入修改堆。
直接使用原生闹钟的自定义运行时须自行承担全部复用，不保证与 libc/libsys 普通睡眠路径混用；原生名称不等同 POSIX alarm() 的信号语义。

#### 示例：重设后收到旧代提示

alarmset(T1) 返回代次10，随后 alarmset(T2) 返回11；即便旧代次10的事件快照已经交付，运行库也不执行当前任务，按实际单调时间与逻辑堆重新检查。未交付的旧提示在重设时清除。

### nanosleep 与逻辑定时任务（已确定）

公开 nanosleep(req, rem) 不新增内核睡眠 syscall。库先快照相对时长，校验非负秒/规范纳秒与截止溢出，读取单调时间并注册自身逻辑定时任务，再事件等待，满足本任务截止后完成。
普通通知/其他任务到期不是本次完成，唤醒后核对本任务状态；等待不消费普通 CALL/SEND。取消仅移除本任务并按逻辑堆重设最早闹钟，不清空进程其他定时任务。
未中断时不早于约定截止完成，调度可使实际恢复更晚。捕获信号中断则返回 -1/errno=EINTR，按中断点记录的剩余时长填 rem，不因 SA_RESTART 自动重启。
信号入口与预付等待状态协作，进入用户处理函数前快照中断时刻/剩余时间，不在处理函数中重入修改定时堆，不等待处理函数运行很久后才计算剩余量。具体信号 trampoline 字段与上下文布局在 ABI 冻结。
服务主循环注册截止后继续处理请求/事件，不用长期 nanosleep 阻塞控制路径；自定义运行时直接管理原生闹钟时不与本套定时复用隐式混用。

#### 示例：5 秒睡眠在第 2 秒被打断

本次截止在单调时间 T+5秒，第 T+2秒进入信号中断路径并记录剩余约3秒；处理函数运行后 nanosleep 返回 EINTR，rem 不因处理函数耗时被错误改为0。移除本次任务不影响其他 RPC 超时或维护任务。

#### nanosleep 的完成、中断与停止排序（已冻结）

用户已接受以下细化方向；信号/运行库布局和标准审计仍未完成。

保留前节不因 SA_RESTART 重启的方向。确定一次调用固定原截止 D；在信号入口与睡眠状态交接时读取单调时间 I，若睡眠尚未终结且 I<D，则固定中断结局和 rem=D-I，先递送 handler，正常返回后报告 EINTR。若先固定正常完成，或裁决时已经达到 D，则保持成功0，信号照常递送，不因 TIMER 位尚未被循环读取便把到期睡眠改成中断。具体读取/提交采用本篇首版I/D裁决和11信号现场交接，不以信号生成时刻代替实际中断裁决时刻。

中断结果一旦固定，handler 运行多久都不重新计算 rem，也不因为 handler 期间经过原截止便改为成功。应用若显式拿 rem 再次调用 nanosleep，这是新的相对睡眠，handler 耗时不从它扣除；本接口不承诺反复重试仍保持最初绝对截止。成功时确定不写 rem；req 先做独立快照，req/rem 别名不能改变已登记时长。rem 非空时通过既有受检查复制输出；复制失败按 EFAULT 处理，不重建原睡眠，最终错误优先级随逐接口映射核对。

纯 STOP 保留原睡眠和截止，单调时间继续经过；CONT 后若原截止已过则按完成条件结束，不重新等待原相对时长。若 CONT 另需捕获 handler，则解除停止与捕获信号分别裁决：仍未到期可固定 EINTR/剩余量，已经正常完成则保持0。KILL 不返回，由退出取消本上下文的任务，不能误取消其他上下文的逻辑任务。

信号交接必须先让本层睡眠记录对 handler 安全：中断终态持有剩余快照，旧任务不得随后覆盖它。定时堆只在短且不可重入的本地更新段维护，禁止持保护跨 handler 或阻塞 RPC；handler 内再次 nanosleep 使用独立预付上下文。旧任务如何摘除/失效、何时重设唯一闹钟仍随运行库布局冻结，不为此新增公开定时对象。

示例：睡5秒，T+2秒固定中断和 rem=3秒，handler 用了4秒。外层仍返回 EINTR/rem=3秒；应用显式再睡3秒，最早约在 T+9秒完成。若是 T+2秒纯 STOP，T+6秒 CONT 且没有捕获 handler，则原截止已经过去，恢复后正常完成，不再睡3秒。

本段是本项目细化提案，具体原子裁决、STOP 和运行库组织不作为外部标准结论。本轮检索未取得可核验正文，POSIX.1-2024 完整兼容核对仍未完成。
待核对资料：[OpenBSD nanosleep](https://man.openbsd.org/nanosleep.2)。

## 首版事件、时钟与推进规格（已冻结）

事件位固定：bit0 TIMER、1 RQ_DONE、2 RQ_CANCEL、3 CHILD、4 LIFE；5..15保留内核；16..31 IRQ独占位；32..63用户通知位。用户notify只允许后32位、bits非零且为授权掩码子集。EVENT words[0]=所取位，words[1]=含TIMER时的alarm代次，否则0，words[2..3]=0，source/request/image=0。IRQ bit超出16..31或冲突拒绝，不能随配置移动位。

CLOCK_MONOTONIC=1、CLOCK_REALTIME=2；time/getres返回s64秒和规范u64纳秒。RTC未校准时REALTIME从纪元随MONOTONIC推进，query报告uncalibrated；只有SYSTEM CLOCK可校时。时钟转换使用商/余数避免乘法溢出；getres报告硬件计数可表示的向上取整纳秒分辨率，而非固定1ns。闹钟deadline=u64单调ns，0是过去时刻不是取消，代次u64从1起、耗尽OVERFLOW且保持原设置。

每进程一个alarm；libsys逻辑任务数组64项、小根堆，禁止业务库直接绕过它覆盖alarm。IRQ计时到期只置事件及内核准备到期标记；内核准备deadline由内核独立维护，不能被用户alarmcancel取消。tick处理最多8个准备、正常CPU安全出口每批32项清理；服务自己的准备/轮询超时在事件循环推进，不能靠父继续运行才释放。

nanosleep固定D，进入捕获信号裁决时I<D固定EINTR/rem=D-I；I>=D或完成先提交则0，handler时间不扣rem。rem输出FAULT优先于EINTR，成功不写rem；req先快照，req/rem重叠不影响时长。纯STOP时间继续经过，CONT后按原D处理；KILL移除本上下文任务。定时堆在短屏蔽段更新；先冻结/摘除本次等待任务及中断快照，再递送handler，handler的新nanosleep使用独立层。每层记录是否注册/完成，旧TIMER代次不能修改新任务。

### IRQ绑定状态与真实递送接续（2026-11-17）

已接固定64份Binding（每份56字节）及不可变启动IRQ库存，来源只取已验证DTB/HAL描述，不把任意整数变成用户授权。绑定精确持有Imageid、完整PID、独占bit16..31及目标Event；每份活绑定持1个Image cleanup引用和目标本地IRQ_BIND ACK槽（子类型11、仅ACK、不转授/继承）。按PID槽组织最多16份的所有者链，结束镜像不用扫描其他驱动；全局库存/记录/头部在默认配置共4360字节固定BSS，无中断期分配。

状态例：可信安装到PREPARING镜像→DISABLED，源屏蔽、位/Local/Image引用同时取得；发布前不能ACK。镜像ACTIVE后首次ACK→ARMED；真实认领→HAL屏蔽/完成→DELIVERED并置持久IRQ位。事件未取走时ACK为STATE；recv取走位后ACK→ARMED，ARMED重复ACK仍STATE。位/源已占、表/池满、错误Image或输入失败不先屏蔽旧所有者，也不取半份引用。IRQ事件仍为提示，words[1]不增加绑定代次，words[2..3]/source/request/image为0；设备队列/中断条件处理由驱动负责，内核不假装验证它们。

Image结束在imageend提交点立即逐项屏蔽、清该绑定pending、解除源/位并放Image引用，状态REVOKED且不再保留Event指针；这覆盖正常退出、故障、强杀、准备取消/超期及类型化旧Image替换。REVOKED记录只占池槽，等Local CPU离栈清理最终释放，代次不回绕；旧Local/内部ID不能重新开放，迟到释放也不能mask新所有者。驱动free确认槽、CONTROL REVOKE和显式irqunbind同样先拆绑定再删槽。解绑只停止软件投递，不证明DMA停止，也不保证物理控制器没有旧锁存提示；新驱动初始化/设备恢复另守09规则。

GIC timer ACK遇外设时保留完整IAR token并返回待取状态，通用入口立即从hal_irq_claim取这同一个token再处理，不重新读IAR丢弃旧认领。RV64内核向量9现与timer向量5同走全现场入口；保留原idle-WFI重开窗口跳过机制。用户现场入口默认允许IRQ，时间片仍由proctimerstart单独启用；无timer时可因已ARMED IRQ进入CPU idle并醒来。事件仅唤醒掩码包含该bit的RECV，不扫观察表/其他请求，不打断call/rqwait。唤醒其他READY驱动时用户IRQ出口按FIFO让出，内核IRQ只请求安全检查点；外设不虚增timer_ticks/kernel_ticks。

反例：驱动BLOCKED在recv，IRQ使其READY但尚未回C续点；管理者unbind清位后，旧recv恢复重新检查并回BLOCKED，不能交付一次假事件。旧镜像结束且源给新Image后，旧确认/迟到Local清理不得屏蔽新绑定。无timer的忙用户也不能在IRQ已唤醒另一驱动后永占CPU：新验收用不主动yield的伙伴，确认真实IRQ导致FIFO切离且两类timer计数仍0，再强杀其已保存IRQ C续点而驱动绑定仍有效。
