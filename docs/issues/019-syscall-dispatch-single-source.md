# 019 系统调用编号存在第二份真相，分派与编号表分离

状态：待处理　优先级：P1　关联：06、018

## 现象

系统调用号在 `include/abi/syscall.h` 定义一次，`kernel/syscall.c` 又用**区间判断**把同一事实编码了第二遍：

```c
known(u64 nr)
{
  return (nr >= 1 && nr <= 3) || (nr >= 0x10 && nr <= 0x1c) || (nr >= 0x20 && nr <= 0x25) ||
         (nr >= 0x30 && nr <= 0x36) || (nr >= 0x40 && nr <= 0x56) || (nr >= 0x60 && nr <= 0x6e) ||
         (nr >= 0x70 && nr <= 0x75);
}
```

同时 `syscall()` 内是 `switch (nr)`，含 **117 个 `case SYS_*` 标签**（多个编号落到同一分支），并提供 `default: status = -ERR_NOTSUP`。

## 影响

- **编号表与区间表必须同步维护**：新增或改号时漏改一处，就得到"号码合法但无实现"或"有实现但被判非法"两种不一致。
- **区间无法表达空洞**：未分配的编号落进某个区间时 `known()` 返回真，再靠 `switch` 的 `default` 兜成 `NOTSUP`。于是"这个号码存不存在"有两个不同答案来源，取决于问谁。
- 无法从代码直接枚举"当前实现了哪些调用"，也难以自动核对实现与头文件声明是否一一对应。

## 建议方案

分两阶段。

**阶段一（低成本）：让区间由头文件生成**

把 `known()` 改为由 `include/abi/syscall.h` 展开生成（X-macro 或生成表），使编号只有一个出处。此阶段不改 `switch`，只消除重复事实；`default` 保留为兜底但仍需与生成表语义一致。

**阶段二（结构）：表驱动分派**

```c
static const Sysentry table[] = {
  {SYS_QUERY,    sysquery},
  {SYS_OBSERVE,  sysobserve},
  ...
};
```

- `known()` 变为查表，"号码存在"与"号码有实现"成为同一个事实。
- `default`/`NOTSUP` 路径自然消失。
- 新增调用的改动收敛为一行。

难点：当前 `syscall()` 有一段很长的公共前导（参数快照、`Arguments` 联合、句柄与 PID 解析、输出写回）。表驱动要求把前导与各分支拆开，或者保留"公共前导 + 表"的混合结构。**拆分方式需在动手前定，不在本条预设。**

## 验收

- 阶段一：任意修改 `include/abi/syscall.h` 的编号集合后，`known()` 行为随之变化，无需同步改动 `syscall.c`；构造一个恰好未分配的编号，验证其被明确拒绝且拒绝原因一致。
- 阶段二：全仓不存在手工维护的编号区间；新增一个仅返回固定值的测试调用只需加一行表项即生效（测试后可移除）。
- 两阶段均需：既有双架构 QEMU 场景不回归；已冻结的编号集合与对外行为不变。

## 备注

- 本条是内核主路径的结构调整，**不与功能批次混提**：行为必须保持不变，只改表达与分派方式。
- 与 018 相邻但不同：018 处理查询记录的字段表达，本条处理调用号与分派的单一出处。
