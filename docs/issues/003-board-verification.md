# 003 验收依赖 QMP，真机无等价手段

状态：进行中（QEMU 无主机观测演练可先做；上板确认待硬件）　优先级：P0　关联约束：01#4（验收不得只依赖主机观测量）

## 现象

现有 110 个 QEMU 场景的断言依赖主机 QMP：特权态、halt 地址、逐页页表审计、`pmemsave`。真机上没有这些通道。

## 影响

现有验收无法在板上复现；照搬则"真机通过"无从判定。

## 建议修复

按 14 的"板端验收与硬件矩阵"落地：

1. 每个场景在程序侧自证并打印结构化摘要（页与费用账目回基线、会话数归零、FNV-1a64 校验和、状态字）。
2. 主机侧只做串口文本比对，不读 guest 内存。
3. 显示类改为绘制后读回自检摘要；QEMU 侧保留 `pmemsave`/`screendump` 作交叉验证。
4. 先挑 `pages`、`ipc`、`cow` 三个场景做"板端等价"试点，形成模板后再铺开。

## 验收

同一场景在 QEMU 与真机产出相同摘要（环境差异字段须显式列出）。


## 为什么优先级提到 P0（2026-11-18）

001、005、007 三条的本地实现均已完成或基本完成，剩下的收尾动作都写作"板端待验"。而"板端怎么验"正是本条。在本条落地前，那三条无法关闭，006 也只能停在"本地已验、板端未验"。因此本条是四条真机相关事项的共同前置，且需要实物板（NEO3 / VisionFive 2）才能推进。

## 无实板时的推进方式（2026-11-18）

真实硬件暂不可用（用户 2026-11-18 确认），本条不空等：先在 QEMU 上把"板端等价"的验收方式建好并演练。

1. harness 增加"无主机观测"模式：不做 QMP 特权态检查、不审计页表、不 `pmemsave`，只按串口输出判定。
2. 每个场景输出结构化自检摘要，例如 `SELFTEST pages total=... free=... allocated=0 acct=0 result=OK`；摘要须能自证关键不变量（页与费用账目回基线、会话归零、校验和）。
3. 先在 `pages`、`ipc`、`cow` 三个场景跑通该模式，形成模板后再铺开。
4. 上板时判定逻辑不变，只把"QEMU 串口文件"换成真实串口设备。

额外收益：该演练会暴露那些过度依赖主机观测的场景——它们在板上必然测不了，必须补自检。演练结果只证明"验收方法可用"，**不构成板端验收**。

板端证据取得成本高，保留优先级高于普通QEMU运行：放在独立板端目录并登记阶段evidence，不参与本地UUID运行自动轮转；本地保留/清理规则见14末尾及issue011。

stage283：`pages` 已在 RV64、ARM64 完成无 QMP、无 GDB 的 QEMU 试点，同架构纯串口和普通 QMP 摘要一致。命令和判定规则见 [14](../design/14-operations.md#板端验收与硬件矩阵2026-11-18)；`ipc`、`cow` 与上板仍待验。
