# 021 `Rq` 命名已被 IPC 请求队列占用，与将来的调度队列冲突

状态：待处理　优先级：P2　关联：00#第二期、006

## 现象

`include/rq.h` 中的 `Rq`、`Rqid`、`Rquota`、`Rqrecv`、`Rqresult`、`Rqinfo` 指的是 **IPC 请求队列**（`REQUESTS 1024`、`RQ_NORMAL`/`RQ_SIGNAL1`/`RQ_SIGNAL2`/`RQ_CONTROL`、`ipc_rqpoll`/`ipc_rqack`/`ipc_rqfinish`/`ipc_rqcheck`），与调度无关。

而 `00` 已把第二期定为多核，届时必须有"每 CPU 就绪队列"。按现在的命名，那个结构**不能叫 `Rq`**，只能另起名（`Runq`/`Ready`/`Runqueue`），否则读代码的人会把 IPC 请求队列与调度队列混为一谈。

## 影响

- 第二期引入调度队列时被迫使用第二套前缀，同一头文件目录下出现 `Rq*`（IPC）与 `Runq*`（调度）并存，容易误读。
- 现在改名的成本是纯机械替换；等调度队列落地后再改，要同时改内核、libsys、多个服务与大量测试。
- 该命名也会误导新读者以为 `rq.h` 与调度有关。

## 建议方案

在引入调度队列之前完成一次纯改名，二选一：

| 方案 | 说明 |
| --- | --- |
| A. 保留 `Rq` 给调度，IPC 侧改名 | 需改大量既有代码与文档，收益小 |
| B. IPC 侧保留 `Rq`，调度侧用 `Runq` | 改动为零，只需在 00/03 明确约定 |

**推荐 B**：`Rq` 已经是 IPC 请求队列的既成事实，语义在既有文档中稳定；只需**显式约定**"调度就绪队列叫 `Runq`，不得叫 `Rq`"，并把这条写进第二期的命名约定，避免将来争议。

若选择 A，则本条变为一次跨内核与用户态的机械重命名，需双架构回归。

## 验收

- 选择 B 时：00 或 03 中有明确的命名约定条文；代码无需改动。
- 选择 A 时：全仓不再存在指代 IPC 请求队列的 `Rq*` 标识符；双架构 QEMU 与主机测试不回归；文档同步更新。
- 第二期实现调度队列时，命名不与既有 `Rq*` 冲突。

## 备注

- 本条是命名与约定问题，不是缺陷；登记的目的是避免"以后改很贵"。
- 与 006（次核停放）同属第二期前置，但互不依赖。
