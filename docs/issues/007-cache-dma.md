# 007 缓存开启与 DMA 一致性未验证

状态：进行中（ARM64开启本地通过，DMA/RV后端/板端待验）　优先级：P0　关联约束：01#5（缓存与屏障按真实语义）

## 现象

以下为原始缺口；ARM64开启前置现已通过本地全量，DMA及板端部分仍未完成。

ARM64 `SCTLR` 仅置 `M`，I/D 缓存关闭；09 的 DMA 同步契约（clean/invalidate、维护粒度、屏障）只有文本，未在真实非一致 DMA 上验证。

## 影响

真机必须开缓存。一开，收发包、块设备、代码装载（I-cache）全部进入"不验证即错误"的状态。

## 建议修复

1. 先在 QEMU 上开启缓存跑现有回归，暴露所有缺少 clean/invalidate 的路径。
2. 落实 09 的维护点：DMA 交接、代码 seal/装载后的 I-cache、12 的零拷贝 rx 槽位。
3. 明确"一致/不可缓存映射"与"非一致 + 显式维护"两种路径的判定来源。

两架构缓存开启后 `test-qemu` 全部场景通过；另加一个故意漏维护的反例（应失败）。
