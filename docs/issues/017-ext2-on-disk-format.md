# 017 盘上格式改为 ext2 兼容（日志置于已分配块）

状态：待处理　优先级：P1　关联：10、07、016

## 现象

`sbin/fs` 使用自造盘上格式，与 ext2 只是骨架相似、细节全不相同：

| 维度 | 当前实现 | ext2 |
| --- | --- | --- |
| 魔数/格式号 | `FS_FORMAT 1`，第 0 块 | `0xEF53`，字节偏移 1024 |
| 根 inode | `FS_ROOT 1` | **2** |
| 位图/表定位 | 固定块号（`FS_INODE_MAP`/`FS_BLOCK_MAP`/`FS_INODE_START`） | 按块组描述符 |
| 目录项 | `{inode, generation, reclen, namelen, kind}` | `{inode, rec_len, name_len, file_type}`（**无内联 generation**） |
| 日志 | 固定块 1 起 64 块 + 自家 EMPTY/COMMITTED 协议 | 无（ext3 用 JBD2） |
| 构建工具 | **无**；测试盘是 `truncate` 的空 raw | `mke2fs`/`debugfs`/`e2fsck` |

直接后果：
- 每次装机都要自己实现镜像生成器，`tools/` 里至今没有。
- 全部盘上验收是"我们造盘 → 我们读"，闭环自证，`01#4` 要求的独立观测无法满足。
- `status` 中长期挂着的"磁盘 magic/CRC、端序、inode flags、目录 type 未定稿"，本质是自造格式必须自己冻结的负担。

## 决定

**采用 ext2 兼容格式**（不用自造格式），**日志采用方案 B：日志块以普通已分配块的形式存在，对 `e2fsck` 呈现为合法文件，由本服务自行重放。**

## 建议方案

### 目标形态

- ext2 rev 1，块大小 4096，镜像小到单个块组即可；
- 不启用 `dir_index`、`resize_inode`、`large_file`、extents 等可选特性，协商面越小越好；
- 根 inode 为 2；superblock 读字节偏移 1024；块组布局一律**从块组描述符解码**，不再用固定块号。

### 镜像构建不再自研

```
mke2fs -t ext2 -b 4096 -O ^dir_index,^resize_inode,^large_file -d rootfs/ rootfs.img
```

`-d` 直接由目录树生成带内容的镜像，权限位、符号链接、时间戳由 e2fsprogs 处理。**本条不再要求实现 mkfs。**

### 日志的位置与可见性（方案 B 的关键）

1. 日志是一段**固定大小、在块位图中正常标记已分配**的块区，挂在根目录下一个固定路径的隐藏文件上；`mke2fs -d` 生成该占位文件。
2. 挂载时**不解析目录**定位日志：构建后由一次短后处理把该文件的 inode 号写入 superblock 的 `s_reserved` 保留区，服务读 `s_reserved` 直接得到日志区。`e2fsck` 不解释 `s_reserved`，因此不会报错。
3. `s_reserved` 同时存放 dirty 标志与日志头尾。重放完成后清空日志并清除 dirty 标志。
4. **代价与约束**：日志非空（dirty）时，该卷**不得由外来工具挂载**——外来挂载会看到日志覆盖前的旧数据，随后的写入会破坏可重放性。这一点必须写入 10 篇并附检查手段，不能只靠口头约定。

### 由此关闭的未决项

`magic`、`CRC` 参数、整数端序、inode flags、目录 type 全部由 ext2 规范给定，"持久格式待冻结"这一条随之关闭；剩余未决只剩本条显式列出的两项（见下）。

### 两个需要拍板、本文不预设的限制

- **权限语义**：ext2 的 `i_mode`/`i_uid`/`i_gid` 建议仅用于 `stat` 展示，实际访问控制仍走 fs 服务的会话授权。冲突时以有能力模型为准，须在 10 篇写明，避免误以为 `chmod` 能改权限。
- **时间戳**：`CLOCK_REALTIME` 来源与校时尚未实现，v1 写入 `atime/ctime/mtime` 只能是零或单调推导值，`stat` 文档须标注"不可信"，不得表现为真实时间。

## 迁移路径

1. **只读 ext2（解 M3）**：用 `mke2fs -d` 造镜像；服务读块组描述符、inode 表、目录项，只读挂载并读出程序。此阶段不动写路径与日志。
2. **可写 + 日志 B**：分配器、位图更新、目录插入、增长；日志按上述方案落位，重放后清除。
3. **断电一致性验收**：在提交到 home 位置的中途停机，重挂后由日志恢复；并验证 dirty 状态下外来挂载被拒。

## 验收

- **外部裁判**：宿主用 `mke2fs` 造盘、`debugfs` 列出目录与读出文件内容，与 QEMU 内 fs 服务的输出逐字节一致。
- **反向验证**：本服务写出的镜像在宿主 `e2fsck -fn` 判定无错；`dumpe2fs` 显示的布局与预期一致。
- **日志**：日志非空时 `e2fsck -fn` 仍判干净（方案 B 的前提）；重放完成后日志区被清空、dirty 清除。
- **拒绝路径**：块组描述符不一致、inode 越界、目录项 `rec_len` 非法、`s_reserved` 中的日志区越界，均明确失败而非猜测。
- 不以"能挂载"替代上述比对；主机工具结论与本服务结论冲突时以主机工具为准并记为缺陷。

## 代价

- 目录项不再内联 `generation`，陈旧名称检测改为读 inode 的 `i_generation`，多一次读。
- 现有针对自造布局的测试（journal/replay/ownership 等大批 stage）需按新格式返工。
- 盘上层的解码与编码要重写；**架构层保留**——cache、分配规划、只读/可写挂载、LOAD 路径与槽位管理不变。

## 备注

- 本条是盘上层的重启，不是小修；不建议与 015/016 混在同一批次推进。
- 与 009 无直接关系；009 是内核侧设备窗口类型，本条是盘上格式。
