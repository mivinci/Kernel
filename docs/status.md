## 目标与工作约定

- 主线分支 `main`。用户授权持续推进完整项目（包括 net）；每完成并验收一个独立点，就提交并推送到同一分支 `main`。实质未定接口再问，保留用户改动，不兼容旧 ABI。
- 先完成可用 POSIX sh：T1 启动包/init → T2 fd/Fix、serial/tty → T3 blk/fs → T4 完整 fork/exec、pipe/dup2、作业控制与 sh。net、图形/GPU 机制排 M3 后；系统和图形机制就绪后最后做 GUI。13 的候选线协议尚未冻结。
- 设计、执行项和验收写对应主题；README 保持简洁，不另建 todo 文件。不得用局部 fixture、QEMU 或格式检查代替全项目、板端、CI 或性能验收。

- [08 运行库](design/08-runtime.md)／[10 文件](design/10-filesystem.md)：独立libsys/csu、基础libc、静态装载及本地fd/File/连接/原RPC记录已接。HELLO/ATTACH/共享READ/控制CLOSE仍为独立fixture；Rctx/快照/IO/关闭worker、参数捕获及目标Boot打包已局部验证。公开POSIX前端、生产FS/TTY/File观察、标准fd API、完整exec路径/Fix尚未完成。

- 文件服务可用固定 CALL 与块服务握手；挂载器先验证设备几何，再探测磁盘，最后从目录扫描结果取得根节点身份。双架构 QEMU `virtiodev` 验证探测顺序、拒绝过早或失效的根获取，以及真实块 I/O；生产 init 发权和盘上解码待接。
- 私有 spawn 可准备、装载和发布真实 ELF 子进程，失败时撤销；ARM64/RV64 QEMU `elf` 验证信号属性覆盖或继承、释放输入后发布，15 项 ELF 主机回归通过。生产路径、目标凭据下的文件动作和后端继承仍未接入。
- `posix_spawnp` 和 sh 后续可共用私有 PATH 搜索：4 项主机测试覆盖候选顺序和错误选择，双架构 SDK 构建通过。实际执行接线待做。
- spawn 文件动作可应用到独立准备表，再关闭仍带 CLOEXEC 的 fd；双架构 `runtime` 以模拟 open 验证动作顺序、同号 dup2 与 File 引用。生产 open、后端继承与发布待接。
- TTY 切换模式时可丢弃本地队列和 RX 环截点前的未读输入；串口终结时收尾仍阻塞的原请求。双架构 `runtime` 验证已到期时不丢输入、终结唤醒 READ 并归还原槽。物理输出排空与公开 `tcsetattr` 待接。
- `FS_LOAD` 等待块映射时保留原请求；双架构 `pipeio` 验证同一请求可恢复，以及无新 IPC 或磁盘完成时也会按期返回 ETIMEDOUT。
- `fcntl(F_DUPFD_CLOEXEC)` 原子发布带 CLOEXEC 的别名，共用原 File；双架构 QEMU `pipeio`、`libsys` 已验证，完整 exec 继承仍待接。
- `Elfsource` 可从已授权的 `FS_LOAD` 会话精确读块；双架构 QEMU `pipeio` 核对 ELF 头、段字节与旧版本拒绝。生产会话授权和基于 FS 的镜像替换仍待接。
- virtio MMIO 精确窗口适配器已纳入 SDK；双架构 `virtiodev` 验证越界拒绝及真实设备访问。生产库存仍只交付 UART。
- 块设备复位、特性协商、几何读取和队列启动共用服务入口；双架构 `virtiodev` 验证只读盘、可写盘和复位后重新启动。
- 设备复位后，块队列等待请求窗口和整个环的 AFTER 完成才进入 STOPPED；双架构 `virtiodev` 验证按失败页续跑。
- 块队列启动先核对 DMA 窗口和队列代次，再设置 `DRIVER_OK`；双架构 `virtiodev` 验证重叠窗口拒绝、新代次启动和真实读盘。
- 块服务故障实例只有确认设备复位并收回 DMA 窗口后才以原请求返回 EIO；双架构 `virtiodev` 验证该路径和旧实例拒绝建连。
- 块传输先保存整批设备完成，再查询原请求；一笔查询失败不挡住同批其他完成，也不丢原设备结果。
